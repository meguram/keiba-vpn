# daily-claude-history

このプロジェクトの全セッション(複数の Claude)の当日の作業を、短い 1 枚の md にまとめる。
保存先は `docs/claude_history/yyyymmdd.md`(例: `20261030.md`)。**要点だけ**にして長くしない。

## 手順

1. **対象日を決める**: 引数に `YYYY-MM-DD` があればその日、なければ今日(Asia/Tokyo)。
2. **素材を集める**(読むだけ。ホストや GCP には触れない):
   ```bash
   python3 -I .claude/skills/daily-claude-history/scripts/session_digest.py [--date YYYY-MM-DD]
   git log --since="<対象日> 00:00" --until="<対象日の翌日> 00:00" --format='%h %s' --no-merges | head -30
   ```
   - 前者は、当日のセッションごとの「ユーザー依頼 → 最終回答(先頭と末尾)」「編集ファイル」「コンテキスト引き継ぎ要約の未了事項」を出す。サブエージェントは含まれない。
   - 後者は、当日のコミット(全ブランチで見たいときは `--all`)。
   - 回答が切れていて判断できない箇所だけ、該当ファイル・コミットを追加で確認する。全文を読み込まない。
3. **既存ファイルを確認**: `docs/claude_history/yyyymmdd.md` があれば先に Read する。
4. **要約を作る**(下記の形式)。
5. **Write で上書き保存**(`docs/claude_history/` が無ければ作る)。コミットはしない。
6. 報告は日本語で 3〜5 行: 保存先、セッション数、横断の残課題の上位 2〜3 件。

## 既存ファイルがある場合の更新ルール

ファイルは毎回、全体を書き直す(追記の積み重ねにしない)。

- 同じセッション(session ID の先頭 8 文字が同じ)の節は、新しい素材で**置き換える**。古い記述のうち今も有効なものだけ残す。
- 今回の素材に出てこないセッションの節は、**そのまま残す**。
- 前回「残課題」「次にやること」だった項目が、今回の素材やコミットで解決していれば**消す**(または `✅` を付けて 1 行に縮める)。新たに出た項目は足す。
- 内容が変わらなければ、無理に書き換えない(「更新なし」と報告する)。

## ファイルの形式

```markdown
# YYYY-MM-DD (曜) Claude 作業履歴

> 更新: HH:MM / セッション N 件 / コミット M 件

## 今日のまとめ
- 全体で何が進んだか(短く)

## 横断の残課題・次の一手(優先順)
1. 〜(どのセッション由来か `[abcd1234]` を付ける。重複はまとめる)
2. 〜

## セッション別
### [abcd1234] 11:02–13:13 — テーマ(1 行)
- やったこと: 〜 / 〜(実際にやった分だけ。件数は問わない)
- 残課題: 〜(なければ「なし」)
- 次にやる: 〜(なければ「なし」)

### [ef567890] 11:01–13:14 — /cost-calculate など
- 費用確認のみ(自明な小さいセッションは 1 行で済ます)

## 当日のコミット
- `abc1234` 件名

## 省略したこと
- 分量の都合で削った内容を書く(なければこの節ごと省く)。例: `[abcd1234] 細かい調整 5 件は省略(UI の文言修正など)` / `コミット 12 件を主要 8 件に絞った`
```

## 書き方の約束

- **件数・行数の上限は設けない**。やったことが多ければその分書く。ただし 1 項目は 1 行で、経緯ではなく要点だけにする。
- **削ったものは必ず「省略したこと」に書く**。分量の都合でまとめた・落とした項目(細かい修正、重要度の低いコミット、素材の「中略 N 件の依頼」で読めなかった分など)は、セッション ID と内容の種類・件数を 1 行で残す。黙って落とさない。
- 既存ファイルの更新で、解決済みとして消した項目は「省略したこと」に `✅解決のため削除: 〜` と 1 行で残す(次回の更新で不要になれば消してよい)。
- 「何をしたか」は成果(直した・追加した・反映した・調べて分かった)で書く。やりとりの経緯、試行錯誤、コマンドの羅列は書かない。
- 「残課題」は、いま未解決のもの(失敗・保留・承認待ち・確認予定)。「次にやる」は、ユーザーの依頼や回答末尾から読み取れる予定。素材から読み取れないことを推測で書かない。
- 時刻の予定(「13:24 に確認」など)は日時つきで残す。
- このスキル自体を実行しているセッションは、1 行(「日次履歴の作成」)で済ます。コンテキスト引き継ぎ要約は、内容を鵜呑みにせず最終回答・コミットと照らす。
- **このリポジトリは公開**。パスワード・トークン・API キー・IP アドレス・個人情報・netkeiba の本文抜粋は書かない。必要なら「(伏せ)」とする。
- 日本語で書く。ファイル名・関数名・コマンドは原文のまま。
