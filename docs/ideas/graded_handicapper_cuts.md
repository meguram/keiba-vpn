# 重賞のルールベース予想家 — 切り口の目録（案）

作成: 2026-11-13。状態: **案。ユーザーと相談して確定させる**（計画書 `docs/ideas/graded_rule_based_handicapper.md` の第 4 節の元）。

## 0. この目録の前提

- **対象**: 重賞（G1/G2/G3）の平地の出走。
  - 2016〜2025 は 1 年に約 128 レース・約 1,900 走。
  - 2026 は 11-08 までで 110 レース・1,654 走。
- **列の出どころ**: 1 出走 = 1 行の表（`src/scripts/data/folklore_build.py` → `/home/jovyan/work/folklore_out/master.parquet`、2016〜2025）。
  - 2026 年は master に無い。元の表（`data/page_reference/tables/2026/` の race_result・race_shutuba・race_oikiri・smartrc_race）で列があることを確かめた。master を作り直せば同じ列ができる。
- **「年の範囲」の数字**: 重賞の出走のうち、その列に値がある割合。2026-11-13 に実データで測った。
  - 空でない値か、0 以外の値か、値の種類の数も確かめた。
  - その結果、`rn_top3_prev`（全行 0）、`allow`（全行 0）、`ok_course`（空の文字が値として数えられていた）は、そのままでは使えないと分かった。B06・F08・H05・L02 に反映した。
- **as-of**: その走より前の情報だけで作れるか。
  - 「○」= 前日までに決まる。
  - 「当日」= 当日の発表で決まる（馬場状態・馬体重など）。前日の予想では使えないため、使うかは決めてほしいこと 4 で決める。
- **オッズ・人気**: どの切り口も、条件・区切り方に単勝オッズ・人気・市場確率・払戻を使わない。使ってよい列はホワイトリストで固定し、テストで検査する（第 3 節）。
- **集計の層**: どの切り口も 3 つの層で数える。
  - 主: 同じレース名 × 同じコース。
  - 副: 同じコースの別レース。
  - 全体: 全重賞。
- **区切り方**: 下の表は案。件数が足りない水準は、隣と合わせる。どの切り口にも「該当なし・不明」の水準を置く（例: 初出走・前走が分からない）。

### 1.2 全体にかかる注意（データの欠け）

1. **2016 年は前走が分からない馬が 17%**。履歴は 2016 年以降の中央の走だけで作っているため（2 走前は 37%、3 走前は 55% が欠ける）。2017 年以降は 99%。
   - 前走系（A〜E）は、**2017 年以降のレースで集計する**（決めてほしいこと 2）。
   - 経歴系（F・I01・J01）は、2016〜2017 は経歴が短く出る。2018 年以降で集計する案と、2016 年から数える案を比べる。
2. **前走が海外・地方の馬**: 履歴は中央だけなので、そのままでは「前走」が中央の最後の走になる。2019 年以降は出馬表の過去 5 走（`race_shutuba_past_flat`、2019〜2026）で直す。2016〜2018 は直せない（該当は重賞で毎年数十走の見込み。第 2 段で数える）。
3. **内外回り**: folklore の `io` は、京都の芝 1400・1600 と新潟の芝 2000 で決まらない（両方のコースがある）。
   - レース結果の `course_type` 列は「外」などが入るが、2026 年でも 8% しか埋まっていない。
   - レース名や過去の実施の記録で決めるか、決められないものは「内外不明」の別のコースとする。主の集計はレース名で絞るので、影響は副の集計だけ。
4. **2026 年**: 核の列（着順・通過順・上がり・タイム・着差・馬体重・騎手・調教師・斤量・ペース・ラップ・出馬表の斤量の決め方・血統）は、2026 年の重賞で 100%。SmartRC（ブリンカー・所属・馬主）もある。
   - 追い切りの評価は約 73%。
   - 払戻は 110 レースのうち 103（2026-10-24 以降が無い）。

## 2. 作れない・入れない切り口

| 切り口 | 理由 |
|---|---|
| 前走の人気・今回の人気・単勝オッズの帯・人気と着順の差（人気より走った／走らなかった）・1 番人気の経験の回数 | **市場の情報**（ユーザーの指定で禁止） |
| 厩舎の中での人気の順位・馬主の中での人気の順位・騎手のその日の人気の順位 | 同上（folklore の tr_pop_rank・own_pop_rank・jday_minpop_rank は人気から作られている） |
| 前走の市場確率・オッズから作った想定の値・期待値 | 同上 |
| 追い切りのコース・強さ・ラップ（L02〜L04） | 2020 年以降のデータがほぼ無い |
| 前走の不利・出遅れ・挟まれた | レース結果に備考（不利・出遅れ）の列が無い。トラッキングのデータは一部の年だけで、重賞の全期間をそろえられない |
| パドックの評価 | 発走の直前にしか出ない（前日の予想では使えない）。2020〜だけ |
| バロメーター（index_total など） | 2023〜だけで、集計の期間（2016〜2024）にほとんど無い |
| 母母父・母母母父の系統 | 2026-11-13 の分析で寄与がほぼ 0（K09） |
| 兄弟（同じ母の馬）の重賞実績 | 母の ID から作れる可能性はある。母の ID の有無を第 2 段で確かめるまで「保留」 |
| 生まれた月・セリの価格 | 手元のデータに無い |

## 3. 市場の情報を使わないことの検査（コード）

- `src/research/graded/catalog.py` に、切り口ごとに使う列を書く。全切り口が使ってよい列を `ALLOWED_COLUMNS`（ホワイトリスト）に固定する。
- テスト（`tests/research/test_graded_catalog.py`）で次の 3 つを確かめる。
  1. 全切り口の列が `ALLOWED_COLUMNS` に入っている。
  2. `ALLOWED_COLUMNS` に禁止の列が無い。禁止の列は、名前に `odds|pop|ninki|tansho|fukusho|payoff|market` を含むもの、`q`・`p_q`・`fav1_prev`、そのレース自身の結果（`fin, y1, y3, pos1, pos4, pos1r, pos4r, l3f, l3rank, tdiff, tsec, pace_cat, lap_cat, pdiff, megu`）、`pd_rank`・`bias_*`・`race_fast`・`day_fast`。
  3. 禁止の列を消した表から、全切り口が作れる。
- tp-75 の正規表現（`MARKET_TOKENS`）は `p_pop` や `q` を拾わないので使わない。
