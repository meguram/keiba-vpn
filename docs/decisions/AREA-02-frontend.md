## 0. 改訂方針

本ドキュメントは `keiba-vpn-git` 既存実装のUIを基準として、新アーキテクチャ（AREA-01 仕様）向けに再定義する。
**継承対象**: デザインシステム・ページ構成・ユーザー向け情報提示・インタラクションパターン
**非継承対象**: DB スキーマ・スクレイピング実装・ML パイプライン（AREA-01/03/06/07 で管理）
管理者専用ツール（スクレイプ操作・キュー監視・ログ閲覧）はユーザー機能ではないため本仕様に含めない。

### 4-5. AI予測: 成長曲線 (`/growth-curve`)

**目的**: 1頭の馬のキャリアアーク（馬体重・タイム指数の推移）を可視化。

**コントロール**:
- 馬名オートコンプリート検索（300ms デバウンス）
- 表示件数選択（5/10/20/30/50/全て）
- 強制再読み込みボタン

**サマリーカード**: 最高着順、平均着順、総出走数、馬体重変動幅、デビュー体重、直近3戦平均、デビューとの体重差

**フィルターバー**: 馬場種別チップ（芝=緑 / ダート=橙 / 障害=紫）、距離 min/max、自動生成プリセット

**グラフ1 — 馬体重 × タイム指数**（Chart.js v4、デュアルY軸 棒+折れ線）
- 棒グラフ = 馬体重（馬場種別 × 距離で色相変化: 芝=142°/ダート=30°/障害=270°）
- 折れ線 = タイム指数（金 `#d29922`）
- 閾値ゾーン: 100（緑）、110（黄）
- 着順バッジ（オーバーレイ）

**グラフ2 — レース間隔 × タイム指数**
- 棒グラフ = 間隔週数（<2週=赤 / >13週=青 / 通常=灰）
- 折れ線 = タイム指数
- 着順バッジ

**レーステーブル**: 日付・競馬場・レース名・コース（馬場+距離）・着順（金/銀/銅）・馬体重・増減・間隔・タイム・指数

URL state: `?horse_id=X&limit=N`

### 4-6. データ分析: トラックスピード指数 (`/track-speed`)

**目的**: 競馬場・馬場ごとの速度レベルを Z スコア正規化指数（TSI）で表示。50=標準、高=速い。

**コントロール**: 日付選択、開催場選択、表示ボタン

**スピードレベル凡例（5段階）**:
| レベル | 名称 | 色 |
|---|---|---|
| 5 | 超高速 | `#ef4444`（赤） |
| 4 | 高速 | `#f97316`（橙） |
| 3 | 標準 | `#a3a3a3`（灰） |
| 2 | 低速 | `#3b82f6`（青） |
| 1 | 超低速 | `#8b5cf6`（紫） |

**表示セクション**:
- **日付別タイムライン**（折りたたみ可能）: 日付ラベル・曜日（土=青/日=赤）・開催場バッジ（TSI値 + スピードレベルバッジ + サンプル数）
- **開催場詳細パネル**（展開可能）: レース別テーブル（R・距離・グレード・タイム・基準タイム・Z値・ペース補正後Z・TSI）。芝行=緑左枠 / ダート行=橙左枠。
- **メインレーステーブル**: R・コース・グレード・馬場状態・レース名（netkeiba リンク）・タイム・基準・Z値・ペース補正・TSI指数・PF指数・PF(2000m)。ソート可・行クリックで馬別サブテーブル展開（着順: 1着=金/2着=accent色）。
- **コースカテゴリ検索**: 開催場+馬場+スピードカテゴリ選択、結果テーブル（ページネーション付き）
- **分布チャートセクション**: 開催場別 SVG スパークチャート（TSI 経時変化）

### 4-7. データ分析: レース品質分析 (`/race-quality`)

**目的**: NNLS（非負最小二乗法）による8アーキタイプのレース分類。

**コントロール**: 日付選択・開催場フィルタ・レース選択・手動日付入力・開催日まとめ読み込みボタン・単レース分析ボタン

**表示モード**:
- **日単位ビュー**: 水平スタック棒グラフ（√頭数 加重平均、1棒=1開催日）
- **セグメントビュー**: 馬場・距離セグメント別スタック棒グラフ

**レーステーブルカラム**:
- 条件帯・場所・距離/馬場/コース
- 消/溜/均 ペース形状（0-100）
- レース名（`/race/{id}` リンク）・頭数・R²
- 上位傾向（上位3アーキタイプラベル + %）
- 分布（ミニスタック棒グラフ）

**単レースビュー**: アーキタイプ別確率バー行（% + R² + ペース形状）

**適性マトリクスパネル**: 馬 × 8軸 ヒートマップ（レース選択時自動表示）

### 4-9. 血統: クラスター検索 (`/bloodline-cluster`)

**目的**: 馬または種牡馬の血統クラスター分類と適性プロファイルを検索表示。

**検索結果 — 適性プロファイルカード**:

- 注目パターンセクション: 期待値から大きくズレる条件のグリッド
- レース記録詳細（折りたたみ可）: 条件グループ別テーブル（馬場×距離×クラス）、複勝率・サンプル数・P値マーカー

### 4-13. 血統: Myostatin 遺伝子 (`/myostatin`)

**目的**: MSTN 遺伝子型（CC/CT/TT）ごとの距離適性を追跡・可視化。

**遺伝子型カラー**:
- CC = 赤（短距離型）
- CT = 金（中距離型）
- TT = 緑（長距離型）

**表示内容**:
- 統計行: CC・CT・TT・Total カウントカード
- **散布図** (Chart.js v4): X=平均勝利距離(m)、Y=Cアレル確率、遺伝子型別カラー、信頼度別ドットサイズ（confirmed=10px, highly_likely=8px, estimated=6px, inferred=5px）
- **遺伝子型分布（ドーナツグラフ×3）**: ナレッジベース / 実測 / オープンクラス
- **育種シミュレーター**: 父・母父入力（datalist オートコンプリート）・距離入力 → CC/CT/TT 確率バー + 適合メッセージ
- **最新知見パネル**: 日付バッジ付き研究更新カード＋影響タグ
- **馬テーブル**: 馬名・英名・型バッジ・信頼度バッジ・C%・T%・平均勝距離・系統・根拠（展開可）。ソート可・検索ボックス・フィルターボタン。
- **系統別遺伝子型分布（積み上げ棒グラフ）**: 種牡馬系統別 CC/CT/TT 積み上げ

### 4-14. 馬券最適化 (`/betting`)

**目的**: Kelly 基準による最適馬券ポートフォリオ生成（ログイン必須）。

**入力フォーム**:
- レース ID（12桁）
- 資金（bankroll、デフォルト 100,000円）
- Kelly 倍率（デフォルト 0.25、範囲 0.05-1.0）
- 最低 EV 閾値（デフォルト 1.05）
- 馬券種別チェックボックス: 単勝・複勝・馬連・ワイド・馬単

**結果パネル**:
- 統計行: 投票総額・期待回収額（プラス=緑/中立=橙/マイナス=赤）・期待 ROI・残資金・投票数
- **投票ポートフォリオ**（左）:
  - 配分バー（馬券種別ごとのスタックセグメント）
  - テーブル: 種別バッジ・組み合わせ・オッズ・確率・EV バー（≥1.5=緑 / ≥1.1=橙 / 他=赤）・Kelly%・投票額・期待回収
- **馬ごとの勝率バー + Kelly 配分チャート**（右）

**馬券種別バッジカラー**: 単勝=赤 / 複勝=緑 / 馬連=青 / ワイド=紫 / 馬単=橙

## 5. 技術要件

### 5-1. フレームワーク・ライブラリ

| 項目 | 採用 | 理由 |
|---|---|---|
| フレームワーク | Next.js 15（App Router） | SSR/ISR/CSR 混在、既存 Next.js 環境踏襲 |

| グラフ（D3） | D3.js v7 | 血統マップのフォースレイアウト・SVG 操作 |
| スタイリング | Tailwind CSS v3 + CSS Variables | デザインシステム変数管理 |
| 国際化 | 日本語専用（i18n 不要） |  |

### 5-2. レンダリング戦略

| ページ | 戦略 | 理由 |
|---|---|---|
| ダッシュボード (`/`) | ISR（revalidate 60s） | 開催日リストは頻繁に変わらない |
| レース一覧 | ISR（revalidate 120s） | 発走まで数日間安定 |
| レース詳細 — 出馬表タブ | ISR（revalidate 3600s） | 出馬確定後ほぼ変化なし |
| レース詳細 — 結果タブ | ISR（revalidate 300s） | 発走後30分で確定 |
| レース詳細 — AI予測タブ | CSR（SWR、TTL=発走まで） | オッズ連動でリアルタイム性必要 |
| 成長曲線・馬詳細 | CSR | ユーザー操作依存 |
| 血統ベクトル空間 | SSG（Server-injected JSON） | 事前計算データのみ |
| 血統マップ | CSR + SSG | D3 描画はクライアント |
| トラックスピード | CSR | 日付選択による動的ロード |

### 5-3. パフォーマンス目標（AREA-01 N-1/N-2 準拠）

| シナリオ | 目標 |

| LCP（Largest Contentful Paint） | ≤ 2.5s（3G） |
