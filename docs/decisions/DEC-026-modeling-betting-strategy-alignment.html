DEC-026: モデリング戦略と馬券戦略（EV・Kelly最適化）の整合

PROPOSED 日付: 2026-09-26　|　関連 AREA: AREA-07（モデリング管理要件）, AREA-12（馬券シミュレーション）

1. コンテキスト

現行のモデリング仕様（AREA-07 Stage 1〜3: T-1〜T-9）は、AUC・Log Loss・RMSE・Spearman相関といった 汎用的な機械学習評価指標でCIゲート判定されている（AREA-07 §6-2「T-1: AUC ≥ 0.65、Log Loss ≤ 0.65」）。 一方、馬券適用（AREA-07 §10 Stage 4: Betting Strategy）は、Stage 1〜3の出力を「与えられた入力」として受け取り、 EV計算・Kelly基準・段階的RL投入を行う、完全に独立した後段レイヤーとして設計されている。

この分離設計には、以下の構造的なリスクがある。

リスク1: キャリブレーション未保証

AUCは順位の分離度（discrimination）を測る指標であり、確率値の絶対的な正確さ（calibration）を保証しない。 EV = 確率 × オッズ という計算はキャリブレーションされた確率を前提とするため、AUC 0.65 を通過したモデルでも、 確率の絶対値が歪んでいれば EV 計算・Kelly 比率が体系的に誤る。

リスク2: 市場対比評価の欠如

馬券で利益を出すには「オッズに内包された市場予想」より優れている必要があるが、現行のCIゲートはモデルの絶対精度のみを見ており、 市場（オッズ由来の implied probability）との相対比較を評価指標に含めていない。的中率が高くても市場と同程度の予測であれば、 控除率（約20〜25%）分だけ負ける。

リスク3: 不確実性の未定量化とKellyの過信リスク

AREA-07 §10-6 の Kelly 実装は固定 Fractional Kelly（fraction=0.25）であり、個々の予測の確信度 （分散・信頼区間）を反映していない。モデルが実際より過信した確率を出す局面（データが薄いレース条件等）でも同じ 0.25 倍で賭けてしまい、 過大なドローダウンリスクを抱える。

リスク4: レース内ベット間の相関未考慮

単勝・複勝・馬連・ワイド・馬単は同一レースの同じ確率分布から派生する高相関な賭けである。AREA-07 §10-7 の的中率バランス制約は 「1レース最大5件・同一馬券種最大2件」という件数フィルタのみで、複数ベットの相関によるポートフォリオ全体のリスク集中を 考慮していない。

リスク5: モデル選定の目的関数がROIと未接続

Stage 1-3 のハイパーパラメータ探索（docs/html/modeling/hyperparameter_tuning_workflow.html）は AUC / Log Loss の改善を目的関数としているが、最終的な事業目標は馬券利益であるため、AUC 改善が必ずしも ROI 改善と一致しない （favorite-longshot bias 等により識別力と収益性が分離するケースがある）。

2. 決定事項

上記5つのリスクに対応する5つの決定を行う。すべて既存の Phase 5a/5b/5c 段階投入方針（AREA-07 §10-1-2）と両立する形で、 段階的に追加する。

D-1: T-1〜T-3 にキャリブレーション評価を追加のCIゲートとする

Brier スコアおよび reliability diagram の傾き（または Expected Calibration Error）を、既存の AUC / Log Loss に加えた 必須評価指標とする。閾値は初期運用データから設定し、モデル再学習ごとに算出・記録する。

D-2: 「市場対比優位性」を主要評価軸に追加する

オッズから導出した implied probability（1/オッズを正規化）をベースラインとし、モデルの予測がこのベースラインに 対して Log Loss 差分・Brier 差分で優位であるかを評価する。Stage 4 のバックテスト ROI 評価（AREA-07 §10-9-3 ROIゲート）は この考え方を部分的に体現しているが、Stage 1-3 のモデル選定・アーキテクチャ比較の段階でも同様の市場対比指標を用いる。

D-3: Kelly比率をモデルの不確実性に応じて動的に調整する（Uncertainty-scaled Kelly）

固定 fraction=0.25 に加え、アンサンブル分散（LightGBM の複数シード学習や bootstrap）から推定した予測の 信頼区間の広さに応じて fraction を縮小する仕組みを、Phase 5a〜5b のいずれかの段階で導入する。信頼区間が広い （データが薄い）レースほどベット比率を抑える。

D-4: レース内ポートフォリオでのリスク集中を制御する

AREA-07 §10-7 の的中率バランス制約に加え、同一レース内で選択された複数ベットの相関（例: 単勝と馬連は同じ馬の1着確率に 強く依存）を簡易的にペナルティ化する仕組みを追加する。厳密な相関行列によるポートフォリオ最適化は複雑化するため、まずは 「同じ馬を含む複数ベットの合計Kelly比率に上限を設ける」程度の簡易ルールから始める。

D-5: Stage 1-3 のハイパーパラメータ探索に、バックテストROI（またはKelly成長率）を二次評価指標として追加する

主目的関数は AUC / Log Loss（学習の安定性・解釈性を保つため）のまま維持するが、複数候補モデルの最終選定時に、 簡易バックテスト（過去データでの EV・ROI 計算）を通過基準に加える。AUC が同等な複数モデルがある場合、ROI が高い方を採用する。

3. 選択肢と比較

選択肢メリットデメリット
A. 現状維持（Stage1-3は汎用指標のみ、Stage4のみEV/Kelly） 実装がシンプル、既存パイプライン変更不要 モデルが市場に対して優位かを保証しない。Kelly過信によるドローダウンリスクを抱えたまま本番投入することになる
B.（採用）D-1〜D-5 を段階的に追加 馬券戦略との整合性が向上し、過学習・過信リスクを低減。既存の Phase 5a/5b/5c 段階投入方針とも両立可能 追加の評価パイプライン実装コスト（キャリブレーション計測・市場対比評価・簡易バックテスト）
C. Stage1-3をKelly成長率でend-to-end最適化する 理論上最も馬券戦略と整合する 学習の複雑化・解釈性低下・VPS 2GB での学習コスト増。現状のプロジェクト規模・運用体制には時期尚早

採用: B。 C は将来的な発展方向として §5 に記録するが、現段階では A と C の中間である段階的強化が最も費用対効果が高い。
