# 改善要件定義書: keiba-vpn 競馬予想Webアプリ

> **バージョン**: v1.0  
> **ステータス**: 確定（全エージェント APPROVE）  
> **ベース**: 5ラウンドの自律的エージェント議論 + 既存アーキテクチャ決定（DEC-002: GCS採用, DEC-004: VPS 2GB制約, DEC-004: プロセス分離）  
> **技術スタック**: Python/Flask + GCS + Redis + Pub/Sub + LightGBM + React/Next.js

---

## サマリー

keiba-vpn は、日本競馬（JRA/NAR）のレースデータをスクレイピングして LightGBM モデルで予測し、Next.js フロントエンドに表示するマルチユーザー競馬予想Webアプリである。コアアーキテクチャは **GCS → Pub/Sub → Redis → Flask API → Next.js** のイベント駆動パイプラインで構成され、VPS 2GB メモリ制約内での安定稼働を最優先とする。スクレイピング・推論・API配信の3プロセスを明確に分離し、データ鮮度をUIまで一貫して伝播させることで「データなし・予測なし」によるユーザー離脱を最小化する。

## 機能要件

### F-A: データパイプライン（Data Pipeline）

| # | 要件ID | 要件内容 | 優先度 | 担当エージェント |
|---|--------|---------|--------|----------------|
| 1 | DP-01 | GCSへのレースデータ取り込みを発走 **T-90分前** までに完了すること | 高 | data-engineer |
| 2 | DP-02 | スクレイピング失敗時は最大3回リトライ（指数バックオフ: 30s → 60s → 120s） | 高 | data-engineer |
| 3 | DP-03 | データ欠損時は `v_latest-1`（1世代前）にフォールバックし `data_status: stale` フラグを付与 | 高 | data-engineer / backend-engineer |
| 4 | DP-04 | GCS Object Finalize イベントを Pub/Sub でサブスクライブし、Redis に `race_data_ready:{race_id}` フラグを立てること | 高 | data-engineer / backend-engineer |
| 5 | DP-05 | ETLパイプライン失敗時、5分以内に Slack 通知を送信すること | 中 | operations-engineer |
| 6 | DP-06 | `v_latest` + `v_latest-1` を常時保持し、それ以前は7日後に GCS Lifecycle Policy で自動削除 | 中 | data-engineer |

**データステータス定義**（API・UI全層で共有）

| `data_status` 値 | 意味 | 発生条件 |
|-----------------|------|---------|
| `fresh` | 最新データ取得成功 | `v_latest` 正常取得 |
| `stale` | 前バージョンデータ使用中 | `v_latest` 失敗 → `v_latest-1` 取得成功 |
| `unavailable` | データ取得不可 | 両バージョン失敗 |

### F-B: AI 予測モデル（Prediction Model）

| # | 要件ID | 要件内容 | 優先度 | 担当エージェント |
|---|--------|---------|--------|----------------|
| 7 | PM-01 | 単勝予測の的中率（推薦1位馬の実際勝率）**≥ 30%** を中期目標とする。初期リリース目標は **≥ 20%** | 高 | ai-model-engineer |

| 10 | PM-04 | 各馬に **信頼スコア（0〜100）** を付与・表示。stale データ推論時は **-10pt** のペナルティを適用 | 中 | ai-model-engineer |
| 11 | PM-05 | モデル再学習は **週次バッチ**（毎週月曜 03:00 JST） | 中 | ai-model-engineer |

| 13 | PM-07 | A/Bテスト対応: `v_current` / `v_challenger` を **50:50** でユーザーIDハッシュにより決定論的に振り分け可能なこと | 低 | ai-model-engineer / backend-engineer |

**SHAP 根拠の自然言語マッピング**（最低限定義）

```python
SHAP_TO_TEXT = {
    "recent_avg_rank":  "過去成績: 直近{n}走平均着順 {val}位",
    "track_win_rate":   "馬場適性: {surface}馬場勝率 {val:.0%}",
    "jockey_combo_wr":  "騎手相性: このコンビ過去{n}走勝率 {val:.0%}",
    "weight_diff":      "斤量変化: 前走比 {val:+.1f}kg",
    "odds_rank":        "オッズ: 現在{val}番人気",
}
```
