# 公開面の出どころ台帳と許可リスト

目的: 一般公開（不特定多数）の画面・API に出してよい情報を、出どころで分類し、**サーバー側で強制**する。正は `config/public_fields.json`（このファイルは説明）。実データの値は書かない。

## 背景（規約）
- netkeiba 利用規約 第14条(1): サービスで入手したデータ等を、私的利用の範囲を超えて複製・販売・出版に使うことは不可。『不特定または多数の者が知りうる状態におく行為は、いかなる目的でも私的利用の範囲を超える』。第15条(1): 営利目的は不可（承認で例外）。
- **『JRA にも載っている情報だから出所は分からない』は安全地帯ではない。** netkeiba から取得して再掲すれば、第14条の対象になりうる。公開する事実情報は、取得元を切り替える（または出さない）。
- JRA 側: アプリ規約（sp.jra.jp/app/terms.html）は JRA アプリの規約で、ウェブサイトの規約ではない。ウェブサイト『ご利用に際して』（www.jra.go.jp/use/）は、映像・音声・画像・記事の二次利用に許諾を求める（申請は法人のみ）。自動アクセスの禁止・頻度制限の記載はなく、**出馬表・オッズ・結果・払戻など事実データの扱いは記載がない（法的に未確定）**。JRA-VAN への言及はない。
- 法的判断は専門家に確認する。以下は設計。

## データの取得元（ユーザー確認 2026-10-22）
- **取得元は netkeiba のみ**（JRA-VAN・JRDB・JRA 公式の出馬表等は未使用。JRA 公式は馬場・カレンダーのみ）。SmartRC の取得は別に存在する（別規約＝要確認）。
- したがって保存データの出どころ（`src/utils/provenance.py`）は、現状**すべて netkeiba（SmartRC 由来は smartrc）**。
- **A（自前計算）も、netkeiba 由来のデータを学習・入力に使った派生物**。勝率・印などの出力そのものは自前の計算結果だが、法的に完全にクリアとは言えない（第14条は『サービスで入手したデータ等』の転載・公開を対象にしており、学習済みモデルの出力の扱いは条文に明記がない）。専門家の確認が望ましい。

## 分類
| 分類 | 意味 | 一般への既定 |
|---|---|---|
| A | 自前計算（勝率・連対率・複勝率・印・展開予想・めぐ指数・成長度など） | 出す |
| B | 取得した事実（出馬表・結果・払戻・馬体重・コース） | 出さない（取得元が確定し、承認が出るまで） |
| C | 取得元に固有で代替が難しい（指数・パドック・バロメーター・厩舎コメント・調教・過去走の表・各種 ID・成績集計の元データ・SmartRC 由来。SmartRC は別規約＝要確認） | 出さない |
| O | 市場オッズに由来（オッズ・人気・期待値・買い目のオッズ・買い判断） | 出さない。**期待値と勝率が両方出るとオッズを逆算できる**ので、オッズと同じ扱い |

| 画面・API | 一般（匿名） | 一般（会員） | 開発者（所有者） |
|---|---|---|---|
| 週間予測・レース詳細の予測（`/api/race/{id}/predictions`） | 勝率・複勝率・順位（A） | ＋連対率・めぐAI印・展開予想・めぐ指数・成長度（A） | 全項目 |
| レース詳細（`/api/race/{id}`） | レース ID だけ | 同左 | 全項目 |

## 切り替えスイッチ（`config/public_fields.json`）
- `mode`: `private`（現状。Cloudflare Access で所有者のみ。従来の匿名／会員の出し分けのまま）／`public`（一般公開用）。環境変数 `KEIBA_PUBLIC_MODE=public|private` で上書き。**設定ファイルが読めないときは安全側（public・何も許可しない）。**
- `release.minimal_identifiers_public`: 馬番・馬名・レースの識別だけ出す。
- `release.b_facts_public`: 出馬表・結果などの事実（B）を出す。
- `release.odds_derived_public`: オッズ由来（O）を出す。会員にだけ出る（匿名には出ない）。
- C は、どのスイッチでも出ない（テストで全 8 通りを検査）。

## 取得元の選択肢（B・O の公開に必要）
| 案 | 内容 | 長所 | 短所・不確かな点 | 必要な手続 |
|---|---|---|---|---|
| ① 正式ライセンスのデータ | JRA-VAN などの公式配信データ | 公開・商用の条件が明確なことが多い | 費用・条件は要確認（一般に商用は許諾が前提）。この資料には根拠なし | 提供元に利用条件を確認・契約 |
| ② JRA ウェブサイトの範囲で利用 | `www.jra.go.jp` のテキストの事実データ（出馬表・結果・払戻・オッズ）を取る | 技術的には可能。既存の JRA 取得（馬場・カレンダー）と同じ系統 | **法的に未確定**（事実データの扱いが規約に無い。画像・記事・映像は不可。二次利用の許諾申請は法人のみ） | 利用条件の確認（問い合わせ）、ユーザーの最終承認。承認まで `KEIBA_JRA_PUBLIC_FETCH` は無効 |
| ③ 権利者の承認 | netkeiba／JRA などに書面で承認を得る | 最も確実 | 時間がかかる・営利は不可の可能性 | 申請（法人要件を含む） |
| ④ 縮小案 | 事実情報は一般に出さず、自前の出力（勝率・印・展開予想）だけ | 規約リスクが最小。すぐ公開できる設計 | 馬名・馬番すら出せないと使いにくい（識別だけ出す案は `minimal_identifiers_public`） | なし（現在の既定） |

## JRA 事実データ取得（部品のみ・既定で無効）
- `src/scraper/jra_facts.py`: テキストの事実（出馬表・結果・オッズの表）だけ。画像・映像・音声・記事・PDF は取らない（Content-Type で拒否）。
- 実アクセスは `KEIBA_JRA_PUBLIC_FETCH=1` のときだけ。JRA 公式（`https://www.jra.go.jp/`）以外は拒否。単一接続・最短 30 秒間隔・1 日 300 件まで。**承認が出るまで cron には載せない。**
- 表の見出しの語から列を対応づける方式で、読めない表は保存しない（None）。実ページとの突き合わせは未実施（承認後）。
- 保存は `_meta.source = "jra"`（`src/utils/provenance.py`）。保存カテゴリ案: `race_shutuba_jra` / `race_result_jra` / `race_odds_jra`（`CATEGORY_MAP` とスキーマへの登録は承認後）。

## 出どころの追跡（provenance）
`src/utils/provenance.py`: 保存データの `_meta.source`（own／jra／netkeiba／smartrc／unknown）。既存の取得データは取得元が netkeiba なので、カテゴリ別の既定を持つ。不明は一般に出さない。JRA は規約確認（`jra_ok`）が済んでから一般に出せる。

## ユーザーに決めていただくこと
1. 公開時に出す事実情報の範囲（`minimal_identifiers_public` のみ／B まで／出さない）。
2. 取得元（上の①〜④）と、問い合わせ・承認の進め方。
3. オッズ由来（想定単勝・期待値・推奨馬券）を会員向けに出すか。取得元が確定するまで出せない。出さない場合、有料会員の価値は『めぐAI印・連対率・展開予想』になる。
4. JRA 事実データの取得（`KEIBA_JRA_PUBLIC_FETCH`）を、確認のうえ試すか。

## 運用モード（3 段階）
| 段階 | 内容 | 設定 | 規約上の位置づけ |
|---|---|---|---|
| 1 私的限定（現状） | Cloudflare Access で所有者だけが見る。全項目 | `mode=private` | 私的利用の範囲（第14条）。最も安全 |
| 2 非営利で出力のみ公開 | 無料・広告なし・個人運営。A（自前の出力）だけを公開。B/C/O は出さない | `mode=public`、`release` は全て false（現在の既定） | グレー。不特定多数への公開は第14条の私的利用の範囲外とされうるが、netkeiba の事実データそのものは出さない。A が派生物である点は未確定 |
| 3 商用（広告・有料会員） | 営利。B/O の公開も含みうる | 取得元の切り替え、または netkeiba の承認が前提 | 第15条(1)で営利は不可（承認で例外）。**netkeiba 承認、または取得元をライセンスデータへ切り替えるまで不可** |

段階 2 と 3 の間で、有料会員の価値は『めぐAI印・連対率・展開予想』になる（オッズ由来の想定単勝・期待値・推奨馬券は、取得元が確定するまで出せない）。

## 取得元切替の影響調査（概算・実アクセス／購入なし）
パイプラインが読む netkeiba 由来のカテゴリと、ライセンスデータ（JRA-VAN Data Lab.・JRDB など）で代替できる範囲の見立て。**各社の提供項目・利用条件・価格は未確認**（要確認）。「代替」は『同等の項目が提供される見込み』であって確認済みではない。

| カテゴリ（読む箇所の目安） | 内容 | 代替の見込み | 再学習への影響 |
|---|---|---|---|
| race_shutuba（出馬表。約 10 箇所） | 馬・騎手・斤量・馬体重ほか | 高（出馬表は標準的な提供項目） | ID の対応づけが必要。特徴量は再構築、モデルは再学習 |
| race_result / race_result_on_time（約 17 箇所） | 着順・タイム・上がり・通過順・払戻・ラップ | 高 | ラベルと履歴特徴量の元。再構築＋再学習（大） |
| horse_result / horse_profile / horse_race_history（約 16 箇所） | 過去走・馬の属性・成績 | 中〜高（過去走は結果データから再構成できる） | 履歴特徴量（127 列ほか）の再構築＋再学習（大） |
| horse_pedigree_5gen（血統） | 5 代血統 | 中〜高（血統データの提供があれば） | 血統特徴量・血統グループの再構築（中〜大） |
| race_odds / race_pair_odds / race_trifecta_odds | 単複・馬連・ワイド・3連複・3連単オッズ | 中〜高（オッズ配信があれば） | 特徴量には使っていない。期待値・買い目・較正の再検証（中） |
| horse_training / race_oikiri（調教） | 追い切り・ラップ | 中（調教データの提供があれば） | 調教特徴量（TL 系）の再構築＋再学習（中） |
| race_shutuba_past / race_index（指数） / race_barometer / race_paddock / race_trainer_comment | 馬柱・独自指数・バロメーター・パドック・厩舎コメント | 低〜中（netkeiba 独自の指数は代替が難しい。JRDB に近い指数がある可能性＝要確認） | 指数系は特徴量に使わない構成が多い（tp-03）。使っている列は再学習（小〜中） |
| race_lists / race_day_schedule / jra_cushion | レース一覧・日程・クッション値 | 高（JRA 公式で既に取得） | 小 |
| smartrc_race / smartrc_prerace | SmartRC 由来（テン 1F など） | SmartRC の規約次第（要確認） | 前段モデル（位置取り等）の再学習（中） |

- 全体の見積り: 取得元を替えると、**ID（馬・騎手・調教師・レース）の対応表、特徴量ストアの全再構築、全モデルの再学習**が要る（モデリング全体のやり直し相当。実行はホストの研究用途）。差し替えと検証は数週間規模の見込み（概算）。
- 先に決めること: 段階 3（商用）を目指すか。段階 2 までなら、取得元の切り替えは必須ではない。
