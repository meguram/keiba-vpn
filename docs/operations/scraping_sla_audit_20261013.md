# スクレイピング SLA・スケジュール穴の監査（2026-10-13）

対象: 全スクレイピングエンドポイントについて「いつから取得できるか（SLA）」と「誰がいつ取りに行くか」を突き合わせ、穴を洗い出した。
機械可読の仕様は `src/scraper/sla_spec.py`、整合テストは `tests/scraper/test_sla_spec.py`（タスクを足したら仕様も足さないと落ちる）。

根拠は 2 つ: (1) 2026-10-13（火）に実 netkeiba へ約 158 リクエストの 1 点観測（10/12 月祝・10/11・10/4 のレースと、翌 10/17 の開催前データ）、
(2) コードと、この PC にインストール済みの crontab / ログの照合。**1 点観測では分からないもの（何曜何時に枠順・オッズ・追い切りが出るか等）は「要観測」**とし、
`python3 -m src.scraper.availability_watch --auto --yes`（dev 専用）を開催前週の水曜から回して first_seen_at を貯める。

## 1. 最重要: この PC では定期スクレイピングが 1 本も成功していない

| 事実 | 証拠 | 影響 |
|---|---|---|
| crontab の `python3 -m src.scraper.auto_scrape ...` 直呼び（daily-race-lists / catchup-missing / jra-baba-morning）は import で全滅 | `logs/auto_scrape_race_lists.log` 等が `ModuleNotFoundError: No module named 'bs4'`（今朝 07:00・09:00 も）。cron の PATH は `/usr/bin:/bin` で、そこの python3 に bs4 が無い（conda の python3 にはある） | レース一覧が更新されない（10/17 は火曜時点 14R のまま）／馬場情報が取れない／欠損補完が動かない |
| `scripts/auto_scrape.sh`（runner / result_runner / raceday / thu / fri_night）はログに残る実行（10/10〜10/11）がすべて `Permission denied` | `logs/auto_scrape.log`・`auto_scrape_result.log`。当時は実行ビットが落ちていた（現在は git 管理どおり 755 で解消済みに見える） | ログ上、10/10・10/11 の開催日ランナー・夕方結果は動いていない（取得済みデータの出所は手動実行・別経路） |
| `setup_all_cron.sh` は **UTC マシン前提**（22:30 = JST 07:30）。この PC は `Asia/Tokyo` | `/etc/timezone` | このまま `install` すると全ジョブが 9 時間ずれる。インストール済みの crontab は別途手書き（JST 直書き）で、設計と食い違っている |

→ 対策（コード側は実施済み）: 全ジョブを `scripts/auto_scrape.sh <mode>`（conda python 固定）経由にし、モードを追加（`eve / weekly / name_index / race_lists / baba / barometer`）。
JST マシン用の雛形 `scripts/cron/crontab.jst.example` を追加。**crontab の入れ替えは未実施**（他プロジェクトの行を含む個人環境の設定なので、承認後に実施）。

## 5. 設計書の訂正（実測で分かったこと）

- 3連複（API type=7）は 6 桁キー・組合せ数 C(n,3) で一致。
- タイム指数は「金曜週次まで待つ」ではなく**翌日には取得可**。
- バロメーターは**レース翌週の金曜 18 時頃**（応答に「公開予定」表示）。障害レースは対象外。
- パドック評価は全レースで**常に 5 頭**（上位表示のみの可能性）。
- 結果ラップは翌日に取得可だが要ログイン。

## 6. 要観測（1 点観測では不明）

枠順確定・馬体重・オッズ発売・追い切り・厩舎コメント・パドックが**何曜何時に初めて出るか**、結果・ラップが**発走何分後に出るか**。
`availability_watch` を水曜〜開催後の金曜まで 30 分毎（開催日は 10 分毎）に回し、`--report` で first_seen_at を確認する。結果で `sla_spec.py` の `available_from` を確定させ、T-60 / T-15 の妥当性（取得時刻の最適化）を再評価する。cron 登録は未実施（承認待ち）。

## 7. 判断が必要なこと

1. この PC の crontab を雛形（`scripts/cron/crontab.jst.example`）に入れ替えてよいか。この PC が本番スクレイパかも含めて確認したい（他 PC が担当ならその PC で）。
2. バックフィル（深夜）をこの PC でも回すか。
3. `availability_watch` を cron（開催前週水曜〜）に載せるか。
4. G9/G10 の取得対象を増やすか（trainer_comment・race_result_lap・race_index の翌朝取得）。
