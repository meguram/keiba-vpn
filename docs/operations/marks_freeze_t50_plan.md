# 印を T-50 で 1 回固める設計（2026-11-25、scope-fix。設計だけ。実装は門 B と承認の後）

## 結論

- 今の印（`mark_type`）は、予測の要求のたびに、その時のオッズと買い目から作り直している（`src/api/app.py` の `_with_bet_marks` → `_with_complete_marks`）。オッズが動くと、同じレースの印が時刻で変わる。
- 発走 50 分前（T-50）に 1 回だけ印を決めて保存し、以後はその保存を返す。画面には「印は ◯時◯分（発走 50 分前）に確定」と時刻を出す。
- T-50 より前は、今の作りの印を「暫定」として出す（会議の決定が出たら、T-50 まで印を出さない形にも替えられるようにする）。
- 予測成績は、固めた印で集計する（記録の印の数え直しは bet-optimizer の件 2 の承認の後）。

## 作り

| 段 | 内容 |
|---|---|
| 決める処理 | ホストの当日の処理（cron）で、発走 50 分前を過ぎたレースを 1 回だけ処理する。入力は、T-50 までに書かれた予測と T-60 の単勝オッズの手元の写し。印の作り（印のルール → 買い目からの印 → `complete_marks`）は今と同じ関数を使う |
| 保存 | `inference/marks_frozen/<日付>/<race_id>.json`。中身は `{"race_id", "frozen_at", "basis": "t50", "marks": {馬番: mark_type}, "scratched": [馬番]}`。1 度書いたら上書きしない（取消は別の欄に足すだけで、ほかの馬の印は付け直さない） |
| 返す側 | 予測の応答の最後の段で、固めた印があれば、それで `mark_type` を置き換える（`complete_marks` の代わり）。応答に `marks_frozen_at` を足す。無ければ今の作り（暫定）で、`marks_frozen_at` は付けない |
| 画面 | ◎ のそばに「印は ◯時◯分に確定」。暫定の間は「印は発走 50 分前に確定します」。会議の固定の文（「◎ は AI の評価 1 位。勝つ馬の予言ではありません。」ほか）は承認の後に足す |
| 無料の印 v2 | `public_mark_type` の影の記録（`src/research/public_marks/marks.py`）と同じ T-50・同じ入力にそろえる。全員の印を v2 に替えるときは、決める処理の中身だけを替える |

## 費用

- 決める処理はホストの手元の写しを読むだけで、GCS の読み出しは増えない（T-60 のオッズ・予測は手元にある）。
- 保存は 1 レース 1 回の書き込み。開催日 1 日 36 レースなら、GCS への書き込み（Class A）は 1 日 36 回・月 約 300 回で 0.3 円未満（ミラーの push に乗せる）。
- Cloud Run 側は、ミラーの写しを 1 件読むだけで、要求の数は変わらない。

## 決めておくこと（承認の前に）

- T-50 より前に印を出すか（暫定で出す／出さない）。
- 取消が出たとき、印の付いた馬が取消なら、その印を空けるか（今の v2 は空けたまま）。
- 予測成績の過去分（11/21〜23 など）は、固めた印が無いので、今の印のまま残すか、`complete_marks` で数え直すか。
