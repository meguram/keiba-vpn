# 月額コスト試算（確定アーキテクチャ）

**最終更新**: 2026-10-02
**対象**: [vps-gcp-responsibilities.md](./vps-gcp-responsibilities.md)「確定アーキテクチャ」の構成
**関連**: [deployment-vps-vs-gcp.md](./deployment-vps-vs-gcp.md) / [gcp-cloud-run-jobs.md](./gcp-cloud-run-jobs.md)

> **重要**: 金額はすべて**概算**（作成者の知識ベース。為替は$1=¥150）。GCPの料金改定・リージョンで変わる。
> 採用前に [GCP料金計算ツール](https://cloud.google.com/products/calculator) で確認し、運用開始後は日次コスト通知
> （`python -m src.scripts.cloud_jobs.gcp_daily_cost_report`）の**実績で本書を更新**すること。
> 「要記入」はユーザーの契約内容・データ量に依存し、見積れていない。

## 1. 試算の前提（確定した構成）

| 領域 | 構成 | 費用の扱い |
|---|---|---|
| **ConoHa VPS**（2GB/3コア/SSD 100GB） | ページ配信・API・Redis・スクレイピングcron・T-45推論（まず） | **契約済み（〜2028/05/18）。追加費用0** |
| **別PC**（ローカル） | 学習（アンサンブル・バックテスト） | GCP費用0（学習データの取得で送信料金のみ） |
| **GCP** | Cloud SQL（stg/prod共用1台）、GCS、重い集計・再構築ジョブ（Cloud Run Jobs＋Scheduler）、日次コストレポート | 本書の対象 |
| dev環境 | ローカルdockerのPostgres/Redis、GCS無効 | 0 |

## 2. 固定費（使っていなくても毎月かかる）

| 項目 | 構成 | 月額（USD） | 月額（円） |

| **Cloud Scheduler** | 集計系の約10ジョブ（3ジョブまで無料、超過は1ジョブ月$0.10） | 約$0.7 | 約¥105 |
| **固定費 小計** | | **約$12〜14** | **約¥1,750〜2,050** |

## 3. 従量費（使った分だけ）

| 項目 | 想定 | 月額（USD） | 根拠・前提 |
|---|---|---|---|
| **Cloud Run Jobs**（集計系） | 日次: 騎手調教師統計・レース質・precompute・GCS→Cloud SQL同期、週次: 種牡馬集計・ベースライン・種牡馬ツリー等。合計で約8.5万vCPU秒・17万GiB秒/月（**ジョブ時間は仮定**） | $0〜3 | 無料枠（約18万vCPU秒・36万GiB秒/月）の約半分。ジョブが2倍重くても概ね枠内 |
| **ネットワーク送信（GCS/Cloud SQL → VPS）** | 画面表示・特徴量・モデル取得のための読み出し。VPSのキャッシュが効くほど減る | **$0.6〜6**（中央$2.4） | 約$0.12/GB。月5GB〜50GBを想定。**最大の不確定要素** |
| **GCS ストレージ・操作** | データ量は**要記入**（例: 100GBで約$2.3）。VPSからの書き込み（スクレイピング結果）は操作課金が少額 | $1〜3 | 標準ストレージ約$0.023/GB・月 |
| **別PCへの学習データ取得**（GCS → 別PC） | 初回数GB＋差分 | $0.1〜1 | 約$0.12/GB。ダウンロード済みは差分のみ更新 |
| Artifact Registry | GCPジョブのDockerイメージ（直近数世代） | $0〜0.3 | 0.5GBまで無料、超過$0.10/GB |
| BigQuery（コスト通知） | 日次1クエリ | ほぼ$0 | 1TB/月まで無料 |
| Cloud Logging | ジョブのログ | $0 | 50GiB/月まで無料 |
| Cloud Tasks | **使用しない**（VPS推論のため）。GCP切替時のみ | $0 | 月100万オペレーションまで無料 |
| GitHub Actions / GHCR | デプロイ用ビルド | $0 | privateリポジトリの無料枠内 |

## 4. 合計（GCP分）

| | 低 | **中央（基準）** | 高 |
|---|---|---|---|
| 固定費 | $12 | **$13** | $14 |
| 従量費 | $2 | **$5** | $13 |
| **GCP 合計（USD）** | **約$14** | **約$18** | **約$27** |
| **GCP 合計（円）** | **約¥2,100** | **約¥2,700** | **約¥4,050** |
| + ConoHa VPS | 契約済み（36か月分を支払済み。月額換算は契約金額÷36を記入: **要記入**） | | |

中央値の内訳: Cloud SQL $12 + Scheduler $0.7 + Cloud Run Jobs $1 + 送信 $2.4 + GCS $2.3 ≒ $18。
**不確定要素の大きさ順**: ①ネットワーク送信（キャッシュの効き次第）、②GCSのデータ量、③Cloud Runジョブの実行時間。

## 5. 推論をGCPに切り替えた場合の増分（VPSのメモリ実測で不足と分かったとき）

| 項目 | 増分（月） | 前提 |
|---|---|---|
| Cloud Tasks（予約配信） | $0 | 開催日のレース数ぶんのタスク（月約300件） |
| Cloud Run（ワーカー、0台にスケールダウン） | $0〜1 | 月約300回×各60秒想定 ＝ 約1.8万vCPU秒。無料枠内 |
| 開催日の時間帯だけ最小インスタンス1（コールドスタート回避） | +$2前後 | 開催日の約9時間×月8日。**必要なときだけ**。概算 |
| モデルをGCSから読む送信 | $0 | 同一リージョン内 |
| **増分 合計** | **約$0〜3** | 基準の$18が約$18〜21になる |

→ 推論の置き場所による費用差は小さい。**切替は費用ではなくVPSのメモリで判断**する。

## 6. 費用を抑えるために採った判断（採用しなかった高額オプション）

| 項目 | 月額の目安 | 判断 |
|---|---|---|
| Cloud NAT（固定送信IP） | 約$32+ | 導入しない。スクレイピングはVPSの固定IPのまま |
| Memorystore for Redis | 約$35+ | 導入しない。RedisはVPSに残す |
| Cloud SQLをstg/prodで別インスタンス | +約$11〜13 | 1台を共用（DB名・ユーザーで分離） |
| Cloud SQLのHA構成 | 約2倍 | 単一ゾーン |
| スクレイピングをGCPの常駐ジョブで実行 | 約$3〜5 | VPSのcronに残す（追加費用0） |
| 学習をGCPのCloud Run Jobsで実行 | $0.5〜数ドル | 別PCで実施 |
| **上記をすべて採用した場合の比較** | **約$80〜100/月** | → 確定構成は**約$18/月（約¥2,700）** |

## 7. 不確実性の確認方法
1. **GCPの実績**: GCPコンソールで課金データのBigQueryエクスポートを有効化し、`GCP_BILLING_BQ_TABLE`を設定 → 毎朝7時にSlackへ前日のサービス別コストが届く。
2. **ネットワーク送信**: `/api/gcs-stats`（GCS APIコール数・キャッシュ統計）と、日次通知の「Networking」項目を見る。
3. **VPSの推論メモリ**: `python -m src.scripts.maintenance.measure_inference_memory --race-id <ID>` で確定。
4. 1か月分の実績がたまったら、本書の「要記入」と従量費を実績に置き換える。
