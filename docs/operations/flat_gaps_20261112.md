# データの欠け（2026-11-12 の調査）: めぐ指数・2026 年の馬柱などの flat

## 1. めぐ指数の flat が 10/30 から更新されていない

### 現状
- 欠けている日: 2026-10-31・11-01・11-07・11-08（10-25 までは作られている）。
- 4 日とも、ローカルの `race_result_flat` には結果がある。

### 経路
`weekly-update`（金 18:00）の `finalize_weekly_update` → `compute_megu_for_opening_dates`。

### 原因
1. 11/06 の週次は、キュー経由で動いた。
2. そのとき、11/01 のアクセス制限による保留（`scrape_access_pause`）がまだ有効だった。
3. `wait_until_queue_idle` が `paused` で打ち切られた。
4. `auto_scrape_queue.run_weekly_update_for_dates` が `status=error` で return し、めぐ指数の計算まで届かなかった。
5. cron の終了コードは 0 で、失敗がどこにも出なかった。

### 直したこと（コード）
- **欠けの日の補完:** 週次のめぐ指数の対象に、今回の開催日に加えて、次の日を足す（`auto_scrape.megu_missing_dates`）。
  - 直近 60 日のうち、ローカルの `race_result_flat` に結果があるのに、めぐ指数が 1 件も無い開催日
  - 補完の日は、索引の更新と PG 同期にも含める。
  - 読むのはローカルの parquet だけ。
  - 「最後に作れた日より後」に限らないのは、後ろの日が先に作られると前の欠けが拾われなくなるため（critic の指摘）。
    決まって作れない日は毎週やり直しになるが、費用はかからない。
- **打ち切りの扱い:** キュー待機が paused・timeout で打ち切られたときは、めぐ指数の計算に進まない。
  - Slack に失敗を通知し（実行した機械の名前つき）、終了コード 7 を返す。3 は dev での中止などと重なるので使わない。
  - この終了コードは、`run_auto_scrape_logged.sh` が cron の記録に渡す。
  - 非 0 にするのは、レース系（結果・指数・偏差値）の待機の打ち切りだけ。馬・血統の待機の打ち切りは warning だけで、後処理に進む。
  - 打ち切られた日の確定結果の取り直しは、次の週次の対象（直近 10 日）から外れると行われない。必要なら手で週次を回す。

### 作り直し（未実施・ユーザーの承認待ち）
- 次の週次（11/13）で 4 日とも埋まる見込み。
- すぐ埋めるときは、ホストで root で次を実行する。

## 2. 2026 年の馬柱・指数・SmartRC の flat が無い

### 対象
`race_shutuba_past`・`race_index`・`race_barometer`・`smartrc_race` の、`data/page_reference/tables/2026/*_flat.parquet`。

### 原因
止まったのではなく、もともと作る定期処理が無い。
- `export_tables_daily.sh` の既定のカテゴリ（CATS）にも、GCP の `export-tables-daily` にも入っていない。
- `backfill_past_sync.sh` は 2016〜2019 年だけ。
- 2025 年以前の分は、手動で全カテゴリを export したときに作られた。

### 1 回だけ作る（未実施）
```bash
python -m src.scraper.export_tables --years 2026 --categories race_shutuba_past,race_index,race_barometer,smartrc_race
```
GCS から約 3,000 レース × 4 種類の文書を読む。

| 項目 | 量 | ホストで動かす | Cloud Run Jobs（東京）で動かす |
|---|---|---|---|
| 一覧（Class A）| 4 種類 × 約 4 回 | 0.01 円 | 0.01 円 |
| 一覧の転送 | 4 × 約 2MB | 0.15 円 | 0 円 |
| 読み出し（Class B）| 約 12,000 回 | 0.7 円 | 0.7 円 |
| 読み出しの転送 | 約 3,000 × 約 70KB ≒ 0.2GiB | 約 3.6 円 | 0 円 |
| **合計** | | **約 4.5 円（1 回だけ）** | **約 0.7 円** |

1 レースの文書の大きさ（約 70KB）は推定。内訳は、馬柱 約 40KB・SmartRC 約 20KB・指数 2 種類 各 約 5KB。

### 毎日の増分（`--refresh`）で回す場合（CATS への追加はユーザーの判断）
`--refresh` は、カテゴリごとに GCS の一覧を 1 回取り、自分の flat に無いレースだけを読む。

前提:
- 新しいレースは、月に約 300 件（土日に約 72 件）。
- 一覧の転送は、1 回あたり約 2MB（約 4,000 件 × 約 500B）。

最悪の回数で見積もる。毎日 1 回 × 30 日 × 4 種類。

| 項目 | 1 か月の量 | ホストで動かす | Cloud Run Jobs（東京）で動かす |
|---|---|---|---|
| 一覧（Class A）| 4 種類 × 4 回 × 30 日 = 480 回 | 0.4 円 | 0.4 円 |
| 一覧の転送 | 4 × 2MB × 30 日 ≒ 0.23GiB | 約 4.2 円 | 0 円 |
| 読み出し（Class B）| 300 × 4 = 1,200 回 | 0.07 円 | 0.07 円 |
| 読み出しの転送 | 300 × 70KB ≒ 0.02GiB | 約 0.4 円 | 0 円 |
| **合計** | | **約 5 円/月** | **約 0.5 円/月** |

- どこで動かすか:
  - 今の `export_tables_daily.sh` は、ホストの cron（07:00 JST）で動く。PC が止まっていると走らない（11/12 の朝がそうだった）。
  - GCP の `export-tables-daily`（Cloud Run Jobs）に載せれば、転送料は 0 円。ただし、いまは費用の歯止めで GCP Jobs を止めている。
- 単価は CLAUDE.md の 2026-10 の実績を使った（転送 約 18 円/GiB、Class A 約 0.8 円/千回、Class B 約 0.06 円/千回）。
- 実施した後は、課金エクスポート（BigQuery `horse-racing-466415.billing_export`）で、1〜2 日後の実績を確かめる。

### 計算が通るかの試算

- ただし、試算は年をまとめて計算する経路。週次の `compute_for_date` は、日ごとに過去の履歴（`df_hist`）を足して計算するので、値は少しずれうる。

### 前提（これが崩れると埋まらない）

- 11/13 の 18:00 JST に PC が動いていること。週次は追いつき実行の対象外（金曜の定時）。
