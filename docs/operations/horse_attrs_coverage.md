# 推論が使う馬の産地・誕生日の埋まり具合（horse_attrs_coverage）

推論（v4・v5・v6e。`V4Features`）は、馬の産地を「馬自身の群」の列（`attr_birthplace`・`attr_bp_*`）に使う。
産地が欠けると、新しい馬の多いレースで予測が弱くなる（2026 年は最大 48% 欠け、市場に対する上積みが消えていた。[v6e_2026_gap_20261114.md](retrain_trials/v6e_2026_gap_20261114.md)）。

## どこから埋まるか（2026-11-14 の修正の後）

推論が使う産地・誕生日は、次の 3 つを合わせたもの（`serving_v4.fill_attrs_from_profile`）。

| 元 | 中身 | 更新 |
|---|---|---|
| `factory/self/horse_attrs.parquet` | 学習で使った産地・誕生日の表（2020〜2025 年の出走馬） | 学習のとき（`factory_self_eval attrs`） |
| `factory/conn/horse_profile.parquet` | 馬主・生産者・産地・誕生日（2020〜2026 年 9 月ごろまでの出走馬） | 一度きり（`factory_conn_fetch`、2026-10-17） |
| `state/profile_dyn.parquet` | 日次の補い（2026 年に走った馬のうち、上の表に無い馬） | 毎晩 23:10 JST（cron `serving-state-profile`、`update_serving_state profile`） |

修正の前は、推論は 1 つめの表だけを使っていた。日次の補いは「2 つめの表に無い馬」だけを取りに行くので、2 つめの表にだけ居る馬の産地が欠けたままだった。

- 毎晩の補い（`update_serving_state profile`）は、馬の成績の文書（`horse_result`）を読む。そこに産地が無かった馬は、プロフィールの文書（`horse_profile`）を 1 頭 1 回だけ読み直す（`retry_birthplace`、2026-11-14 から）。読み直した馬には `bp_retry` の印を付け、二度と読まない。
- 推論の起動ごとの補い（`profile_for`）は、読み出しを増やしていない（Cloud Run のジョブは起動のたびに新しいコンテナなので、ここで足すと繰り返し読むことになる）。
- 馬主・生産者の表から埋めるとき、学習の期間（2025 年まで）に走った馬は埋めない。産地ごとの累積が学習のときとずれないようにするため。日次の補いから足す分は、今までどおり除外しない。
- 毎晩の補いは、`profile_dyn.parquet` の誕生日を保存の形（「2024年2月2日」の文字列）にそろえて書く。
- 新しい親モデル（2016 年起点、s18）では、`rebuild_groups_2016.redirect_serving` が 1・2 つめを `retrain_out/base_2016/profile/` の表に向ける。同じ合わせ方で埋まる（2 つめの表は 2026 年の馬 10,941 頭のうち 10,382 頭の産地を持つ）。

## 見張り

`python -m src.scripts.data.horse_attrs_coverage`（週次の `frozen_tracking_weekly.sh` の最後で回す。手元の表だけを読み、GCS・GCP は読まない。費用 0 円）。

- 直近 28 日に走った馬と、今日以降の出走予定の馬のうち、推論で産地が無い馬の割合を出す。
  - 出走予定は、既に走ったことのある馬と、初出走の馬に分ける。馬番 0 の行（登録だけ・除外）は数えない。
- 走った馬か、出走予定の既走馬が 5% を超えたら WARNING を出し、`is_warn` を立てる（週次の処理は止めない）。
  - 初出走の馬は、走る前には毎晩の補いが届かない（推論のときに読む）ので、数を出すだけで判定に使わない。
  - 走った馬が 0 頭（結果の表が読めない・向き先が違う）のときも WARNING。
- 記録: `data/local/meta/horse_attrs_coverage/latest.json`（上書き）と `history.jsonl`（追記）。欠けている馬の ID を 20 頭まで出す。

欠けが増えたときに見るもの:
1. 日次の補い（cron `serving-state-profile`）が動いているか。`state/profile_dyn.parquet` の更新時刻を見る。
2. 新しい馬の文書（`horse_result`・`horse_profile`）が保存されているか。取得の側の問題なら、取得の担当に回す。
3. 2 つめの表を作り直すか（`factory_conn_fetch`）。GCS を大量に読むので、作り直す前に見積もる。
