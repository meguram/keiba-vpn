# 凍結した馬券候補の前向き追跡（tp-59・tp-62）

事後に見つけた馬券の候補を採用せず凍結し、**2026-10-22 以降の新しいレース**で何が起きるかを溜めて確かめる仕組み。
確証には tp-59 で約 3,300 件・約 2 年かかる見込みなので、毎週自動で積む。判定は報告専用で、モデルや閾値の選択・学習には使わない（市場オッズは買いの判定にだけ使う）。

## 追跡する規則

| 規則 | 内容 | 凍結ファイル |
|---|---|---|
| tp59 | 単勝 100 円。V4 の勝率 × 単勝オッズ ≥ 1.5、かつ騎手・調教師の両方が『2025 年までの勝ち数が市場の見込みを上回る』ID | `config/tp59_frozen_rule.json` |
| tp62 | 馬連。V4 の確率 + 単勝の Benter 混合 + 割引 Harville を、凍結した折れ線で較正 → 較正後 EV ≥ 1.0 の買い目を EV 降順に最大 5 点。点数 k は『最小オッズ ≥ 5×k、的中確率の和 ≥ 20%』を満たすうち 1 点あたり EV が最大のもの。等額（1 点 100 円） | `config/tp62_frozen_rule.json` |
| 混合係数 | 単勝の Benter 混合の a（モデル）・b（市場）。2022〜2025 年で当てはめた値を 2026 年以降も使う | `config/frozen_tracking.json`（`blend`） |

組み合わせの軸は 3 つ。

- **モデル**: `v4`（`predictions_v3`。凍結した規則の入力。評価の主）／`v5`（`predictions_v5`。参考。較正・条件表は V4 用なので凍結の評価には含めない）。
- **オッズ時点**: `final`（確定オッズ。`race_*_flat`）／`pre`（発走前の最後のスナップショット。`race_odds` は t02→t05→t10→t15→t60、`race_pair_odds` は t15→t60 のうち発走時刻より前のもの。ホストで保存の中身を読める時だけ）。どのスナップショットを使ったかは台帳の `odds_phase_win` / `odds_phase_pair` に残る。
- **規則**: tp59 / tp62。

## 流れ（毎週月曜 10:30 JST）

1. `export_tables_daily`（毎日 07:00 JST）で `race_*_flat` が更新される。
2. `scripts/cron/frozen_tracking_weekly.sh` が `python -m src.scripts.data.frozen_tracking track` を実行（nice 19、`load>14` の間は最大 30 分待つ、二重起動は `flock` で防止）。
3. 直近 60 日のうち、予測があって結果（払戻）が確定したレースを判定して台帳に追記。**同じキー（規則|モデル|オッズ時点|レース）は書かない＝何度回しても同じ**。
4. `report` で `latest.json` / `latest.html` と、時刻つきの `reports/<日時>/` を作る。

## 出力（`data/local/meta/frozen_tracking/`）

| ファイル | 内容 |
|---|---|
| `ledger.jsonl` | 台帳。1 行 = 規則 × モデル × オッズ時点 × レース。買い目・オッズ・払戻・的中。**追記のみ。書き換えない** |
| `hashes.jsonl` | 凍結ファイルのハッシュ。初回の記録と今が違えば追記を拒否 |
| `runs.jsonl` | 実行ごとの追加件数とスキップ理由（結果がまだ・pre オッズなし・単勝オッズが揃わない など） |
| `latest.json` / `latest.html` | スコアカード（最新。上書き） |
| `reports/<日時>/scorecard.{json,html}` | 同じ内容の日時つきコピー（上書きしない） |

### スコアカードの見方

規則 × モデル × オッズ時点ごとに次を出す。

- 確定したレース数、買ったレース数、賭け数、購入額、払戻額、的中したレース数。
- **回収率（%）と 95% 区間**（買ったレース単位のブートストラップ）。区間の**下限が 100% を超える**まで確証とは言えない。
- **月ごとの回収率**と、100% 超の月の数（月次過半の基準）。
- **確証までの残り（買ったレース数）の目安**: `(1.645·SD/(μ−1))²` から今の件数を引いた値。SD は『買ったレース 1 つあたりの払戻倍率』の標準偏差で、2026 年 1〜10 月のバックテストで見積もった値（`config/frozen_tracking.json` の `reference_sd`）と観測値の大きい方。真の回収率が今の観測値に等しいという仮定の目安。
- **凍結前の期待**（バックテストの回収率、tp62 は予測と実績のレース的中率）との比較。

主に見るのは `v4` × `final`。`pre` は購入時点に近い条件での再検証（直前オッズが貯まってから意味が出る）。`v5` は参考。

## 止め方・やり直し

- **一時停止**: crontab の該当行（`# KEIBA-FROZEN-TRACKING`）を外す。または実行時に `KEIBA_FROZEN_TRACKING=0`。
- **登録**: ホストで root が `bash scripts/cron/install_frozen_tracking_cron.sh /home/jovyan/work/keiba-vpn`（月曜 01:30 UTC = 10:30 JST。登録前の crontab は `data/local/meta/cron_backups/` に退避される）。
- **凍結ファイルを書き換えた**場合は、追記が拒否される（ハッシュの不一致）。意図した変更なら、`FROZEN_TRACKING_DIR` を新しいディレクトリにして**別の履歴として**再開する（古い履歴は消さない・混ぜない）。
- **手動実行**: `python -m src.scripts.data.frozen_tracking track --from 20261022`、スコアカードだけ作り直すなら `report`。

## コードの正しさの確認（バックテスト）

`python -m src.scripts.data.frozen_tracking backtest --from 20260104 --to 20261018 --pred-dir data/local/modeling/betting/tp36/pred2026 --out <dir>` は、2026-10-22 より前の期間に**同じ判定コード**を流す。tp-62 の既存チケット表（`tickets_2026.parquet`）・tp-59 の報告値と一致するかを確認するためのもので、**結果は凍結の評価には使わない**（結果は台帳 `<dir>/ledger.jsonl` に出力され、本番の台帳には入らない）。結果と照合の中身は章 `jockey_trainer_roi` / `monthly_roi_search` と決定ログの該当行を参照。

## 注意

- 確定オッズでの評価は購入時点のオッズとは違う。`pre` が貯まるにつれ、直前オッズでの回収率が確定オッズより低くなる（買えたときの価格はもっと悪い）可能性がある。
- 台帳は `data/local`（ホストの取り込み）にだけ置く。公開リポジトリには入れない。
- 2026 年以降の追跡データは**学習・選択に使わない**。
