# 無料ユーザーに出す印（public_mark_type）の決め方 — 事前登録の plan（2026-11-25 改め、bet-optimizer）

## 結論
- 匿名・無料には、予測の値を出さず、印（◎○▲△★消・なし）だけを出す。欄は予測の行の `public_mark_type`（scope-fix の受け口。語は honmei/pair/show_val/anchor/star/kesi/none）。
- 決め方は `config/public_marks.json`、止める規則は `config/public_marks_stop.json` で事前登録した（この 2 つを commit した日が固めた日）。
- 印は発走 50 分前（T-50）の 1 回で決めて固める。入力は T-60 のオッズと、T-50 までに書かれた予測だけ。
- 合否は前向きの影の記録だけで決める（門 B・門 C）。30% の側と 2025・26 年は使わない。
- 本番の印も会員の印（mark_type）も、今は変えない。公開は門 B を通り、R0〜R3・統括役とユーザーの承認の後。
- 会議の記録: `docs/operations/roi_plus_council/decisions.md` の「印（public_mark_type）の議題の R3」（06ffe27d）と「印の議題: 決定 3 の改め」（577bf7c7）。

## 印の意味（画面の文言。「買う候補」「市場より高い」は使わない）
| 印 | 文言 | 決め方（主の候補） |
|---|---|---|
| ◎ | AI の評価が最も高い | p_win が最大 |
| ○ | 2 番目 | p_win が 2 番目 |
| ▲ | AI の複勝の評価が高い | ◎○ を除き、p_win から Harville で換算した 3 着内の確率が最大（人気馬で過大に出る偏りがある。前向きの記録だけで判定） |
| △ | AI の評価は高いが、人気も高い | p_win の順位 5 位以内・T-60 の人気 3 位以内で、まだ印の無い馬の p_win が最大（0〜1 頭） |
| ★ | AI の評価が人気より高い穴（発走前 10 倍以上） | T-60 の単勝 10 倍以上で r = log(p_win / q) > 0 の r が最大（0〜1 頭） |
| 消 | 今の消の型 | `config/kesi_mark.json` のまま。人気は T-60 の人気 |
- 候補（影の記録だけに残す）は、印 1 つに 2 まで・全体で 8（`config/public_marks.json` の candidates）。主は ◎ の主の候補。割引きは Bonferroni（片側 0.005）。

## 印なし
- 理由の文は 3 種: 出走 8 頭未満／発走前のオッズがそろわない／AI の評価が割れている（p_win の最大 < 0.25）。
- 区切り 0.25 は、2026 年の本番の予測の p の分布だけで決めた（着順・払戻・オッズは見ない）。頭数と合わせて約 29%。目標は 20〜40%。
- 時刻の都合の印なしは、別に数える。オッズの取得が T-50 より後（45 分前の取得など）は「印なし（オッズ待ち）」、予測の最後の書き込みが T-50 より後は「印なし（予測待ち）」。

## 決める時刻と入力
- 発走時刻は出馬表の start_time。T-50 = 発走時刻 − 50 分。
- p のモデルは bundle_v6_2025（v6e、bundle.json の sha256 の先頭 a668bf5eb922a582、2016〜2025 年で学習）。入力の 1,193 列にオッズ・人気の列は無い。
- 影の記録の行には、オッズの取得時刻・予測の最後の書き込み時刻・発走時刻・決めた時刻・その開催が p の学習に入っていたか（11/28 以降は入っていない）を残す。
- 固めた後は印を変えない。取消の馬は「取消」と出し、ほかの馬の印も付け直さない。
- 画面は、T-50 より前は「印は発走 50 分前に出ます」と出す（ポーリングは足さない）。

## 会議の文からの替え（作りの都合。意味は変えない）
- T-60 のオッズの出どころは、研究用の表 pre_odds.parquet ではなく、開催日に書かれる手元の写し odds_t60（取得時刻と書き込み時刻を持つ）。
- 穴の印の記号は ★（語は star。scope-fix の対応表のまま）。会議の文の ☆ と同じ印。
- 取消（T-60 の単勝 999.9 以上）の馬は印の計算から外して「取消」と記録し、ほかの馬の印は付け直さない。
- 出馬表・予測・特徴量の対応づけができないレースは「印なし（data）」にし、印なしの割合に入れる。

## 影の記録
- 固めた日の次の開催日から、開催日の 17:00 より後に、手元の `odds_t60`・`predictions_v3`・`features`（馬番の対応）と出馬表から計算する（`python -m src.research.public_marks.marks shadow --day <日>`）。予測の行に欄は足さない。費用 0 円。
- 記録は `docs/operations/retrain_trials/public_marks_shadow/<日>.jsonl`。既にある日は書き直さない。固めた日以前・その日の 17:00 より前・出馬表か odds_t60 が無いときは書かない。レースは出馬表から数える。
- 行には入力の指紋（odds・予測・特徴量のファイルの sha256 の先頭）を残し、門 A の「hash から同じ印が 100% 再現」を後から確かめられるようにする。
- 予測の最後の書き込み時刻はファイルの更新時刻で見る。書き直しの履歴は残らないので、T-50 にはあったが後で書き直されたレースも「予測待ち」になる（偏りとして門 A で件数を出す）。

## 70% の側（11/30〜12/2、1 回だけ・通算 8 回目）
- 使い道は止める検査と記述だけで、合格の根拠にしない。定義を選び直さない。
- p は v6e の学習に入っているので使わず、開催単位の out-of-fold（cycles16_fix3 の年を外した OOF）を代わりに使い、その違いを記録する。
- 判定の q は 3 通り（T-60 の再現 s=1・s* 0.86・SmartRC の想定人気）。悪い側で判定する。R・excess_mr は確定の q で測る。
- 出すもの: 着順の分布・市場比・excess_mr（同じ確定オッズの帯 × クラス群で割る）・基準線 3 本（今の印・確率の順・人気の順）との差・q の 3 通りでの ◎ の入れ替わり・印なしの割合。区間は開催日で束ねる。

## 門の線（会議の決定のまま）
- 門 A（12/3）:
  - 印の付いた行で、オッズの取得・書き込みが T-50 より後のものは 0 件。予測の最後の書き込みが T-50 より後のものは 0 件（その行は時刻の都合の印なしになる）。確定オッズを使った行は 0 件。固めた後に印が変わった行は 0 件。
  - hash から同じ印が 100% 再現できる。研究と本番の推論の経路で 99% 以上一致する。
  - 印なしの割合が 20〜40%（時刻の都合の分は別に出す）。
  - ◎ の入れ替わりが 30% を超えたら「再現が作った印」と記録し、門 C は本物の T-60 だけで判定する。
  - 70% の側で印を外す線: excess_mr の点推定 < 0.90、または ◎ の R が人気の順の ◎ より 0.05 以上低い。消は、複勝率が同じ人気の基準線より高い。
- 門 B（公開してよいか）: 影の記録 300 レースまで止める線に当たらない。止める線は 200・300・400・500 レースの時点で ◎ の excess_mr の点推定 < 0.90、または消の複勝率の Clopper-Pearson の下限 > 同じ人気の基準線（`config/public_marks_stop.json`、`enabled` 1 つで切れる）。
  - 模擬（着順は読まない）: 真の比 1.1 で誤って止める確率 3.2%（決定の線 15% 以下）、比 1.0 で 22%、比 0.8 で 98%（◎ の線だけ。◎ のある 37 レースの q で）。50 レースごと・100 レースから見る組は 10〜11% で、早い時点ほど誤って止めやすいので採らなかった。
- 門 C（「人気より勝つ」と言えるか）: 満期は影の記録 3,000 レースか、◎ の見込みの勝ち数 E ≥ 400 の早い方。◎ の excess_mr（確定の q）が、95% の下限 > 1.00・点推定 ≥ 1.05・片側 p ≤ 0.005・前半と後半の両方で > 1。「買う候補」と書いてよいのは、帯の比が約 1.27 を超えたときだけ。
