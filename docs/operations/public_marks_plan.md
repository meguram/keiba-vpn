# 無料ユーザーに出す印（public_mark_type）の選び方の plan（2026-11-25、bet-optimizer）

## 結論
- 匿名・無料には、予測の値を出さず、印（◎○▲△☆消・なし）だけを出す。欄は予測の行の `public_mark_type`（scope-fix が画面を作る。語は honmei/pair/show_val/anchor/star/kesi/none）。
- 印は「買い方の参考」として意味を決め、意味ごとに発走前に分かる値だけで選ぶ。「予測の確率が高い順に ◎○▲」にはしない。
- 選び方は rules-council の会議（protocol.md）にかける。主は bet-optimizer。
- 本番の印は、設計と検証の後、統括役とユーザーの承認を経てから替える。今の会員の印（mark_type）は変えない。

## 今の印（変えない側）
- `src/api/local_predictions.py:114` の `score_entries` が、確率・期待値（実オッズ）・合成スコアを出し、`src/utils/race_probabilities.py:470` の `assign_mece_marks`（v1/v2、`config/mark_rule.json`）で ◎○▲★△ を付ける。消は `assign_kesi_mark`（`config/kesi_mark.json`）。
- 推奨馬券があるレースでは、印を買い目から付け直す（`src/pipeline/inference/bet_marks.py`、`marks_basis: "bets"`）。
- 実オッズは「保存済みの最新」で、発走後は確定オッズになる。public の印は、これとは別に発走前の値だけで決める。

## 印の意味（案。会議で決める）
| 印 | 意味 | 使う値（発走前だけ） |
|---|---|---|
| ◎ | 単勝を買う候補の第 1。勝つ見込みが市場より高い | 自前の勝率 p と発走前の単勝の市場の勝率 q の比（r = log(p/q)）、p の下限 |
| ○ | 単勝・連の相手の第 2 | 同上の 2 番目、または連対率の比 |
| ▲ | 複勝を買う候補 | 自前の複勝率と、発走前の複勝オッズの下限から作る市場の複勝率の比 |
| △ | 押さえ（勝つ見込みは高いが、市場がもう買っている） | p は上位だが r が小さい |
| ☆ | 穴（オッズは高いが、市場が見落とす分がある） | 発走前の単勝 10 倍以上で r が大きい |
| 消 | 買われ過ぎ（人気ほど来ない型） | 人気上位で r が大きく負。前走の好走で過大に買われる型（RC-2 の前走の結果への反応しすぎ）など |
| なし | 印の根拠が弱いレースは印を減らす（全頭に印を付けない） | 見送りの規則（頭数・クラス・r の最大が小さい） |

- RC-2 の「前走で負けた馬は過小」の材料は、使うなら事前登録した上で ☆・▲ の加点にだけ使う。

## 検証の決まり
- 判定に使うのは発走前の値だけ。確定オッズは使わない。2019〜24 に本物の発走前のオッズは無いので、T-60 の再現（lessons の s* で割り引く）と SmartRC の想定人気の 2 通りで流し、楽観の側を記録する。
- 開催の 70/30（`src/research/rules_council/engine.py:118` の SPLIT70、seed 20261124）で、探すのは 70% の側だけ。30% の側は 1 回だけ当てる。2025・26 年は最後に 1 回だけ（台帳に申告）。
- 印ごとに出す: 着順の分布（1-2-3-着外）・勝率・複勝率・単勝と複勝の回収率（区間は開催日で束ねたブートストラップ）・市場比 R（勝ち数 ÷ 発走前の市場の勝率の和）。
- 比べる相手（基準線）: 今の印（mark_type）、予測の確率の順の印、発走前の人気の順の印。
- 合格の線は、会議で事前に固定する。例: ◎ の R の下限 > 1（同じ人気の基準線より上）、消の複勝率が同じ人気の基準線より下（区間で）。
- 回収率の「100% 超」は印の合否にしない（印は買い方の参考で、全部を買う方策ではない）。会員の画面と同じく、回収率は区間と注記つきで出す。

## 作り（承認の後）
- `public_marks(entries, pre_odds) -> {馬番: 印}` を 1 つの関数にし、予測の行の `public_mark_type` に入れる。決め方の設定は `config/public_marks.json`（凍結の hash を持つ）。
- 発走前のオッズが無いレースは、`public_mark_type` を付けない（scope-fix の作りで今の mark_type が出る）。この扱いでよいかは scope-fix・統括役と決める（今の mark_type は確定オッズに頼る面があるため、代わりに「なし」を出す案もある）。
- 費用: 推論の中の計算だけで、GCS の読みは増えない。
