# 無料の AI 印（public_mark_type）の決め方 — 事前登録 v2 の plan（2026-11-25、bet-optimizer）

## 結論
- 印は 1 種類で、全員に同じ「めぐAI印」（サンプル買い目のルール＋complete_marks で全レースに過不足なく）を出す（ユーザーの判断、2026-11-25）。この v2 の印（`public_mark_type`）は画面にも応答にも出さず、影の記録だけを続ける。今のめぐAI印より良いと分かったら、全員の印をこれに替える候補として会議にかける（別の名前は作らない）。
- v2 は、ユーザーの方針「印は過不足なくすべてのレースに付ける。どう付けるかは買い目の判断のルールで決める」に合わせた版。予測があり予測待ちでないレースには、必ず ◎○▲★ を頭数まで（重複なし）付け、△・消は 0 頭以上。
- 決め方は `config/public_marks_v2.json`、止める規則は `config/public_marks_stop_v2.json`（この 2 つを最初に commit した日が固めた日）。
- v1（`config/public_marks.json` 89c2decb・`config/public_marks_stop.json` 7639a938）は消さずに残し、「使わずに置き換えた（影の記録 0 行・70% の側は 0 回）」とした。
- 印は発走 50 分前（T-50）の 1 回で決めて固める。入力は T-60 のオッズと、T-50 までに書かれた予測だけ。
- 合否は前向きの影の記録だけで決める（門 B・門 C）。門 B は「全員の印を替える候補として会議にかけてよいか」と読み、比べる相手は今のめぐAI印。30% の側と 2025・26 年は使わない。本番の印も会員の印も、bet-optimizer は触らない。
- 会議の記録: decisions.md の「印（public_mark_type）の議題の R3」（06ffe27d）・「決定 3 の改め」（577bf7c7）・「事前登録の確認」・「v2 への固め直し」（fdceda27）。

## 付ける順と印の決め方
付ける順は ◎ → ○ → ▲ → ★ → △ → 消。同じ馬に 2 つの印は付けない。頭数が足りないときは ◎ > ○ > ▲ > ★ の順に頭数まで。

| 印 | 画面の文言 | 決め方 |
|---|---|---|
| ◎ | AI の評価が最も高い | p_win が最大 |
| ○ | 2 番目 | p_win が 2 番目 |
| ▲ | AI の複勝の評価が高い | ◎○ を除き、p_win から Harville で換算した 3 着内の確率が最大（人気馬で過大に出る偏りがある。前向きの記録だけで判定） |
| ★ | ◎○▲ の次の注目馬。オッズがあれば、10 倍以上で AI の評価が人気より高い馬を優先 | mode ana: T-60 で 10 倍以上かつ r = log(p_win / q) > 0 の中で r が最大。ana がいなければ mode fallback_r: 印の無い馬の r が最大。T-50 までにオッズが無ければ mode no_odds_p: 印の無い馬の p_win が最大 |
| △ | AI の評価は高いが、人気も高い | ◎○▲★ の後、p_win の順位 5 位以内・T-60 の人気 3 位以内で p_win が最大（0〜1 頭）。オッズなしでは付けない |
| 消 | 今の消の型 | ◎○▲★△ の残りから。★ の馬は消の条件に当たっても消にしない。人気は T-60 の人気。線は固めた日に `config/kesi_mark.json`（commit aadc3665、version 2）から写した値。8 頭未満・人気がそろわない・オッズなしでは付けない |
- 「穴」「人気より高い」と言うこと、★ が人気より勝つかの判定（門 C の型）は、mode=ana の行だけで行う。
- どの集計も mode（ana・fallback_r・no_odds_p）ごとに出す。
- 「割れている」（取消を除いて合計 1 に直した p_win の最大が 0.25 未満、params.split_pmax）は、印を外す規則ではなくラベルとして残す（集計の分け目）。
- 候補（影の記録だけ）は印 1 つに 2 まで・全体で 8。主は ◎ の主の候補。候補の集計と検定は odds_used=true の行だけで行う（オッズなしの行では候補は空）。

## 決める時刻と入力
- 発走時刻は出馬表の start_time。T-50 = 発走時刻 − 50 分。
- p のモデルは bundle_v6_2025（v6e、bundle.json の sha256 の先頭 a668bf5eb922a582、2016〜2025 年で学習）。入力の 1,193 列にオッズ・人気の列は無い（p_uses_odds = false）。
- T-60 のオッズは手元の写し odds_t60（取得時刻 snapshot_at と書き込み時刻 written_at）。門 C の「本物の T-60」も同じ出どころ。取得か書き込みが T-50 より後・書き込み時刻が無い・T-75 より前・phase が t60 でない・一部の馬のオッズが欠けるなら、そのレースはオッズなし（no_odds_p）で付ける。T-50 にオッズが無いレースでは取消を判定せず、一部が欠けるだけのレースでは T-50 に分かっていた取消（999.9）を使う。
- T-50 に使えるオッズがあるのに予測と馬がそろわない（予測にしかいない馬・T-60 にいる取消でない馬が予測にいない）レースは data として記録だけに残す。
- 予測の最後の書き込み時刻はファイルの更新時刻。ホストの元のファイルの更新時刻で、写しや同期で付け直されたものではない（11/21〜23 の 72 レースで、ホストの予測の記録 events の時刻より 53〜76 秒後、同じ秒の書き込みなし。2026-11-25 に確かめた）。
- 予測待ちは、画面の印なしではなく、測る側の穴（本番では T-50 の時点の予測で印が付くが、影の記録には T-50 の時点の予測が残らない）。開催日ごとの割合を出し、10% を超えた日が 3 日続いたら、案 B（予測を T-50 の時点で写して残す）を統括役の承認の上で議題に戻す。
- 固めた後は印を変えない。取消（T-60 の単勝 999.9 以上）の馬は「取消」と出し、ほかの馬の印も付け直さない。
- 画面は、T-50 より前は「印は発走 50 分前に出ます」と出す（ポーリングは足さない）。

## 影の記録
- 固めた日の次の開催日から、開催日の 17:00 より後に、手元の `odds_t60`・`predictions_v3`・`features`（馬番の対応）と出馬表から計算する（`python -m src.research.public_marks.marks shadow --day <日>`）。予測の行に欄は足さない。費用 0 円。
- 記録は `docs/operations/retrain_trials/public_marks_shadow/<日>.jsonl`。レースは出馬表から数える。行には、設定と止める規則の hash・道具の sha・入力の指紋（odds・予測・特徴量の sha256 の先頭）・時刻（すべて JST）・mode・割れているか・status（marked・wait_pred・no_pred・data）を残す。
- 固めた日以前・その日の 17:00 より前・出馬表・予測か odds_t60 の日のフォルダが無い・既に記録がある、のどれかなら書かない。

## 開催日ごとに出す数（1 号の v2 の確認、2026-11-25）
- 取消: オッズの無いレース（取消を判定しない）で、後から取消と分かった馬に印が付いていた件数。画面では「取消」と出し、ほかの馬の印は付け直さない。全レースの 1% を超えた日は 1 号に返す。取得時刻の付いた出馬表の取消の情報は手元に無いので、v2.1 は出さず今のままにする。
- no_odds_p: その日の no_odds_p の割合と、オッズの取得が発走の何分前だったかの分布。古いオッズで穴は埋めない。20% を超えた日が 3 日続いたら、取得の時刻を直す案を統括役の承認の上で上げる。
- 予測待ち: その日の割合（10% を超えた日が 3 日続いたら案 B を議題に戻す）。
- 止める規則の模擬の値（59 レースの q。真の比 1.1 で 5.3%、比 1.0 で 27% が止まる）は仮の値。70% の側の q と帯の比の振れを入れた作り直しと、消の線の模擬（消の頭数で数える）を 12/3 の門 A までに出し、15% を超えたら 1 号に返す。

## 70% の側（11/30〜12/2、1 回だけ・通算 8 回目）
- v2 の定義で 1 回だけ見る。使い道は止める検査と記述だけで、合格の根拠にしない。定義を選び直さない。
- p は開催単位の out-of-fold か as-of の p だけ（v6e の p は 2016〜24 を学習に含むので使わない）。そういう p が無ければ検査は行わず、見た回数 8 は使わずに残す。どちらにしたかを門 A の結果に書く。
- 判定の q は 3 通り（T-60 の再現 s=1・s* 0.86・SmartRC の想定人気）。悪い側で判定する。R・excess_mr は確定の q で測る。
- 出すもの: mode ごとの着順の分布・市場比・excess_mr（同じ確定オッズの帯 × クラス群の ◎ 以外の馬で割る）・基準線 3 本（今の印・確率の順・人気の順）との差・q の 3 通りでの ◎ の入れ替わり・割れているレースの割合。区間は開催日で束ねる。

## 門の線
- 門 A（12/3）:
  - 予測があり予測待ちでないレースで、◎○▲★ が頭数まで重複なしで付いた率が 100%。この率は odds_used の値に関係なく全行で数える。
  - 全レースを分母に、予測のあるレース・予測なし・data（理由つき）・予測待ちの数を出す。予測なしと data を合わせて 2% 以下（超えたら不合格）。
  - mode ごとの件数と割合を出す。
  - odds_used=true の行で、オッズの取得・書き込みが T-50 より後のものは 0 件。印の付いた行で、予測の最後の書き込みが T-50 より後のものは 0 件。確定オッズの使用 0 件。T-50 の後に印が変わった行 0 件。
  - hash から同じ印が 100% 再現・研究と本番の推論の経路で 99% 以上一致・◎ の入れ替わりが 30% を超えたら「再現が作った印」と記録・70% の側で印を外す線（excess_mr の点推定 < 0.90、または ◎ の R が人気の順の ◎ より 0.05 以上低い、消の複勝率が同じ人気の基準線より高い）。
- 門 B（公開してよいか）: 影の記録 300 レースまで止める線に当たらない。止める線は 200・300・400・500 レースの時点で ◎ の excess_mr の点推定 < 0.90、または消の複勝率の Clopper-Pearson の下限 > 同じ人気の基準線（`config/public_marks_stop_v2.json`、`enabled` 1 つで切れる）。数える単位は全レース（消の点検は消の頭数）。
  - 模擬（着順は読まない）: v2 で T-50 に手元にあった T-60 のオッズを使って印を付けた 59 レースの ◎ の q で、真の比 1.1 で誤って止める確率 5.3%（決定の線 15% 以下）、比 1.0 で 27%、比 0.8 で 96%（◎ の線だけ）。50 レースごと・100 レースから見る組は 14〜16% で、早い時点ほど誤って止めやすいので採らなかった。70% の側の q と帯の比の振れを入れた模擬は 12/3 までの宿題（15% を超えたら 1 号に返す）。
  - 通っても、公開は R0〜R3・統括役とユーザーの承認の後。
- 門 C（「人気より勝つ」と言えるか）: 満期は影の記録 3,000 レースか、◎ の見込みの勝ち数 E ≥ 400 の早い方。◎ の excess_mr（確定の q）が、95% の下限 > 1.00・点推定 ≥ 1.05・片側 p ≤ 0.005・前半と後半の両方で > 1。★ は mode=ana の行だけ。「買う候補」と書いてよいのは、帯の比が約 1.27 を超えたときだけ。

## 消したこと・置き換えたこと
- 30% の側に 1 回当てること、2025・26 年の 1 回の確かめ、確定オッズでの判定（v1 の前に消した）。
- 「買う候補」「市場より高い」という意味づけ。
- T-60 の 1 回で決めること（予測が T-60 より後に書き直される作りのため、T-50 に改めた）。
- v2 で置き換えた: 決定 3 の「発走前のオッズが無ければ印なし」、T-50 の改めの条件 3（T-50 より後のオッズは「印なし（オッズ待ち）」）、門 A の「印なしの割合 20〜40%」、印なしの規則（頭数 8 未満・割れている・オッズがそろわない）。
- 着順・払戻: 11/21〜23 の 72 レースの着順・払戻は、v1・v2 のどの選択にも使っていない（試しは印の付き方と件数だけ）。
