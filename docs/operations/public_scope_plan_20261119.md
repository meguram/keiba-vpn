# 公開の範囲を「確定の前後」で分ける計画（2026-11-19、weekend-launch）

## 結論

- 今は、確定の前後で出し分けるコードが無い。区分（tier）だけで分けている。
- ルールとの一番大きな違い: 匿名・無料会員にも、確定前から v6e の勝率・複勝率が出ている。確定後でも、匿名・無料会員には連対率・印・推奨が出ない。
- **今週末（金の昇格）に入れるのは P0 だけ**: 第 2 段の試行の ◎ が、有料会員の予測の印に漏れる経路を塞ぐ（済み・テストつき）。v6c は全員に出さない（今の目印のまま）。これで「試行の分は確定前は開発者だけ」は守られる。
- 確定の前後で分ける本体（P1）は、テストとキャッシュの確かめに時間が要るので来週（11/24〜26 に develop・stg、次の昇格）。

## P0（今週末・金の昇格に入れる）

- `delegates.bet_horse_marks`（予測の応答の印。全区分で共有する事前生成・キャッシュに載る）は、第 2 段を通らない（`optimize_betting(stage2=False)`）。
  - それまでは、`view="full"` で呼ぶため、開発者だけの判定（`view!="full"` のときだけ効く）を素通りしていた。11/21 以降の未勝利・新馬のレースで、有料会員の予測の画面に第 2 段の ◎ が出るおそれがあった。
  - テスト: `tests/api/test_stage2_live.py::test_prediction_marks_never_use_stage2`。
- 予測の応答の進み具合（`pipeline_status._bets_state`）も、全区分で共有するので第 2 段を通らない（今は漏れていないが、作りの危うさを先に塞ぐ）。
- **試行の目印を止める側に倒した**（レビューの指摘 1）。`bets_stage2/_dev_only.json`・`predictions_v6c/_disabled.json` が無ければ、第 2 段は開発者だけ・v6c は誰にも出さない。会員・全員に出すときだけ `{"disabled": false}` を置く。置き忘れ・push の遅れで漏れない。
  - それまでは「ファイルが無ければ止めない」作りで、金の昇格の前に目印を置く段取りに頼っていた（置く前に昇格すると、11/21 以降の未勝利・新馬で第 2 段が有料会員に、v6c が匿名を含む全員に出るおそれがあった）。
- v6c の確率は全員に出さない。開発者だけに出す切り替えは P1。
- 今週末に残る表示の食い違い（漏れの向きではない）:
  - 開発者の画面で、予測の印（target の ◎）と推奨馬券のタブ（第 2 段の ◎）が別の馬になりうる。
  - レース一覧の推奨度（race-values）は、開発者でも第 2 段ではなく target の段。

## P1（来週）

1. **確定の判定を 1 か所に**: `race_settled(race_id)` ＝ `race_result` に着順があり、かつ払戻（payoff）がある。速報（race_result_on_time）だけ・発走時刻を過ぎただけでは確定としない。
   - 既存の `src/utils/race_result_availability.race_result_status` と `prediction_results.load_race_result` の official を土台にする。
   - プロセス内で、確定したレースは長く、確定前は短く（60 秒）覚える。
2. **予測 API**（`/api/race/{id}/predictions`）: 取り出した後の出し分け（redactor）に確定の判定を足す。
   - 非会員×確定前: 予測値・印をすべて落とす（馬名などの出馬表の事実は残す。「結果の確定後に公開」の表示）。
   - 非会員×確定後: 予測値・印を出す。
3. **推奨 API**: 確定したレースだけ、非会員にも読み取り専用で返す（推奨度・買い目・結果）。確定前は今どおり 401。`tier.py` の会員だけのパスに、確定の判定の例外を足す。
4. **第 2 段**: 開発者だけの判定を「確定前だけ」にする。確定後は誰にでも、試行中の札つきで出す。
5. **v6c**: 予測の計算が全区分で共有なので、開発者だけに出すには、区分で計算を分けるか、開発者だけの別の口が要る。確定後は誰にでも出す。
6. **画面**: 非会員でも確定後は、予測・印・推奨のタブを開ける（今は 🔒）。確定前は今どおり。
7. **キャッシュ**（下）。

### レビュー（別エージェント、2026-11-19）の指摘で P1 に足すこと

- 予測成績の API は、速報（race_result_on_time）が入った時点で、匿名にも印と勝率を出している（`prediction_results.load_race_result` が速報でも結果ありと返す）。予測成績も同じ `race_settled` で判定する。払戻は `race_result_payoff` の区分にある場合も見る。
- **Cache-Control は、ミドルウェア（`http_cache_headers.cache_control_value`）だけで決める**。処理側で付けると、ミドルウェアが匿名の判定と Vary: Cookie を付けずに素通しするので、会員の応答に public が付いて匿名に渡るおそれがある。処理側は「確定前」の目印を内部のヘッダで渡すだけにする。テストを足す。
- 共有キャッシュの「確定」は、今は結果ではなく日付で決まる（開催から 3 日で 30 日置く）。P1 の配備の手順に、nginx（`purge_api_cache.sh`）と Cloudflare の全消去を入れる。今の匿名の応答（確定前でも v6e の勝率入り）が残っているため。
- 推奨 API の例外は、パスでは判定できない。`/betting/optimize` は POST で race_id が本文、race-values は開催日の単位で、確定前と確定後のレースが混ざる。処理の中でレースごとに絞る。匿名の view と、実オッズ由来の値の扱いも決める。
- 確定しないレース（取消・中止・審議の長引き・払戻の解析の失敗）: 「速報あり・払戻なしが N 時間続いたら知らせる」見張りと、開発者が手で確定扱いにする口を足す。地方・海外は扱う範囲の外と明記する。
- 確定前は、匿名に `prediction_source`・`model_description`・`prediction_note` も出さない（試行のモデルの名前が分かる）。伏せる処理は 2 つ（公開モードの `_redact_predictions_public_mode` と `redact_predictions`）あるので、両方に入れる。
- 取り残しの上限（約 10 分）は条件つき: nginx は上流のエラーのとき古い版を返す（`proxy_cache_use_stale`）。cache-warm の取り直しは Cloudflare に届かない。L6（PR #3）との取り込みの順を決める（`tests/api/test_shared_cache_tiers.py` は PR #3 の側にある）。
- 費用の見積もりの数え直し:
  - GCS の操作料（Class B）。確定前のレースの判定で、60 秒ごとに数回読むと、1 インスタンスで最悪 約 750 円/月になりうる。**発走前は GCS を読まずに「確定前」とし、読むのは発走後だけ**、年単位の一覧（Class A）は要求ごとに使わない。
  - 週の予想の画面で前日から出る分（24 時間・72 レース）、クエリ文字列の違い、Cloud Run の CPU 秒も、最悪の回数で数える。

### キャッシュの決まり

- **会員だけの値を、匿名の共有キャッシュに入れない**。
  - 匿名の応答（Cookie も Authorization も無い）だけが nginx・Cloudflare（L6 の後）に置かれる。その中身は、応答の時点の確定の判定で落とした後のもの。
  - 確定前に置かれるのは伏せた版だけで、漏れる向きにはならない。
- **確定した後に、伏せた版が残る時間**:
  - 今の匿名の s-maxage は、当日のレースで 6 時間（`config/http_cache.json` の settled）。
  - 結果の保存で cache-warm が取り直すが、それまでの 5〜30 分は伏せた版が残る。
  - 確定前のレースの予測・推奨だけ s-maxage を 300 秒に縮めて、取り残しの上限を 5 分にする。確定後は今の長さ。
- **L6（PR #3。Cloudflare に 5 分）**: 合わせて取り残しの上限は約 10 分。`tests/api/test_shared_cache_tiers.py`（共有できる応答に会員の項目が無い）は、「確定前の応答に会員の項目が無い」に直す。

### 決めてほしいこと（ユーザー）

- **実オッズ由来の値**: `config/public_fields.json` の `actual_odds_public: false`（netkeiba の規約）と、ルールの「確定後は誰でも」がぶつかる。
  - 対象: 実オッズの期待値・オッズ・人気、第 2 段の q・r・T-60 オッズ。
  - **推奨: 確定後も、実オッズ由来の値は非会員に出さない。** 出すのは、自前の計算（勝率などの確率・印・推奨の買い目と推奨度・的中と払戻の結果）。
- 確定後の推奨の公開に、成績（回収率など）を含めるか。今は予測成績の API で会員だけ。

### テスト（P1）

- 確定の判定: 結果あり・払戻ありは確定。速報だけ・払戻が無い・発走を過ぎただけは確定前。
- 予測 API: 区分 4 つ × 確定の前後 2 つで、出る項目を表で確かめる。
- 推奨 API: 非会員×確定前は 401、非会員×確定後は読み取り専用。
- 第 2 段: 開発者だけは確定前だけ。予測の印には出ない（P0 のテストを残す）。
- キャッシュ: 匿名の応答の Cache-Control（確定前 300 秒・確定後は今の長さ）。会員の Cookie 付きは private。

### 費用（最悪の回数で）

- 確定の判定: Cloud Run の中で race_result を読む（同じ東京で 0 円）。事前生成と覚える仕組みで、要求ごとの読み出しは増えない見込み。
- 確定前の匿名の s-maxage を 6 時間から 300 秒に縮める分: 匿名で開かれるレースの予測・推奨の取り直しが、1 レースあたり最大 12 回/時。
  - 開催日 9 時間 × 36 レース × 12 回 ＝ 3,888 回/日 × 9 日 ≒ 3.5 万回/月。Cloud Run の要求の無料枠（200 万回）の中で、ほぼ 0 円。
  - コールドスタートの回数は、匿名の要求が 15 分に 1 回以上ある時間帯は増えない。最悪でも、CLAUDE.md の再発防止 1 の 96 回/日の見積もりの内。
- 合計 ±0〜数円/月。
