# めぐAI印 v2（ユーザー定義）の評価と切替

2026-10-22。評価スクリプト: `src/scripts/data/mark_v2_eval.py`（build / design / compare）。設定: `config/mark_rule.json`（`version` 1=従来、2=v2。環境変数 `KEIBA_MARK_RULE=v1|v2` で上書き）。**既定は v1（挙動は変わらない）**。

## 1. v2 の定義（ユーザーの言葉 → 実装）
| 印 | ユーザー定義 | v2 の実装（`assign_mece_marks_v2`） |
|---|---|---|
| ◎ | 勝率がある程度担保されながら、一番期待値の取れる馬 | 勝率上位 3 頭のうち勝率が均等確率の 2.0 倍以上の馬から、単勝期待値が最大の馬 |
| ○ | ◎を除いて一番勝率が高い馬／◎とセットで着やすい馬 | ◎以外で勝率が最も高い馬（「セットで着やすい」の候補 top2・blend は差が 0.001 未満で、単純な勝率順を採用） |
| ★ | オッズの高い馬で、馬券内率がある程度あり、期待値が一番高いもの | 想定単勝 10 倍以上（**上限なし**）、複勝率が均等水準（3/頭数）以上の馬から、単勝・複勝の期待値の大きい方が最大の馬 |
| ▲ | 3 番手候補で馬券内の確率が高そうな馬 | 残りのうち複勝率が最も高い馬 |
| △ | 残りの中で馬券内に入る確率が高い 2〜3 頭（頭数で調整） | 残りから複勝率の高い順に、12 頭以上 3 頭・11 頭以下 2 頭 |
| 消 | 現行のまま | 現行のまま |

付ける順序は ◎ → ○ → ★ → ▲ → △。内部名（honmei / pair / star / show_val / anchor）は互換のため同じで、`race_bet_suggestion`（買い目の提案）は無改修で動く。

## 2. ★ の複勝率の下限（設計年 2022〜23 で比較して決定。想定単勝 10 倍以上・上限なし）
複勝率の下限（均等水準の倍率）ごとの ★（市場補正なし／あり）。「ex3」は単勝払戻の大きい 3 件を除いた回収率。
| 下限 | 出現/レース | 3着内率 | 単勝回収率 | 複勝回収率 | ex3 | 50倍超の割合 |
|---|---|---|---|---|---|---|
| 0.6 | 0.97 / 0.96 | 16% / 22% | 95% / 95% | 91% / 95% | 89% / 92% | 27.1% / 2.8% |
| 0.8 | 0.90 / 0.88 | 20% / 24% | 93% / 95% | 91% / 90% | 89% / 93% | 12.7% / 0.5% |
| **1.0（採用）** | 0.77 / 0.71 | 23% / 27% | 96% / 102% | 92% / 92% | 91% / 100% | 5.7% / 0.0% |
| 1.2 | 0.56 / 0.48 | 25% / 28% | 95% / 94% | 91% / 89% | 90% / 92% | 2.4% / 0.0% |
| 1.5 | 0.24 / 0.15 | 28% / 32% | 76% / 110% | 90% / 96% | 68% / 104% | 0.6% / 0.0% |
（市場補正なし / あり。表は ★ の期待値に複勝を使った場合。採用は単勝・複勝の大きい方（max）で、下限 1.0 では近い値: 補正なし 単勝 97.6%・複勝 90.4%、補正あり 101.3%・89.6%）
下限が低い（0.6）と、補正なしでは ★ の約 27% が 50 倍超の大穴になり、回収率が大穴の的中に左右される（上位的中除外で下がる）。下限 1.0 で大穴は 6% 以下に収まり、出現は 0.7〜0.8 頭/レース（現行 v1 は 0.75〜0.80）。下限 1.2 以上は出現が 0.5 頭/レース前後に減る。

## 3. 比較した候補（4 候補。多重比較に注意）
A=現行 v1、B=ユーザー定義 v2、C=期待値追求型（各印を期待値順に選ぶ）、D=レース別に規則を切替（状況別・頭数別の 2 方式。各グループで A/B/C から設計年の回収率下限が最大のものを選ぶ）。設計は 2022〜23 年だけ、確認は 2024〜25 年、2026 年は選択に使わず最後に 1 回だけ。回収率は `race_bet_suggestion` の買い目（1 点 100 円）を確定払戻で精算した合計（市場補正あり=本番、なし=参考）。区間はレースの再標本化 95%。

| 買い目の回収率（補正あり） | 設計 2022〜23 | 確認 2024〜25 | A との差（確認、95%区間） |
|---|---|---|---|
| A 現行 v1 | 101.9% [93.8, 110.2] | 96.6% [88.8, 103.3] | — |
| B v2（採用候補） | 108.6% [97.9, 119.5] | 95.6% [88.5, 102.2] | −1.0pt [−6.6, +3.7] |
| C 期待値追求型 | 101.0% [88.0, 116.6] | 94.5% [82.2, 107.7] | −2.1pt（補正なし: −12.7pt [−24, −2.4] で有意に悪い） |
| D 状況別切替 | 107.8% | 95.6% | −1.0pt |
| D 頭数別切替 | 110.1% | 94.2% | −2.4pt |

補正なし（参考）: A 93.6%→102.8%、B 95.9%→106.4%（差 +3.6pt [−4.8, +14.2]）。2026 年（最終確認、複勝オッズ無しのため ★ は評価できず）: A 87.3%、B 97.2% [58.7, 142]、C 59.3%（有意に悪い）で、区間が広く結論は出ない。

- **C は不採用**: 確認年で A より低く（補正なしでは有意に低い）、2026 年も有意に低い。
- **D は不採用**: 設計年で A を上回る（頭数別 +8.2pt）が、確認年では逆転して再現しない（選択による見かけの改善）。
- **B と A は回収率が統計的に区別できない**（差の区間が 0 を含む）。年別・月別も一貫して上下しない（月別 B≧A は 5/12）。

## 5. 判断
- 回収率の区間下限と再現性を最優先とする基準では **A も B も勝たない**（B は設計年で高く確認年で再現しない）。よって **既定は v1 のまま出荷**し、v2 は設定で切り替えられるようにした。
- 切替を決めたら、`config/mark_rule.json` の `version` を 2 にする（または `.env` に `KEIBA_MARK_RULE=v2`）。同時に画面の凡例（`frontend/app/race/[id]/page.tsx`・`weekly-predictions/page.tsx`・`prediction-results/page.tsx` の印の説明）と `_MARK_LABELS`（`local_predictions.py`・`prob_calibration.py`・`app.py`）を v2 の文言にそろえる。保存済みの予測の印は読み出し時に付け直されるため、データの書き換えは不要。
- 追加の検証: v2 の ★ は想定単勝 10 倍以上の上限なしなので、直前オッズ（T-10/T-5/T-2）が貯まったあと（10/24〜）に ★ の出現と回収率を再確認する。
