# 学習・評価・テストのデータの監査（2026-11-16）

ユーザーの問い「訓練・評価・テストデータ自体に不備（本来あるはずの値が空白、数字列が一つズレている等）はないのか」に答えるための全体の監査。
統括役（claude-orchestrator-handover）からの依頼。範囲は 2016〜2026 年、元の表（`data/page_reference/tables/<年>/*_flat.parquet`）→ 学習の表 → 推論の入力。

- 調べ方: 手元のファイルだけ（GCS・GCP は読まない、費用 0 円）。例外として、pf_rank の影響の見積もりの途中で GCS を 640 回・7.2MB 読んだ（約 0.2 円。権限の判定で止められたので以降は読んでいない）。
- 毎回の検査として `src/data_health/table_audit.py`（CLI: `python -m src.data_health.table_audit`）を足した（§6）。
- 期間の区切りは、学習（〜2023）・開発（2024）・テスト（2025）・2026。本番 v6e の学習の表は 2020〜2025、候補 s18（親モデル v6e16）は 2016〜2025。

## 1. 既存の検査で何が見られていたか

- `src/data_health`（checks・coverage・schema_check）は「GCS に文書があるか」「スキーマに合うか」「派生物のファイルがあるか」を見る。**列の中身（欠けの割合・値の範囲・列ずれ・レース内の整合・学習と推論の差）は見ていなかった**。
- 個別のスクリプトはある（`audit_column_drift_by_year.py`・`missing_audit.py`・`drift_diagnose_features.py`・`v6_parity.py`）が、毎回は流れておらず、月単位の急変・列ずれ・払戻との突き合わせは無い。
- そこで `table_audit.py` を足した（既存の data_health の検査の枠は「存在と形」を見るもので、中身の検査は別の関数群として置いた）。

### D. 問題が無かったもの

- 値の範囲: 着順（1〜頭数）・馬番（1〜18）・斤量・距離・オッズ・馬体重の増減・日付（race_id の年と一致）は、C2 のレースと取消の 0 を除いて範囲内。
- 枠番と馬番の関係（頭数から決まる JRA の規則）: 全年で食い違い 0。
- 人気とオッズの順位: 人気の順にオッズが逆転する行は、取消・除外で人気が飛んだもの以外に無い（以前の「2020〜2023 年に年 300〜500 行」は取消の飛びで、ずれではない）。
- 1 着の確定の単勝オッズ×100 = 単勝の払戻: C2・C5 のレース以外で一致。
- レース内の属性（日付・距離・馬場・クラス・頭数・発走時刻）: 全年でレース内に 1 つの値。
- 馬の ID の生年と馬齢、性の一貫性: 食い違い 0。
- 結果の表と出馬表の馬の一致: 取消・除外の分を除いて一致。
