# 調教の列・めぐ指数・補助モデルの列のリークの確かめ（2026-11-24、model-improve-cycles）

## 結論
- 候補 r04 にも本番 v6e にも、2017〜19 年の調教の記録の「生き残りの偏り」は学習に入っていない。本番のモデルは替えなくてよい。
- r04 は 2016〜2025 年で学習するが、`tl_*`・`wc_*` は 2020 年より前の行を空にし、`rb_nk_*` は外している（fit_info の spec。11/17 の「生き残りの漏れの除去」）。megu-cycles が計ったのは、この加工の前の X だった。
- v6e は 2020〜2025 年だけで学習している（283,714 行）ので、2017〜19 年の偏りは当たらない。
- 残る小さな問題: 補助モデルの列 `mtl_*` は、2017〜19 年の市場の残差との相関が 2020〜21 年の約 3 倍ある。2020 年より前を空にすると、開発の検証で対数損失が 0.0014〜0.0016 良くなる。r04 が v6e より良い幅（0.016）の約 1 割で、採るかどうかは次の候補として決める。

- `tl_*`・`wc_*` は v6e で 2〜4%、r04 で 1〜1.4% を占める。
- `rb_mg_*` は約 0.6%。

## 2. r04 に実際に入る値での年ごとの偏り（2016〜2021 年。2022 年以降の着順は読まない）
- 計り方: 確定の市場の残差（勝ち − 確定オッズの勝率）とレース内の順位の相関を、列・年ごとに計った（約 28 万行）。そのうえで、2017〜19 年の平均と 2020〜21 年の平均の差を見た。差の偶然のぶれは約 0.004 で、並べ替えの帰無とも分布が一致する（別のエージェントの裏取り）。
- 加工の前は `tl_has_training` が 2017〜19 年で 0.06〜0.11、2020 年は 0.00 だった。加工の後はこの形が消える（2016〜19 年の値は空）。
- 加工の後で差が最大の列は `mtl_t_rank_norm`（−0.015）。2017〜19 年が −0.015〜−0.024、2020〜21 年が −0.005 だった。`rb_mg_*` の差は 0.006 以下。
- 補助モデルの入力（175 列）に調教の列は入っていない。最初の年（r04 は 2016、v6e は 2020）だけは、年内を 4 つに分けて、同じ年の後の日付で学習している（学習の側の行だけ）。

## 4. 本番への影響と直し方の提案
- 予測の質: r04 の v6e に対する改善（開発の検証 −0.0161、2025 年 test −0.0125）は、評価の年の入力が as-of なので、リークで水増しされていない。v6e の検証・test には、めぐ指数の基準の先読みが少し入る（効きは乱数のぶれ以下。retrain_trials/README の段 9）。
- 買い目: 第 2 段・凍結した買い方の判定は r04 の確率の上に立つ。今回の結論では、作り直しは要らない。
- 直し方の 3 案:
  1. 外す: 不要。主な経路はもう外れている。
  2. as-of で作り直す: `mtl_*` を 2020 年より前は空にする（または補助モデルを 2016 年から as-of で学習し直す）。次の候補（r05）として、束の作り直しと影の並走で確かめる。
  3. 2020 年以降で学習する: 採らない。対数損失はほぼ同じで、学習量が 4 割減る。
- 本番の切り替えは統括役の判断の後に行う。

## 5. 確かめていないこと
- 追走難度（EASE2）とラップ予想（LAP・LAPD）は「その年を除く全年」で作るとある（retrain_trials/README）。r04 の学習の行で直っているかは見ていない。
- v6e の実際の学習の表（2020〜2025 年）での年ごとの偏り。
