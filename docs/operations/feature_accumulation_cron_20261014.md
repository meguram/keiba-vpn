# tp-02 / tp-03 の特徴量を cron で蓄積できるか（調査と実施内容、2026-10-14）

> **最新の設計は `docs/html/operations/raceday_prediction_workflow.html`（毎レースの予測出力までのワークフロー）と `docs/html/operations/cron_schedule.html`（cron 登録内容）を参照。このメモは当時（2026-10-14）の記録で、以降の変更（馬体重ランナーの cron 登録、v4 の影モード、確定結果の橋渡し、サービング状態の事前計算など）は反映していない。**

## 結論

- **履歴特徴量（A〜H の 127 列）は cron で蓄積できる。** 特徴量は「その行の日付より前の履歴」だけで決まる（as-of。打ち切り検査・同日入れ替え検査・摂動法で確認済み）ため、新しい結果が入っても過去の行は変わらない。ただし結果の取り込みが遅れた日があると、その日より後の行は取り込み後に変わる。そのため当年分は毎回作り直す。
- 実装した（`feature-accumulate`。毎日 07:40 JST）。**2020〜2025 年は蓄積の対象にしない**（学習用で、tp-02 が作る）。**2026 年は別ファイルに分けて蓄積するだけで、学習には使わない**（2026 年は不完全で学習に採用しない方針のまま）。
- tp-02b 以降の拡張特徴量（追い切り・厩舎コメント・クッション値・近交係数）は、**特徴量そのものがまだ無いので蓄積できない**。元データの取得状況だけを下表に整理した。2 件は取得側に穴がある（要判断）。

## 2. 実装した内容

### feature-accumulate（毎日 07:40 JST。netkeiba には触れない）

- 履歴 2020 年〜当年の確定結果から、学習と同じ計算（`build_from_runs`）で特徴量を作り、**当年分だけ** `data/local/modeling/feature_store/horse_history/features_<年>.parquet` に置く（原子的に置き換え）。`manifest_<年>.json` に行数・最終日・履歴の最終日・前回からの変更行数を記録。
- 実測（ホスト）: 約 25 秒、2026 年 36,512 行・2,664 レース・127 列。最終日は 2026-10-04（10/10〜12 の確定結果がまだ取れていないため。recent-retry が取得すれば翌日の実行で反映される）。
- **本番と学習のずれの監視**: 推論モードが保存した特徴量（`data/local/inference/features/<日付>/`）を、結果の確定後に学習時と同じ計算で作った値と比べ、一致しない特徴量を tier 別に `skew/<日付>.json` に記録する。合成データでは tier 0・2 の食い違いは 0。実データでは `sr_var_today` などの想定された差が出る。
- 履歴テーブルの更新（export_tables_daily、07:00）の後に走る。実測 約 4 分。

### 予測時点の出馬表スナップショット

馬体重の検知ランナーが特徴量を作るとき、**そのとき使った出馬表**（馬体重・馬場状態・取消を反映した行）を `data/local/inference/snapshots/<日付>/<race_id>.json` に保存する。出馬表は後の取得で上書きされるため、予測時点の入力をあとから再現できるようにする（再学習時の「当時の値」の検証、馬体重の発表時刻の把握に使う）。

### サービング用バンドル（小さなメモリのマシン向け。同日追記）

`feature-accumulate` は、特徴量と同じ計算の結果から**サービング用バンドル**（fit 済みの値・過去走の素材・Elo の最終状態。約 140MB）も毎日書き出す。馬体重検知ランナーはバンドルがあれば出走馬の履歴だけを読んで特徴量を作る（約 340MB・0.6 秒。全履歴方式は 2.4GB・約 20 秒）。設計と検証は `docs/html/modeling/chapters/feature_serving_low_memory.html`。

## 3. 要判断

1. **クッション値を GCS に上げる（2026-10-15 実施済み）**: 承認を受け、GCS の 2026 年分（92 件）をローカル（194 件。既存は全て含まれ値の違い 0）で更新した。2020〜2025 年は同一のため書き換えていない。旧版は `data/local/backup/jra_cushion/` に退避。アップローダは取得処理の出力先 `data/page_reference/cushion` を読み、既存キーを落とさず統合し、変化のある年だけ書く。
2. **レース前の厩舎コメント（2026-10-15 追加）**: ユーザーから「前日 16 時頃に更新されるデータで、遅くとも前日 20 時には取れる」との指摘があり、T-15 ではなく前日 20:00 の専用タスク `raceday-comment`（と当日 07:40 の取り直し）にした。既存の `race_trainer_comment` に保存する（レース前の厩舎の話は同じページ）。コメントが 0 件のページは保存せず、保存済みより件数が減る更新はしない。公開時刻は最初の週末（10/16 夜）の実行ログ（`logs/raceday_comment.log`、`auto_scrape_status.json` の `raceday-comment`）で確かめる。
3. **新規出走馬の血統取得（2026-10-15 追加）**: `new-horse-pedigree`（毎日 21:00）。今後 1 週間の出走予定馬（保存済みの出馬表から集める）のうち `ped_tbl` が無い馬だけ取得する。導入時点の対象は 623 頭中 1 頭。
4. **2026 年の特徴量を学習に使うか**: 現状は使わない。蓄積しておけば、2026 年のデータが揃った時点で再学習に使える。
