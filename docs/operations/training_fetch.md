# 調教ページ（horse_training）の取得: 運用と穴埋め（2026-10-21）

運用予測の調教系の列（V5 の `tl_*`・`wc_*` 約 87 列）は、出走馬の horse_training に「そのレース日の調教の行」があるときだけ値が入る。
2026 年 4 月以降、この行が取り直されておらず、予測が欠損のまま出ていた。原因・現状・対策をまとめる。

## 1. 原因と被覆の推移

- 定期取得が無かった（`sla_spec` で「手動投入のみ」）。手動の一括取得が 4 月で止まった。
- 前日夕方の raceday-eve に出走馬の最新ページを取り直す仕組み（`horse_training_recent.refresh_for_horses`、環境変数 `KEIBA_EVE_HORSE_TRAINING=1`）は
  実装済みだったが既定オフで、ホストで有効になったのは **2026-10-17 夕方（10/18 開催分）が最初**。それ以前の開催日には効いていない。
- 被覆 = 「その出走馬の保存記録に、そのレース日の調教の行がある率」（`drift_coverage`）。2026 年の月別（ホストの保存記録、2026-10-21 時点）:

| 月 | 出走行 | 被覆 | 備考 |
|---|---|---|---|
| 2026-04 | 3,718 | 78.8% | 手動取得が残っていた |
| 2026-05 | 4,175 | 17.5% | |
| 2026-06 | 2,862 | 5.7% | |
| 2026-07 | 3,721 | 5.1% | |
| 2026-08 | 4,722 | 5.2% | |
| 2026-09 | 3,116 | 6.2% | |
| 2026-10 | 2,604 | 20.2% | 10/18 だけ 100%（前日の取り直し） |

- 開催日別: 10/03・10/04 6〜10%、10/10〜12 1.5〜2.9%、10/17 0.4%、**10/18 100%（446 頭すべて）**。
- 保存記録がそもそも無い馬（`rec` が False）は 2026 年の出走馬の約 2 割。
- 2025 年と 2026 年 1〜3 月は約 100%（学習側は全件取り直し）。

馬ページは最新 10 走分を 1 ページに載せる。2026 年 4 月以降に 10 走を超えた馬は 1 頭だけだったので、**1 頭 1 リクエスト（最新ページ）で穴は埋まる**。

## 2. 運用の取得（前日）

前日夕方（raceday-eve 18:00 JST）に、翌開催日の出走馬の最新ページを取り直す（既に実装・ホストで有効）。

- 実測（2026-10-17）: 450 頭、18:32〜19:13 JST の約 41 分。保存された 450 頭すべてに 10/18 の行があった。
- 同じ日付の行だけ入れ替え、それ以前の行は保存済みを残す。0 件のページは保存しない（既存を空で上書きしない）。**最新 10 走分が入るので、その馬の直近の取りこぼしも自動で埋まる。**
- raceday-eve 内の順序: 取得 → 調教の取り直し → 馬の基本情報 → 前夜の事前計算（追走難度 v2・想定オッズ）。lap_forecast（19:30 JST）より前に終わる。
- 見積もり: 開催日 36R × 約 14 頭 = 約 500 頭 × 約 5.5 秒 ≒ 46 分。金曜は eve の取得本体が約 75 分（〜19:15）で、続けて調教 約 46 分（〜20:00）、その後に馬の基本情報と前夜の事前計算（追走難度 v2・想定オッズ）。
  lap_forecast の eve（19:30 JST）は出馬表（キュー取得分）だけに依存するので影響を受けない。前夜の事前計算が 20:00 以降にずれる点だけ注意（翌朝の予測には間に合う）。
- 当日（T-60）の再取得は不要（最終追い切りまでが前日夕方に載る）。ただし日曜開催分の eve は土曜夕方なので、土曜の追い切りが載らない可能性はある（被覆は監視で見る）。
- フラグ: `.env` の `KEIBA_EVE_HORSE_TRAINING=1`（現在オン）。

## 3. 過去分の穴埋め（バックフィル）

`python -m src.scripts.scraping.backfill_horse_training_recent --from 2026-04-01 [--dates 2026-10-10 2026-10-11] [--limit N] [--dry-run]`

- 対象: 2026-04-01 以降の出走馬のうち、そのレース日の調教の行が無い馬。行が足りない数の多い馬から。1 頭 1 リクエスト（最新ページ）。
- 規則: 他のスクレイピング（`scripts.scraping.*` / `repair_*` / `scraper.*` / 三連単バックフィル / 取得系の acq パイロット）が動いている間は待つ（最大 1 時間、待ちきれなければ中断）、
  負荷 18 以上でも待つ、4.5〜7 秒間隔、100 頭ごとに 30〜60 秒休止、連続 8 件の失敗/読めないで中断、再開可（進捗 `data/local/meta/horse_training_backfill_progress.json`）。
- 保存は `refresh_one`（既存の記録を空で上書きしない・スキーマ検証あり）。
- 規模（`--dry-run`、2026-10-21）: 出走 26,368 行 / 馬 9,416 頭 / **調教の行が足りない馬 8,437 頭**。実測は 1 頭 約 6 秒（クライアントの間隔 + 上乗せ 0.5〜1.5 秒）なので、全体で **約 14 時間**。
- パイロット（2026-10-21、ホスト）: 40 頭、保存 40・読めない 0・空 0・失敗 0。これらの馬の 2026 年の出走 323 行は、取り直し後 **100% で調教の行が揃った**（実測 10.2 秒/頭は上乗せが 4.5〜7 秒だった版。以後 0.5〜1.5 秒に変更）。
- 検証用の取り直し（2026-08-30・09-06 の抜き取りレースの 263 頭のうち 250 頭）: 約 25 分、保存 250・失敗 0。
- **夜間の分割実行（提案、未登録）**: `scripts/cron/horse_training_backfill_night.sh`（1 晩 2,200 頭 ≒ 3.5 時間）を、月〜木の 22:00 JST（13:00 UTC）に。
  1 晩 2,200 頭（約 3.7 時間）なら、残り約 8,150 頭は **4 晩（10/26〜10/29）** で終わる。開催日の前夜（金・土）と開催日を避け、21:00 JST の new-horse-pedigree の後。登録は `scripts/cron/install_horse_training_backfill_cron.sh`
  （ホストで root。タグ `KEIBA-TRAINING-BACKFILL`。`--remove` で外す）。**登録はユーザーの判断**（取得量が多い）。対象が無くなれば 0 頭で終わるので、完了後は外す。

## 4. 保険（サービング側）

- `KEIBA_TRAINING_COVERAGE=1` のとき、予測 API の応答に `training_coverage: {n, n_with_record, n_with_block, rate, level, note}` を付ける
  （`src/pipeline/inference/training_coverage.py`）。`level`: ok（≥0.9）/ low（≥0.5）/ poor。low/poor には注記（調教系の評価が欠けている）を返す。既定オフ・読み取りのみ。
- 監視: `drift_coverage` の調教被覆（下限 0.90）が週次監視の警報に入っている（`docs/operations/drift_monitor.md`）。
- race_oikiri（レースごとの追い切り一覧）からの代替列は、**実装しない**（提案のみ）: race_oikiri は評価の要約（評価ランク・短評）で、tl_ 系の
  区間ラップ・標準化時計・加速度は作れない。代替できるのは `oikiri_*`（すでに別の特徴量として存在）だけで、tl_ 欠損の穴は埋まらない。

## 5. 再予測による検証（取り直し前後）

`python -m src.scripts.data.training_refetch_restore --days 20260830 20260906 --out compare.json`（抜き取り済みの行の `tl_`・`wc_` だけを、取り直し後の horse_training から作り直し、同じ V5 バンドル `bundle_v5_2025` で再予測。特徴量全体は作り直さない）。
比較の関数は `training_refetch_compare.py`。2026 年はテストセット②なので結果の確認だけ。

| 指標（2026-08-30・09-06、20 レース・272 頭） | 取り直し前 | 取り直し後 |
|---|---|---|
| 調教系の列（tl_・wc_）の欠損率 | 98.0% | 42.1% |
| 勝率 LogLoss | 0.24096 | 0.24316 |
| 市場との差（モデル−市場、正が悪化） | +0.0011 | +0.0033 |
| 対数オッズ SD の比（モデル/市場。尖り） | 0.921 | 0.936 |

- 前後の勝率 LogLoss の差は **+0.0022（区間 −0.0063〜+0.0112、20 レース）**。区間が 0 を大きくまたぎ、20 レースでは良し悪しを言えない。**取り直しで精度が戻る証拠は、この標本では得られていない。**
- 尖りは 0.921 → 0.936 と少し戻る。参考: 調教が揃っている 10/18 の抜き取り（10 レース）は 1.105。
- 欠損率が 42% 残るのは、調教系の列の一部が構造的に欠損するため（例: 坂路/ウッドのどちらか片方、14 日・28 日の窓に調教が無い馬）。調教が揃っている 10/18 でも 59% 欠損。
- 先に診断した「欠損の再現実験では勝率 LogLoss の変化がほぼ 0」（`drift_diagnosis`）と整合する。調教の欠損は尖りの低下の一部を説明するが、モデル−市場差の拡大の大半（約 6 割）は別の要因。
- 全体を取り直した後は、2026 年 4〜10 月の予測を作り直して（`backfill_predictions`）、差と尖りが戻るかをレース数の多い標本（約 2,700 レース）で確かめる。20 レースでは足りない。
