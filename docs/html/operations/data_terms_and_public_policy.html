取得元の規約と、公開・有料化の方針

調査日: 2026-10-22。規約は取得ツール経由の要約で読んだもので、条文の原文での再確認と、専門家（弁護士など）への相談が前提。ここは判断の記録で、法的な結論ではない。

要約：データの取得元は netkeiba のみ（SmartRC は別枠）。netkeiba は、入手したデータ等を不特定多数に公開することを目的を問わず私的利用の範囲外とし（第14条）、営利目的の利用を禁じる（第15条）。例外は「当社の承認」。このため、一般公開は保留し、Cloudflare Access（所有者のみ）を維持する。公開する場合も、自前の出力だけを出す設計にしてある。

1. 取得元ごとの規約（要点）

取得元要点設計への影響
netkeiba第14条: 私的利用を超える複製・販売・出版の禁止。不特定多数が知りうる状態に置く行為は、目的を問わず私的利用を超えるとみなす。第15条: 営利目的（準備を含む）の禁止。第16条: 設備の利用・運営への支障の禁止。第12条: ID の共有・貸与の禁止。承認の申請方法・窓口は規約に書かれていない。公開面は自前の出力に限る。広告・有料化は、承認を得るか、取得元を切り替えるまで行わない。
JRA（アプリの規約）知的財産権は JRA に帰属。著作権法の範囲を超える利用の禁止。営業目的の利用の禁止。アプリのサーバー直接アクセスの禁止。「JRA から取れば公開してよい」とは言えない。
JRA（ウェブサイト「ご利用に際して」）自動アクセスの禁止・頻度制限の記載なし。映像・音声・画像・記事の二次利用は事前許諾で、申請は法人に限る。出馬表・オッズなど事実データの扱いは記載なし。テキストの事実データの取得は技術的に可能だが、法的に未確定。取得の実装は既定で無効。
JRA-VAN（公式フォーラムの回答）通常契約（個人）のデータは、Web 公開・広告・課金に使えない。商用は法人向けの契約が必要。ライセンスデータへの切り替えは、法人化を伴う。
SmartRC利用規約が見当たらない（規約の不在は許諾ではない）。低頻度で取得し、元の数値は表示せず、モデルの入力にだけ使う。

2. 個人で予想 AI を公開している事例（調査の結果）

  • 自前の確率・印だけを公開している個人はいるが、取得元を明記して問題なく運用できていると確認できた例は見つからなかった。
  • netkeiba に承認を問い合わせた体験談は、確認できなかった（承認が出ないことを意味しない）。
  • netkeiba のスクレイピングでは、短時間の連続アクセスで IP 制限（約 24 時間）を受けた体験談が複数ある。
  • 有料化の論点: 特定商取引法の表記、景品表示法（「当たる」「絶対」の表現）、競馬法（購入代行の禁止・20 歳未満）。

3. 公開の 3 段階

段階内容状態
1. 私的限定Cloudflare Access で所有者のみ。現在
2. 非営利で、出力のみ公開無料・広告なし。自前の出力（勝率・複勝率・印・展開予想）と、識別情報（レース番号・馬番・馬名）だけ。グレー。承認の問い合わせの後
3. 商用広告・有料会員。netkeiba の承認、または取得元をライセンスデータへ切り替えることが前提。保留

4. 公開してよい項目の許可リスト

正は config/public_fields.json。項目を A（自前計算）／B（事実）／C（取得元固有）／O（市場オッズ由来）に分け、mode=public では開発者以外に A だけを、サーバー側で出す。期待値と勝率が両方出るとオッズを逆算できるため、期待値と買い判断も O に分類した。台帳: docs/operations/public_data_inventory.md。

5. 有料ゾーンの「推奨度」

推奨馬券全体（ポートフォリオ）を、レース単位の 5 段階（見送り／標準／注目／高注目／最注目）に変換して出す。オッズ・期待値・購入金額の数値は出さない。方式は 3 つで、config/paid_zone.json の mode で切り替える。

方式実オッズの使用内容
A使わないAI の確率のみ。
B（承認前の既定）使わない想定オッズ（AI が予測した単勝・複勝と、そこから導いた全券種）。想定オッズのモデルの学習・較正には、過去の確定オッズを内部で使う。
C（承認後）内部で使う全券種の実オッズから期待値を作り、推奨度に変換する。画面には数値を出さない。

評価（2024〜2025 年、確定払戻で精算）では、推奨度が上がるほど回収率が上がる傾向は、どの方式でも有意ではなかった。推奨度は「値段の見通し」の段階で、当たりやすさではない。表示には「目安であり、的中や回収を保証しない」を添える。詳細: docs/operations/paid_zone_tiers.md。

6. 取得の姿勢（誠実な形式）

  • User-Agent は固定で識別できるもの（連絡先入り）。ブラウザを装わない。
  • 取得間隔は平均約 3 秒、プロセスあたり同時 1 本、全体で同時 2 本まで。
  • 制限を受けたら、User-Agent・IP・経路を切り替えて続けず、停止して人の判断を待つ。
  • 不要な取得を減らす: 完了済みのバックフィルの空振りログインを止め、現行モデルで採用ゼロの取得を停止した。詳細: docs/operations/cron_access_audit.md、方針: docs/operations/scraping_policy.md。

7. 公開リポジトリの扱い

  • netkeiba の取得データの抜粋、学習済みの重みと係数、第三者サイトの文章の抜粋は、公開リポジトリに置かない（.gitignore と、push 前の検査 scripts/dev/secret_scan.sh で再発を防ぐ）。
  • 過去の履歴に残る分は、履歴の書き換えで取り除く手順を用意している（docs/operations/history_purge_runbook.md）。
