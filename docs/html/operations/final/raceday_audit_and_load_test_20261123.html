影のランナー（開発者だけの試行）

  • 11/21〜23 の 3 日で、対象 31 レース。
  • 判定は 30 レース（買い 9・見送り 21）。
  • システムの見送りが 1 レース。7 頭立てで前段が無かった。直し済み。
  • 全判定が、発走 38 分前までに API で見えた。

見つかった問題

  • (a) 直前オッズの取りこぼし（T-60 などは発走の何分前に取る段か）。待ちの単調時計と判定の壁時計がずれ、数 ms 早く起きていた。
    • T-60 が T-45 に回った。T-10 は 7/24 しか取れず、T-05 は 2〜4/24。
    • 発走時のオッズが、発走 2 分前の段（t02）の名前で保存された。
    • 直してホストに入れた。11/28 から効く。
  • (b) 今年の race_id の API が s-maxage=30 だった。索引が Cloud Run で作られないため。
  • (c) Vary: Accept-Encoding のため、温めたキャッシュ（圧縮なし）を利用者（gzip で圧縮を受ける）が使えなかった。
  • (d) 開催中の本物の閲覧は少なかった（iPhone から約 48 件、レースのページ 6 回）。nginx のログに応答時間が残っていなかった。

モンキーテスト（本番・匿名）

  • Playwright で本番を匿名で巡回した。ブラウザの名乗り（User-Agent）に keiba-monkey-test を付けた。
  • 条件は ① 1 人 4 分、② 3 人 4 分。
  • 50 人の同時は未計測。nginx の IP ごとの制限があるため。
  • 429・5xx・タイムアウトは、3 回とも 0。

本番に入れた直し（11/23〜24）

edge-fix 1 回目（本番）

  • nginx が Vary で保存先を分けない。上流へは gzip で頼む。
  • 応答時間とキャッシュの状態をログに残す。
  • cache-warm の対象から、匿名では 401 しか返らないパスを外す。
  • 合言葉を作り直す。
  • 今年の確定済みのレースを nginx に 30 日置く。
  • 期限切れの直後は古いものを即座に返し、裏で取り直す（stale-while-revalidate）。
  • 保守の状態を 120 秒、匿名の auth を 300 秒置く。
  • 匿名の会員 API には nginx が 401 を返す。
  • API の制限の枠を、外の IP ごとと、VPS の中（Next.js のサーバ側・cache-warm）とに分ける。

edge-front（本番）

  • 匿名では会員 API を呼ばない。
  • 先読みは、マウスが乗ったときだけ。

edge-fix 2 回目（本番の承認待ち）

  • 直近の開催の判定を、結果で行う。確定の結果があれば 30 日、速報だけなら 6 時間まで置く。
  • 起動の準備が終わるまで、その台は要求を受けない。
  • モデルを起動の中で先に読む。

直しの中身と費用の見積もりは docs/operations/edge_fix_20261123.md。
