取得データの扱い（共通）

netkeiba を取得する全ジョブ（出馬表・オッズ・結果・指数など）は、同じ流れで保存する。

段階内容
1. 生のHTML原則、保存しない。ページ構造の変更を検出するためのサンプルだけを GCS に gzip で置く（カテゴリごとに最大 10 件）。ローカルには残さない。
2. 構造化パーサーが HTML から項目を取り出し、JSON にする（出走馬の行、オッズ、着順・時計など）。値は画面に出ているまま。集計や派生量は作らない。取得時刻とスキーマ検証の結果（_meta）を付ける。
3. 検証スキーマに合わない場合は GCS に保存せず、ローカルの data/local/quarantine/ に隔離し、違反の記録を data/local/meta/schema_violations/ に残す（既定）。
4. 保存先（正本）GCS（chuou/data/preprocessed/netkeiba/pc/<カテゴリ>/<年 または馬IDの先頭4桁>/<ID>.json）。ローカルには、メモリキャッシュと、週に 2 回以上読まれたキーだけの data/cache/ を補助として置く。GCS と同じ形のミラー（data/local/mirror/）は設定で無効（ホストでは未設定）。
例外（ローカルのみ）レース一覧（data/page_reference/race_lists）と発走時刻表（data/page_reference/race_day_schedule）は GCS に置かない。JRA 馬場（data/page_reference/cushion）もローカルで、GCS へは手動でアップロードする。
加工して別の場所に置くもの取得とは別の段階で作る。履歴テーブル（Parquet、data/page_reference/tables）、騎手・調教師統計（data/features）、馬場速度指数（data/analysis/track_speed）、推論用の特徴量（data/local/inference）、DB への取り込み（PostgreSQL）。いずれも GCS の構造化JSONを元に作る。
