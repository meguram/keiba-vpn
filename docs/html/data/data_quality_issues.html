データ品質の既知の問題と対応

2026-10-13〜20 に見つかったデータ・実装の問題を、解決済みと未解決に分けて 1 か所にまとめた。調査への影響と採否は 学習パイプラインの確定事項ログの §33 B。データの存在・スキーマ適合の検査は データヘルスチェック。最終更新: 2026-10-20。

1. 解決済み

問題影響原因と対応
学習表の sire / dam_sire が全行空血統系の特徴量が条件別の全体平均だった（tp-24）出馬表ページに血統が無く空保存。血統 JSON から horse_id で父・母父を引く（pedigree_keys）。v4 で差し替え
出馬表の course_type（内回り/外回り）が全行空外回りと内回りの区別が全特徴量から欠落正規表現が実書式に合わなかった。パーサー修正、過去分はコースマスタから導出
horse_training（追い切り）の空保存 5,261 件（14.1%）2021 年最終走の 2,598 頭が TL_A 被覆 57% の主因HTTP クライアントが 150 リクエストごとのセッション更新後に再ログインせず、匿名で取得していた。修正して全件を再取得（被覆 83/57/76% → 98/95/97%）
horse_result の列ずれ（通過順の一致 0.6%、上り 1.1%）horse_result を入力にする派生と最終オッズモデルの学習データ。v3/v4 は flat 由来で無関係会員表示の 33 列を固定位置で読んでいた。列名ベースに修正し、flat から補正するオーバーレイで直して最終オッズモデルを再学習
払戻 JSON で複勝・ワイドの複数行が区切りなしに連結2024 年〜2026 年 3 月に約 5,900 レース（2026 年は 1〜3 月の 587 レース）。連結したレースは採点できず、評価から外れていた。人気は復元できない補正表（payoff_fix_*.parquet）を作り、payoff_repair.apply_fix で評価に適用（曖昧 108 → 9 レース、2026 年は 10 レースを補正しない）。現行のパーサーは新規取得分を正しく割れる
確定結果の公開遅延（2026-10-17）結果ランナーが空振りし、履歴の最終日が進まなかった速報結果から橋渡し（bridge_on_time_results）。確定結果が公開されれば入れ替わる
2025 年 5〜12 月の結果ページで、指数列を読んで単勝オッズ・人気が破損（約 2,100 レース）race_result_flat の 2025 年のオッズ・人気は使えない。Σ(1/odds) が 1.25 からずれるodds_fix の補正表（race_odds 由来）で置き換え。列ずれの日次検査（parse_audit）と年別ドリフト監査を追加
出馬表フラットが 1 レース 1 頭に潰れる（2026 年 134 レース）枠順確定前の出馬表は馬番が全頭 0。重複除去が馬番だったため重複除去を馬 ID に変更。元 JSON から復元（repair_shutuba_flat_collapsed、36,909 → 38,431 行）
特徴量生成が馬番 0 のレースで空配列エラー（horse_history/match.py）2026-06-06・06-07 の予測が作れない。1 レースの失敗で同じバッチの全レースが error馬番が未確定のレースだけを error にして他は通常どおり作る（weight_triggered_predict）。回帰テスト追加
2026 年の単勝オッズが壊れた 2 レース（2026-02-08、Σ(1/odds)=0.18）tp-36 の 2026 年の結果が高く出ていたΣ(1/odds) が 1.0〜1.6 の外のレースを除外する検査を、2026 年の評価すべてに入れた
期待値の水準が高く出る 2 か所（連対 EV の「単勝オッズ×1.65」、複勝 EV の（下限+上限）/2）ほぼ全馬が EV≥1 で「強推奨」、買い目提案の 93% が「高」連対は馬連プールと整合する公正オッズ、複勝は下限＋0.3×幅に修正（tp-47）。さらに表示を実績に較正（tp-49）
3 連単オッズのバックフィルが DNS の一時不調で自動中断8 件連続失敗（アクセス制限ではない）--retry-failed で再開し、9,711 レースを保存して完了
「累積和 − 自分」の浮動小数点の端数今回勝ったときだけ値が厳密に 0 になり、木モデルが拾って見かけの改善（R6 で −0.0038）累積和を 1 行ずらす共通関数に置き換え、先読みテストを端数まで一致に強化。V4 の全採用群を監査して実害なしを確認
含水率の欠け・4 コーナー通過順の入れ替わり（2020〜2024 年）クッション値・含水率の特徴量（tp-16）ローカルと GCS（jra_cushion）に補完・訂正を反映し、旧版は退避。tp-16b で再評価（不採用）

2. 未解決・対応待ち

問題影響状況・次の手

3. 再発を防ぐ仕組み

  • 保存前のスキーマ検証: HybridStorage.save が必ず検証し、不合格は理由と項目を記録（python -m src.scraper.schema_violations）。
  • 日次の列ずれ検査（parse_audit）: Σ(1/odds) が払戻率から決まる範囲（約 1.0〜1.6）にあるか、人気が 1〜頭数の範囲か、馬体重が 300〜700kg かを、取得の翌日までに見つける。
  • 評価側の検査: 2026 年の評価はすべて、Σ(1/odds) が 1.0〜1.6 の外のレースと払戻が曖昧なレースを除外する。
  • 先読みテスト: 統計量は「そのレース日より前」で作り、完全一致テスト（端数まで）を付ける。
