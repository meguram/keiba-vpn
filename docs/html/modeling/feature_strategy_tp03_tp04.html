1. 設計原則

原則内容実装・根拠
時点ルール（as-of）特徴量は「対象レース日より前」のデータだけで作る。同日の他レースも使わない。Elo は 1 日分のレースを前日までのレーティングで評価し、日の終わりにまとめて更新する。src/pipeline/features/horse_history/。リーク検査は builder.py の truncation_check（2023-07-01 以降を消して再計算しても、それ以前の特徴量が完全一致）と permutation_check（以降の結果を入れ替えても当日の特徴量が不変）。tp-02 で不一致 0 を確認。
全体フィットの範囲縮約強度（κ）・分位点・クラスタ・類似度の重みなど、全期間で決める値は FIT_END = 2021-12-21 以前のデータだけで決め、全 fold で固定する。最初の fold（valid 2022）の学習終端 2021-12-22 より前。common.py。
学習対象年2020〜2025 年のみ。2026 年は不完全なため、学習・検証・テスト・履歴集計のいずれにも使わない。time_split.py の TRAINING_YEARS。
予測時点と可用時点（tier）予測は馬体重の発表後（T-60）のみ回す（前日夜の別バージョンは作らない）。前日までに確定する特徴量（tier 0）を先に計算してキャッシュし、当日朝（馬場状態・クッション値。tier 1）、T-60（馬体重。tier 2）の順に足す。詳細は モデリング戦略書 §10。tp-02 で feature_tiers.json を出力する予定。
オッズ・人気は使わないLayerA（市場独立の確率推定）には入れない。市場との合成（Benter 型の 2 段階ロジット）は LayerB（tp-06 以降）で扱う。pre_race_feature_whitelist.html。学習時と運用時でオッズの時点が違うと劣化した事例（出典 L13）。
欠損の扱い欠損は 0 で埋めず NA のままにする。疎なデータには has_* フラグを付ける（例: has_speed_index）。ホワイトリスト。木モデルは NA を扱える。
時代ずれへの対処年そのもの、時間とともに単調に増える累積件数、2020 年からの集計の始まりに由来する特徴量は、時代を見分ける手がかりになる。adversarial validation で追跡する。f5_n（全期間の累積件数）は出力から外した。残る候補への対処は tp-03（§7）。
取得データの不備の補正結果ページの last_3f・通過順・馬体重が壊れたレースは、優先順に (1) 生値、(2) GCS の race_result_on_time、(3) 母表の past_races で補う。common.py の apply_repair、repair.py。

4. 前段予測量（ステージ予測）と特徴量への組み込み

4.1 なぜ必要か

  • 馬とレースの「マッチ」は、そのレースの展開の予測と馬の得意な展開の組み合わせで決まる。前者の精度が、マッチ特徴量の効きの上限になる。
  • 現状（F2）の想定ペースは、過去走の脚質から先行馬を数えて 3 区分に分け、対応表で確率にするだけの簡易版。実測では確率がほぼ一様で、前傾・後傾への相性（f2_a_reg0/1/2）を活かしきれていない。
  • 上がり・位置取り・走破タイムも同じで、「今回の条件・展開の下での期待値」を先に予測してから、後段の特徴量にする方が、過去走の平均だけを渡すより情報が多い。
  • 例: ペース予測を先に出し、その確率で区分別成績を重み付けする。先行馬の頭数も、過去の脚質の平均ではなく、位置取り予測から数える。

4.5 リーク防止と精度の基準

  • ラベルは結果、入力は as-of: 位置取り・ペース・上がり・時計は当該レースの結果なので、学習のラベルにだけ使う。入力は tp-02 の as-of 特徴量と、前の段の OOF 予測だけ。P2 の集計は出走馬の as-of 値だけで作る（自馬の結果を含めない）。
  • 時系列の OOF: 年 Y の予測は、Y の開始 10 日前（purge 7 日 + embargo 3 日）より前のデータで学習したモデルで出す。2020〜2021 年の行には予測が付かない（NA）。2025 年（test）の予測は、2020〜2024 年で学習したモデルで出す。
  • 連鎖の注意: 第 2 段以降が使える行は、前段の OOF がある 2022 年以降に限られる。その分、後段の学習行が減る（助走期間が実質的に長くなる）。代替として、年単位の leave-one-year-out の OOF（学習行は増えるが、将来のデータでパラメータを学習する軽い先読みを含む）も比べるが、既定は厳密な expanding window とする。
  • 精度の基準（P3 の例）: 3 区分の予測の LogLoss が、一様予測（≈ ln 3 = 1.099）を明確に下回ること（seed 間のばらつきを超える改善）。下回らない場合は m_pace_match に使わず、簡易版（F2）に戻す。P1 は実際の位置取りとの相関と MAE、P4 は MAE と相関で評価する。
  • 寄与の確認: 各段の予測そのものの精度とは別に、後段への寄与（s_*・m_* の有無での p_win の LogLoss 差）を tp-03 と同じ手順で測る。
  • 簡易版との関係: F2 の f2_pressure・f2_p_fast・f2_pace_match は、P2・P3・m_pace_match の簡易版（ルールベース）としてそのまま残し、前段の予測で置き換えた版と比べる。

5.1 標準条件レーティング H の設計（斤量・性別・年齢の補正）

目的: 斤量・性別・年齢の違いを取り除いた「標準条件でのパフォーマンス」を過去走ごとに保持し、今回の条件で期待値に戻す。順位ベースの Elo（F3）は斤量差を無視しているため、能力推定の質に関わる。

既存の実装（src/pipeline/features/race_performance.py）と課題

  • 原型: 過去走は標準斤量基準の weight_adjusted_figure で保持し、horse_pre_rating_pre_race を今回の斤量で補正する（(基準 − 負担) × kg_to_sec）。仕様は race_performance_rating_system.html。

  • 出力は 2025 年分のみで、tp-02 の特徴量・LayerA に未統合。

推奨設計

  1. 係数は予測精度で選ぶ: 候補（0、0.05、0.1、0.17、0.25 秒/kg など。距離帯別）を時系列 CV の損失（次走のパフォーマンスの予測誤差、または p_win の LogLoss）で比べて決める。固定効果回帰の推定値は参考にとどめる。係数は FIT_END 以前のデータ（または fold 内）で決め、固定する。
  2. 負担の指標は「斤量 ÷ 馬体重」: 同じ 1kg でも馬体重で重さが違う。時計は log で扱い、距離を超えて比較できるようにする。馬体重が無い走は、馬の過去平均で補う（has_* を付ける）。
  3. 基準は全レース共通の 1 つ: 牡・4 歳以上・基準の負担比。レースごとに基準を変えない。年齢の差は年齢×月の成長曲線の項で、性別は斤量とは別の固定効果で扱う（牝馬の減量は表示斤量にすでに反映されているため、+2kg の擬似補正はやめる）。
  4. 二層で保持: 過去走は標準条件のパフォーマンス値（トラックバリアント・par 補正済みの時計）にし、そこから能力の平均と不確実性を更新する（Glicko・Kalman 型）。今回は 期待パフォーマンス = 能力 − β × （今回の負担 − 基準） ± 性・年齢の項 で戻す。
  5. Elo にもハンデ項: P(i が j に勝つ) = σ((R_i − R_j − δ·(w_i − w_j)) / s)。δ は 1 の係数から換算するか同時に学習する。斤量差が大きいレースでの過小・過大評価を防ぐ。
  6. 特徴量: 標準条件のパフォーマンス（EWM）、負担比、今回の補正量、期待パフォーマンス、前走比の負担の変化、不確実性。生の斤量・馬体重は木モデルにそのまま残し、交互作用を学習させる。
  7. 時点: 斤量は出馬表で既知。馬体重は発走約 1 時間前に発表されるため、運用時点（T-60 など）に合わせる。未発表なら前走の値で代替する。
  8. 検証: 係数の符号・距離依存の妥当性、負担の変化量別の予測残差が 0 に近いこと、ハンデ戦と別定戦を分けた評価、tp-03 の ablation（H の有無）。
  9. 将来の識別手段: 見習騎手の減量（同じ馬で斤量だけが変わる準自然実験）。減量の情報が必要だが、現在のデータには明示されていない。
