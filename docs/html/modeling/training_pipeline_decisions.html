申し送り（tp-03 以降で対応）

  • 採用候補: F3・C・A・D・B・F2a・E。小さい／要再確認: F5。見送り候補: F1・F4・F2b。最終判断は tp-03 の ablation（3 fold、採否基準は「全 fold で悪化せず平均が改善」）。
  • 時代を見分ける特徴量への対処を ablation で比べる: (a) 助走期間（2020〜2021 年）の行を学習から外す、(b) クラス・相手関係系の年内標準化、(c) 件数系（d_career_days など）の除外。
  • last_3f・通過順・馬体重の不正値は race_result_on_time で補正済み。取り直しは不要。ただしパーサーの列検出（parsers.py:193-243）とローカルの race_result_lap_flat（同じ約 2,810 レースの値が壊れたまま）は未修正。
  • race_index（タイム指数）は生データが不完全（約 55% のレースが 3 頭分のみ）。ログインが実質的に効いていなかった取得の疑いが強く、取り直し手順は docs/operations/stg_rescrape_login_dependent_20261014.md。モデル側は has_speed_index で欠損を扱う。
  • 結果の round 列が全行 0（parsers.py:186-187）。race_id の下 2 桁から導出できる。

5. tp-03 特徴量の ablation（採用する特徴量の確定）

根拠: コミット 863be66、MLflow 実験 keiba-tp-ablation の run 6fb037385c3545d18d4a6b68125ddada（運用の前提: speed_* なし）と 75dcd920eed9405094a1ac3d3ac7435d（参考: speed_* あり）。実装は src/pipeline/models/ablation.py、notebook は notebooks/modeling/training_pipeline/tp-03-feature-ablation.ipynb。成果物は data/local/modeling/training_pipeline/ablation_nospeed/（主）と ablation/（参考）の adopted_features.json・ablation_results.csv・final_candidates.csv。

条件

LightGBM 固定（n_estimators=300, learning_rate=0.05, num_leaves=31, min_child_samples=100, subsample=0.8, colsample_bytree=0.7, reg_lambda=5）、3 seed、valid 2022・2023・2024 の expanding window（purge 7 日 + embargo 3 日）。test 2025 は使っていない。主指標は p_win の LogLoss。採否の基準は「共通の全 fold で悪化せず、平均が改善し、改善幅が max(0.0001, 2×seed 間のばらつき) 以上」。B0 は LayerA の既存列（horse_prior_*・jockey_prior_*・trainer_prior_*・track_bias_*・sire_*・レース条件・馬体重）。

ベースを 2 通りで評価した理由: B0 の speed_*（タイム指数）は、そのレースのタイム指数ページ由来で、開催前に取得できるか未確認（SLA 監査 G11）。使えないと運用で動かないため、speed_* を含めない B0′ を運用の前提（主）とし、含める場合を参考として併記した。

adversarial validation の見方

B0 に 騎手・調教師の累積件数（2020-01 からの通算。jockey_prior_races など 6 列）と、sire_prior_win_rate_surface など時間とともに収束する事前統計があり、これらを含む構成は train と valid を AUC 1.000 で見分ける（分布差の目安にならない）。累積件数・件数系を除いても 0.998 と、B0 の事前統計が残るため、履歴特徴量だけの AUC（tp-02 の再計測: 0.78〜0.87）で見る。B0 の事前統計が時間で単調に変わる点は、2026 年（学習範囲の外）で予測するときの分布の外挿として、tp-06 のバックテスト（test 2025）で影響を確認する。

申し送り（tp-04 以降で対応）

  • tp-04 以降の入力は ablation_nospeed/adopted_features.json（B0′ + 履歴特徴量 127 列）。speed_* と has_speed_index は使わない。開催前に取得できると確認できたら、参考版（ablation/）に切り替えられるが、精度の差は 0.0004 と小さい。
  • H と既存 race_performance.py（固定係数）の比較は未実施。既存実装を 2020〜2025 年分で出力する必要がある。H が基準の斤量補正より良いかは未確定。
  • B0 の騎手・調教師の通算件数と、種牡馬の事前勝率は、時間とともに単調に変わる列。累積件数を除いても精度は変わらない（+0.00013）ので、外す選択肢（運用で 2026 年の値が学習範囲を超えるリスクを避ける）を tp-04 で再度比べる。
  • 学習と推論の出走馬の定義のずれ（学習側は競走中止などで着順が付かない馬を履歴から外している）を、「含める／含めない」で比べる（未実施）。
  • 複数 seed の LogLoss のばらつきは 0.0002〜0.0003（3 seed）。採用基準の閾値は 0.0001〜0.0003。
