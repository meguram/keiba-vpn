データの収集〜加工〜統合フロー（cron 時刻つき）

時刻はすべて JST。cron の登録内容（scripts/cron/setup_all_cron.sh show）から生成: 2026-10-15 17:20。再生成: python -m src.scripts.docs.build_data_flow_html。cron の一覧は cron 登録内容、特徴量とモデルの設計は 特徴量戦略書。

読み方　左から「データ → 取得するジョブと時刻 → 保存先 → 加工するジョブと時刻 → 統合・利用」。時刻 黄色 が cron の発生時刻。右端の線の色は統合先（■ 学習（手動・ノートブック）■ 履歴特徴量の蓄積■ 当日の推論（特徴量づくり）■ 期待値・推奨馬券（LayerB）)。
cron で動くのは取得と、一部の加工（flat 表・履歴特徴量の蓄積）まで。学習（tp-01〜tp-07）は手動で、cron には載っていない。

4. 毎日の流れ（結果が特徴量になるまで）

  1. 前日の結果: 夕方 毎日 17:30 に速報結果、翌朝 毎日 06:10・19:40 の取り直しで確定結果・ラップ・指数が揃う。
  2. flat 表: 毎日 07:00 に当年分を増分更新（race_result・race_shutuba・race_result_lap・race_result_on_time）。
  3. 履歴特徴量: 毎日 07:40 に当年分の127列を作り直し、推論モードの特徴量とのずれを記録（flat 表の更新後に動く順序）。
  4. 当日: 毎日 08:00 に検知ランナーが起動し、各R 発走65〜30分前に出馬表を取り直す。馬体重が揃ったら推論モードで特徴量を作る。
  5. オッズ: 毎日 07:30 に起動したランナーが、各R 発走60分前・15分前に取得する（T-15 は出馬表・馬柱なども）。

5. cron に載っていない工程（手動）

  • 学習: tp-01（母表・分割）→ tp-02（履歴特徴量）→ tp-03（ablation）→ tp-04（前段モデル）→ tp-05（最終モデル）→ tp-06（較正）→ tp-07（最終再学習・登録）。ノートブックを手動で実行する。
  • flat 表の更新は4カテゴリのみ（race_result・race_shutuba・race_result_lap・race_result_on_time）。race_index・race_shutuba_past・race_oikiri・race_odds・race_paddock・race_barometer・race_trainer_comment の flat 表は手動で export する。
  • 予測の起動点は2系統（T-45 の疑似特徴量ビルダー、T-15 のモック）が残っている。馬体重の検知ランナーは既定で予測を起動せず、特徴量の作成までを行う。
  • 優先処理（2020〜2025 年の取り直し）が動いている間は、同じ netkeiba アカウントを使う定期ジョブ（レース一覧・週次更新・バロメーター・recent-retry・backfill）を自動で見送る。

6. 整合性の注意

  • 2026 年のデータは学習に使わない（2020〜2025 年のみ）。
  • オッズ・人気は母表（LayerA）に入れない。入るのは LayerB（期待値の計算）だけ。
  • この図の時刻は cron の起動時刻。実際にデータが公開される時刻（馬体重・バロメーターなど）は、データの可用時点の表（特徴量戦略書の補足）を参照。
