ハロンごとのラップ予想（ラップ傾向別のタイムと発生確率）（tp-55）

ユーザー要望: メンバー構成、枠並び、脚質の分布、逃げ先行馬の直近テン1F、会場の特徴などをふんだんに使って、全レースで 1F ごとのラップ予想を出したい。ミドル・スロー・ハイでラップの傾向が変わるので、傾向ごとにハロンごとのタイムを予測し、それぞれの傾向がどのくらいの確率で起きそうかという粒度のモデルにしたい。

要点.
  • 『傾向（シナリオ）の発生確率』＋『傾向ごとのハロン別タイム』の混合として、全レースの予想を出せるようにした.シナリオはコース別の基準（par）に対する『前半3F と後半3F の差』の分位でスロー/ミドル/ハイ（25%・50%・25%）と定義。評価年 2022〜2025 年（学習は評価年より前）でシナリオの log loss は事前分布の 1.049 から 0.947（-9.7%）、確率の較正は良好（ECE 0.016）。
  • 確率の分布の当たりが、単一の予測より大きく良くなる.ハロンあたりの対数尤度は、par を中心とした単一のガウス -0.37、直接回帰の単一ガウス -0.24 に対し、混合は -0.17（2024 年）。80% 帯のカバー率は前半3F 0.80、後半3F 0.83（目標 0.80）。
  • 期待ラップの点の精度は、直接回帰と同じ水準.前半3F の誤差は par の 0.630 秒から 0.522 秒、後半3F は 0.690 秒から 0.558 秒（R² 約 0.3）。正解のシナリオが分かれば 0.358／0.380 秒まで縮むので、残りの誤差の大半は『どの傾向になるか』が事前には決まらないことによる。
  • 効く特徴量はコース・脚質の分布・同日の先のレースのラップ・馬場など。枠並びとテン1F は単独ではほとんど効かない.（第 4 節）特徴量の版の比較は第 4 節。
  • 2026 年（未使用。学習は 2020〜2025 年。2026 年は SmartRC の表が無いのでテン1F なしのモデル）: シナリオの log loss 0.947（事前分布 1.031）、前半3F の誤差 0.524 秒（par 0.643）、後半3F の誤差 0.551 秒（par 0.697）。なお 2026 年の 1 回目の評価は特徴量 v2（コース別の直近の傾向を足す前）で行い（log loss 0.949、前半3F 0.528 秒）、v3 に決めたあとの評価はこの 2 回目。

1. 出力の形

各レースについて、(a) ラップ傾向（シナリオ）の発生確率 P(k)、(b) 各シナリオ k のときのハロン（1F）ごとの予想タイム（スタートから。最初の区間が『テン1F』）、(c) 確率で重み付けした期待ラップと 80% 帯。1700m のように 200m で割り切れない距離は、最初の区間が短い（100m など）。API の lap_forecast に載る形は第 8 節。

2. データと先読みの安全性

  • 実測のラップ: race_result_flat のハロンごとのラップ（2020〜2026 年、芝・ダート。障害は除く）。ラップを読めて区間数が距離と合うレースだけ（全体の約 97%）。
  • 脚質・位置取り: 過去走の最初のコーナーの通過順位を（順位−1）/（頭数−1）にし、直近 5 走を 0.35・0.25・0.20・0.12・0.08 で重み付け（position_forecast と同じ定義）。その走より前の走だけを使う（日付が厳密に前）。
  • テン1F: SmartRC の馬ごとの『前走のスタート1F』（h1_ten1f）と『最近の最速』（ten1f_best）。smartrc_race_flat（2020〜2025 年）から。2026 年の表は無い（欠損）。先読みの検査: h1_ten1f は本走自身のレース最初のラップと一致する割合が 3.0%（偶然水準）で、本走の値ではなく前走までの値。前走で逃げた馬では前走の最初のラップと中央値の差 0.0 秒で一致する。データの出どころの経緯（DEC-024 でスタートデータを一度除外）を踏まえ、ここでは『前走までの値を日付で切る』使い方に限り、2026 年のようにテン1F が無いレースには、テン1F を使わないモデルで予測する。
  • 同日の傾向: 同じ日・同じ会場でラウンドが前のレース（同じ面）のラップの par との差。ラウンド順で前のレースだけ。
  • 完全一致の検査: 2024-07-01 以降の結果をすべて消して特徴量を作り直しても、それ以前の 15,053 レースの特徴量は全列で完全に一致した（先読みなし）。
  • 使わないもの: 市場オッズ・人気は使わない。

3. ラップ傾向（シナリオ）の定義と予測しやすさ

  • A（既定）: コース別の par（過去の同コースの平均ラップ。件数が少ないコースは距離×面の平均へ縮約）との差で、『後半3F の差 − 前半3F の差』が学習データの下位 25% ならスロー、上位 25% ならハイ、それ以外はミドル。直感的で、予測も当たりやすい。
  • B: 前半3F・中盤・後半3F の par との差を k-means（5 クラスタ）でまとめ、スロー寄りからハイ寄りに並べる。形の違いは細かいが、傾向の当てやすさは下がる（正解率 0.47〜0.49）。

7. 全レースで出せるか・応用

  • 被覆: ラップが分かる全レースで予想を出せる（評価の被覆率 100%）。出馬表の段階で、過去走が無い馬が多いレースは、脚質の特徴が『不明』の割合（unknown_ratio）として扱われる。テン1F が無いレース（2026 年・取得前）は、テン1F を使わないモデルで出す（評価では差はほぼ無い）。
  • 追走難度（tp-54）への土台: 想定ラップ（期待ラップ・シナリオ別ラップ）を、『想定位置取りを取るのに必要な通過ラップ』の要求の土台として使える。形は第 8 節の lap_forecast。
  • 整合層（pace_coherence）との関係: 整合層のペースは先行勢の頭数から推定する簡易なもの。ここの確率つきシナリオは、先行頭数だけのロジットより log loss が良く（第 3 節の最右列）、置き換え候補。ただし画面での置き換えは UI 担当の判断。
  • 勝率予測への増分（V5 の列セット d_CY_BEST に、ラップ予想の特徴量 12 列を足す。valid 2022〜2024 年、既定の採否基準）:

8. API・フラグ・運用

  • 予測 API（/api/race/{id}/predictions）に、環境変数 KEIBA_LAP_FORECAST=1 のときだけ lap_forecast を付ける（既定は無効）。保存済みの予想を読み出すだけ（src/pipeline/inference/lap_forecast_service.py）。
  • 保存: python -m src.scripts.data.tp55_backfill --dates YYYY-MM-DD ...（出馬表が書き出された日の全レース。過去分のバックフィルも同じ）。保存先 data/local/inference/lap_forecast/<日付>/<race_id>.json。モデルは final2026 の A（テン1F あり／なし）。
  • lap_forecast: version, race_id, date, distance, n_laps, lap_meters, model(A_full|A_noten), pace_label, pace_prob, scenarios[{name, prob, laps, sd, first3f, last3f}], expected_laps, band80_lo, band80_hi, expected_first3f, expected_last3f, par。laps はスタートから 1 区間ずつの秒。
  • 本番へは未反映。T-60 の確定出走表（枠順確定後）で動かす。出馬表の書き出し（export_tables の差分）が前提で、書き出し前は暫定にならない（保存なし＝付かない）。

9. 限界と今後

  • ラップ傾向の予測は、正解のシナリオが分かれば誤差が約 3 割縮むが、事前にはあいまい（正解率は『常にミドル』並み）。確率で持つ意味はここにある。
  • 特徴量は、馬の過去走の脚質とコースが中心。騎手の意図や当日の馬場の直前変化は入らない。2026 年のテン1F は取得できていない（SmartRC の 2026 年の表が無い）。
  • 勝率予測への応用は、第 7 節の増分の結果に従う。ペース予測は tp-25b でも不採用だった。
