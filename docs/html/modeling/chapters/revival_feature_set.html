復活セット: 過去に不採用だった特徴量を、緩めた基準で分ける

ユーザー依頼（2026-10-22）: 『今までの採用検討ログをもとに、復活する特徴量を分けておいてほしい。最終的にそれあり（復活セット）となし（今までの基準）で精度比較したい』。学習はしていない。台帳 docs/operations/revival_feature_ledger.csv、定義 config/feature_sets.json、読み出し src/pipeline/features/feature_sets.py、集計 src/scripts/data/revival_scan.py・revival_ledger.py。

要点.
  • 台帳 171 行（群 143・束 16・構成 12）。採用済み 14、R1 候補 6、R2 候補 32（代表に絞ると R1 4・R2 5）、リーク・市場依存・既存と重複で不採用のまま 9、年別が取れず要再集計 105。
  • 復活セットは 3 つ: R1（4 群）、R1+R2（7 群）、広い版（34 群・弱いシグナルの束ねを見る）。基準は v6e（z:RB@e）。
  • 復活候補はすべて、推論側の生成経路が未整備（採用済みの CY・ALL_BEST・RB・前段 e だけが本番の保存値から作れる）。そのため R に入る群は『オフライン評価では比べられるが、本番で使うには整備が要る』と読む。工数の目安を 5 節に付けた。
  • 注意: R1 でも、v6e に足して効く保証はない。 台帳の増分は V4・V5・d_CY_BEST に対するもので、v6e（RB・前段 e）に対する増分ではない。RB に足して増分が消えた群（クラス基準・展開利・非 JRA 過去走ほか）が実際にあった。また 138 群を検定しているので、R2 の基準（S3・S4）は偶然でも一定数が通る（S4 は片側で約 16% の割合）。比較の主役は R1 と、束ねた広い版で、R2 は参考。

6. 比較の実行計画（学習再開後）

  1. 比べる構成: A = 今までの基準（z:RB@e）、B = A + R1、C = A + R1 + R2、D = A + 広い版。python -m src.pipeline.features.feature_sets show が各構成名を出す。実行は python -m src.scripts.data.v6_eval run <構成名> --tag rev。
  2. 評価: LOYO（2022・2023・2024）、LightGBM、seed は構成間で共通（0・1、確認で 2・3）。勝率・連対・複勝の LogLoss、レース単位の paired bootstrap。層別は、初出走・履歴 3 走未満、クラス別、面別。test 2025 は、選んだ 1 構成について 1 回だけ。2026 年は選択に使わない。
  3. 採否: 構成単位で、二段の基準（従来の S1、または緩めた S2 を満たし、連対・複勝の悪化が +0.0002 以内）。D は束ねた効果を見るためで、合計の増分がシャドウ特徴量の束を上回るかを併せて見る（feature-screening の手順）。
  4. 推論側: 採用候補になった群だけ、5 節の整備を行い、v6_parity と同じ手順で学習側との一致を確認してから shadow に入れる。
  5. 所要の見積り（過去の実績からの目安で、実測ではない）: 1 構成の LOYO 評価（3 年 × 2 seed × 3 目的）は 0.5〜1 時間、4 構成で 2〜4 時間（直列）。seed 2・3 の確認は 1〜2 時間。通った場合の LOYO アンサンブルと最終学習（v6e と同じ手順）は 8〜9 時間。

7. 限界

  • 増分の基準が揃っていない。V4（tp-32〜42）、V5（tp-60）、d_CY_BEST（v6）に対する値で、v6e に対する増分ではない（重複で縮む見込み）。
  • 年別の OOF が保存されていない群は、段階（2022+2023 と 2024）の 2 期間でしか符号を見られない（105 群が要再集計）。再集計は学習なしでできる範囲を超える（OOF が無い）ため、学習再開後に行う。
  • 各群は、過去の第 1 段・第 2 段の選別を通ってきた（または落ちた）ものなので、選択バイアスがある。基準を緩めた S2〜S4 は偽陽性を含む。偽陽性率の見積りは feature-screening のシャドウ特徴量で行う。
  • 2026 年は使っていない。市場オッズ・人気は特徴量にしていない（tp-29 の市場版は除外した）。
