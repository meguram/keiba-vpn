想定位置取り・追走難度・想定上がりの連動（tp-53）

ユーザー指摘（2026-10-20）: 想定位置取りと、追走難度、想定上がりがうまく連動していない気がする。結果から読み取れる関係と、予測値との関係の差分を確認する。 対象: 2020〜2025 年の 20,270 レース・28.3 万頭（追走難度側は事前計算の保存物、位置取り側は馬柱から同じ関数で再計算、実測は確定結果）。

1. 要点

  • 連動していません。原因は設計です。この 3 つは別系統で作られ、共通のペース想定がありません。位置取り（隊列）は馬柱の通過順位だけの集計、追走難度・想定上がりは別のルールで、画面の「展開」の見出しは位置取り側のペース、上がりの基準は追走側のペースに由来します。
  • 追走側のペースは実測と無関係です。91% のレースが「ミドル」、実測の前半 3F との相関は −0.02（位置取り側の先行勢の圧力は −0.33）。追走側の脚質の分布は 92% が「差し」で、逃げ・先行が 0 頭のレースが 82%（位置取り側は逃げ・先行が平均 4.6 頭）。
  • 想定上がりは位置取りにほとんど反応しません。実測では、後ろの馬ほど上がりが速く（全体で最後方と先頭の差 約 0.9 秒、ペースが速いほど大きい: ハイ −1.4 / ミドル −0.8 / スロー −0.3）、追走側の想定上がりでは同じ傾きが −0.15（全期間）で、2024〜25 年はほぼ 0（2023 年は −0.25）、追走側が「ハイ」と判定したレースでは符号が逆です。
  • 整合層（既定オフ）で連動を回復できます。位置取り側の先行勢からペースを推定し、位置取り×ペースで上がり偏差を決め、同条件の中央値と自己の過去の上がり偏差を足す。2023〜2025 年の walk-forward で、上がり偏差の相関は 0.07〜0.16 → 0.35〜0.36、MAE は 0.76〜0.93 → 0.69〜0.70、ペース 3 分類の一致は 37〜40%（全部ミドルと答えるだけでも 39〜40%）→ 46〜47%。
  • V4/V5 の勝率予測への影響はありません（これらの値は V4/V5 の入力ではなく、画面表示用です）。

2. 2 つのペース定義は一致せず、追走側は実測と無関係

位置取り側（逃げ・先行の頭数から ハイ/ミドル/スロー）と追走側（pace_prediction.pace_type）の一致率は 26.2%（追走側の 91.0% が「ミドル」）。実測のペース（前半 3F の同条件 z で 3 分類）との一致率は、位置取り側 37.9%、追走側 39.1% で、どちらも低い（全部『ミドル』と答えるだけで 39〜40% 取れるので、位置取り側 38〜39%・追走側 37〜40% は、その水準を超えていない）。ただし相関で見ると、位置取り側は実測と意味のある関係があり、追走側はほぼ無関係です。

4. 原因の切り分け

  1. (a) 3 つが独立に作られている: 位置取り側（馬柱だけのルール）と追走側（別のルールとスコア）が別々の脚質判定を持つ。追走側の脚質は 差し 91.9%・先行 5.0%・追込 2.6%・逃げ 0.5%、位置取り側は 差し(中団) 39.6%・先行 24.9%・追込 23.5%・逃げ 12.1%。
  2. (b) ペースの共有が無い: 位置取り側の先行勢の数が追走側のペース・想定上がりに伝わらない。追走側のペース指数は実測と無相関。
  3. (c) 想定上がりの水準が不安定: 追走側の基準上がり（last_3f_baseline_sec）は、実測のレース中央値に対し MAE 1.7〜2.3 秒、ダートで偏り −2.2 秒（芝 −0.1 秒）。同条件の中央値（前年まで）なら MAE 0.74〜0.77 秒・相関 0.87〜0.88。
  4. (d) 馬の上がり能力の測り方: 近走の上がり『秒』の加重平均で、条件（芝/ダ・距離・馬場）の補正がなく、サンプルが無い馬（41%）は基準のまま。自己の過去の上がり偏差（同条件の中央値との差）は、単独で実測との相関 0.34〜0.36 と最も効く。
  5. (e) 特徴量の先読み・時点ずれ: 追走側の保存物は pre_race_only=True で対象日より前の走だけを使っており、先読みは見つからなかった（lgbm は heuristic）。

6. 実装と導入（画面表示用・既定オフ）

  • src/pipeline/inference/pace_coherence.py（config/pace_coherence.json に係数と同条件の表）。環境変数 KEIBA_PACE_COHERENCE=1 のときだけ、予測 API の応答に pace_unified（z・ハイ/ミドル/スロー・想定の前半 3F・基準の上がり）と、各馬の l3f_coherent（上がり偏差・想定の上がり秒・順位）を足す。無効・設定なし・材料不足のときは何もしない。
  • 画面は pace_unified を見出しのペースに使い、l3f_coherent を想定上がりに使えば、位置取り・ペース・上がりが同じ流れになる（UI の編集は keiba-vpn-72 の担当）。追走側の既存の値は残る（併記できる）。
  • V4/V5 の入力ではない（tracking_difficulty・position_forecast は特徴量にもサービングにも使われていない）ため、再学習は不要。

7. 限界

  • 『整合層』は実測の関係を作るだけで、予測の当たりを保証しない（上がり偏差の相関は 0.35 前後）。追走難度（ease_pct）自体の再設計（stamina と位置の重複の解消）は未実施。
  • 位置取りは枠順補正後の過去走ベースの集計で、実際の隊列とは別。初出走・履歴の浅い馬は位置取りも上がりも出ない。
  • ペースの 3 分類の閾値（±0.5 SD）は 3 分位に近いが、実測のペースは連続量。
