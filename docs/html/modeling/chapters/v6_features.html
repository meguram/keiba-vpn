v6 への追加候補の評価（前段の作り直し・展開タイプ・枠順バイアス・クラス基準・他の調査の候補の合算）

要点. V5 の構成 d（1,142 列）に累積して、新しい知見（追走難度 v2・位置取り予想・ラップ予想・展開タイプ・枠順バイアス・クラス基準）の『別の使い方』と、他の調査（tp-59・tp-64・tp-65・非 JRA 過去走・馬主名の正規化）の候補を、同じ手順（valid 2022〜24 の expanding、2 seed、95% ブートストラップ上限 < 0・効果 ≥ 0.0002・連対/複勝の悪化 ≤ 0.0002）で評価した。試した構成は単独 22・組合せ 10（対の比較 32）。

(1) 新しい知見の独立列としての追加（追走難度 v2・ラップ予想・展開タイプ・枠順バイアス）は、どれも基準に届かない（勝率 −0.00001〜−0.00008、上限は +0.00008〜+0.00016）。(2) 前段 S3 を新しい入力で作り直した版（S3B: tl_ 再取得 + CY + 追走難度 v2 + ラップ予想 + 位置取り予想）は勝率 −0.00023（上限 −0.00003）・連対 −0.00042 だが複勝が +0.00043 悪化で単独は不採用。(3) めぐ指数 v3b／netkeiba 指数の履歴 16 列（RB、tp-65）は単独で基準を満たす最初の群（勝率 −0.00028、上限 −0.00012）。(4) RB + S3Bは勝率 −0.00055（上限 −0.00031）・連対 −0.00068・複勝 +0.00017 で、S3B は RB の上でも増分がある（RB に対し −0.00027、上限 −0.00007）。(5) 騎手・調教師の通算成績 10 列と fe_year_frac を外した軽量版 v6-lite（d + RB 16 列 + S3B − 11 列 = 1,147 列）は勝率 −0.00059（上限 −0.00036）・連対 −0.00074・複勝 −0.00064 で、3 年とも負。(6) 残りの候補（CB・NJ・PB4・RS59・OWNN・展開タイプ・枠順）は RB の上に増分がない。 再現の結果は 6 章。

1. 設定と注意

  • 基準: V5 構成 d = V4 + tl_ 再取得版 + CY + ALL_BEST（1,142 列）。LightGBM binary（勝・連対・複勝）、valid 2022〜2024 の expanding、seed 0・1。基準の OOF は同じ手順で作り直して再現を確認した（完全一致）。test 2025 と 2026 年は選択に使っていない。市場オッズ・人気は特徴量にしない。
  • 先読み: クラス基準・枠係数・脚質×展開の倍率・馬主の成績は年ごとの as-of（その年より前の年だけで推定。2020 年は欠損）。展開タイプの確率は評価年以降の学習行にだけ『2020〜2023 年の他の年から学習』を許した（2022 年以降の行は厳密に過去のみ）。追走難度 v2（EASE2）とラップ予想（LAP）は年ごとの leave-one-year-out の予測で、tp-54・tp-55 と同じく軽い先読みがある（増分は上限として読む）。
  • 採否は feature_bakeoff.compare_oof（95% paired-bootstrap・レース単位）。段階 2 は『2024 年 + 新しい seed 2・3』。
  • 実装: src/pipeline/features/v6_groups.py（相対化・シナリオの不確実性・交互作用）、v6_ext.py（as-of の基準）、src/scripts/data/v6_stage.py（前段の作り直し）、v6_ext_build.py（群の作成）、v6_eval.py（累積評価と対の比較）、v6_members.py（LOYO アンサンブル用のメンバー）。テスト tests/pipeline/test_v6_*.py。

7.2 採用する構成案（v6）と採用しない群

  • 採用: v6 = V5 構成 d + RB 16 列（rb_mg_* 8・rb_nk_* 8）+ 前段 S3B（s_time_pred / s_time_gap / s_rank_pred を差し替え）。軽量版 v6-lite（騎手・調教師の通算 10 列と fe_year_frac を外す、1,147 列）は LightGBM 単体で同等以上（アンサンブルでは未確認）。列を外す扱いは配備時に選べる。
  • 採用しない: 展開タイプ（PT）・枠順バイアス（GB）・追走難度/ラップ予想の独立列とレース内相対・シナリオ条件付き前段（S3C）・ペース補正後の走破力（S3D）・馬主名の正規化（OWNN）— V5 の上に増分がない。クラス基準（CB）・展開利（PB4）・非 JRA 過去走（NJ）・rs59 — 単独は境界、RB の上で増分なし（NJ は複勝のみ改善、rs59 は運用側の更新が要る）。tp-68 の列削減・暦の列の削除 — 勝率は保つが複勝が悪化。

7.3 v6 最終学習・配備に必要な作業（未実施。配備・.env・MLflow 登録はユーザー判断待ち）

  5. shadow 並走: KEIBA_V6_SHADOW=1・predictions_v6/ を v5 の shadow と同じ設計（別系統・逐次・例外隔離）で。

7.4 推論（serving_v6）と shadow の設計（コード済み・未配備）

  • RB 16 列: src/pipeline/features/serving_v6.py。学習側（tp65_feat.asof_features）と同じ式（tp65_var の関数）を、馬ごとの履歴状態（1 走 1 行のクリップ後の値と、勝ち馬−40 点の下限つきの値）と定数（2020〜2021 年の分位点・尺度）から出す。学習側の値と完全一致: 2025 年の 12 開催日・5,491 行で全 16 列の最大絶対差 0.0、欠損の位置も一致（合成データのテスト tests/pipeline/test_serving_v6.py と、ホストの build_rb_state verify）。同じ日に 2 走ある馬（記録の重複）は、学習側の merge_asof が日付の先頭の行を拾うのに合わせた。履歴状態は python -m src.scripts.data.build_rb_state build（既定の置き場 data/local/inference/state/rb_v6/、KEIBA_V6_RB_STATE で変更）。日次の更新（前日までに確定した走を足す）は shadow の導入時に cron へ。
  • 前段 S3B: 最終モデルは fit_final_stage_v6（final_stage/v6_b_2024・v6_b_2025、各 1.9MB）。2024 年版の 2025 年の行の予測は expanding の OOF と完全一致（相関 1.0、最大差 0）。推論の入力は V3Serving.features が tl_・wc_ を履歴から、EASE2_*・lp_*・pf_* を本番の保存値（tracking_v2/・lap_forecast/ の JSON）から作る。未完: 学習側にあって保存値から写せない列（EASE2_full・EASE2_vs_prev・td_ease・td_l3f_ability・td_stamina、ラップ予想の馬別の交互作用 4 列）は serving_v6.UNMAPPED。これらを要求されると KeyError で止める（黙って欠損にしない）ので、shadow は写しの実装と過去日の一致確認が済むまで動かせない。
  • shadow の経路（v5 と同形）: KEIBA_V6_SHADOW=1 で weight_triggered_predict が v6 の V3Serving を別に持ち、v4・v5 の後に逐次で予測して predictions_v6/<日>/<race_id>.parquet に保存する。失敗はイベント（v6_status / v6_error）に残すだけで v4・v5 には影響しない。パスは KEIBA_V6_BUNDLE（既定 final_v6/bundle_v6_2025）・KEIBA_V6_STAGE（既定 final_stage/v6_b_2025）・KEIBA_V5_TL_REF・KEIBA_V6_RB_STATE。release_manifest の挙動フラグに KEIBA_V6_SHADOW を追加。

8. 申し送り

  • EASE2・LAP は leave-one-year-out の予測なので、前段 S3B の増分は上限として読む。運用では、追走難度 v2・ラップ予想・位置取り予想は既に本番で動いているので、前段 S3B は学習側の入力をそのまま推論で出せる（EASE2・LAP は本番の保存値、学習行は OOF）。ただし学習と推論で入力の分布が少し違う（OOF と全期間学習の予測）点は、v5 の ALL_BEST と同様に確認する。
  • top3（複勝）の対の比較は、特徴量の数が少し違うだけで ±0.0005〜0.0008 動く（6 列の追加でも +0.0007）。複勝の悪化 ≤ 0.0002 の基準は勝率・連対より判定のぶれが大きい。
  • 温度調整（戦略 4）は未実行（src/scripts/data/v6_temp.py は実装済み）。上の群が基準に届かなかったため優先度を下げた。
