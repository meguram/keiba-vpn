特徴量の掛け合わせ（交互作用・組合せ）の探索（tp-58）

ユーザーの問い（2026-10-21）: 各特徴量の効果的な掛け合わせ（交互作用・組合せ）も使えないか、検証する価値がありそう。もうやっているか。対象: V5（V4 の 1,062 列 + tl_ 再取得 + CY 37 列 + ALL_BEST 43 列 = 1,142 列）の上に、掛け合わせが上乗せになるか。検証年 2022・2023・2024（OOF のある年）。test 2025・2026 年は選択に使っていません。市場オッズ・人気は使っていません。

1. 要点

  • これまでにやっていたこと: 手設計の掛け合わせは G3 cross_misc（採用）、tp-37 の交互作用 11 群（不採用）、tp-38 の祖先×位置×条件のセル、tp-29/31 のコース適性、PED_sire_cond（採用）、tp-51 の特徴量グルーピング型。V5 の列にも、距離変化（chg_dist*）・間隔（rest_*）・脚質×ペース（frp_style_x_pace*）・体重変化（d_wt_chg*）などの掛け合わせが既に入っています。未実施だったのは『自動の総当たり』と、交互作用を表現できるモデル構造の検証で、今回それを行いました。
  • A 自動の総当たり: 上乗せなし。V5 の重要度上位 150 列とそのレース内偏差 60 列（基 210 列）から、積・差・対数比 44,631 候補を、V5 の OOF 確率に対するスコア検定（再学習なし）で全て調べました（3 目的で検定数 133,893）。発見期間（2022–23）で Bonferroni（z=5.08、帰無のばらつき 1.4〜2.0 倍に補正）を超えたものは 0 でした。上位の候補は『単独列の残差の足し算』にすぎません（§4）。
  • B 手設計の掛け合わせ（as-of 目的変数統計 12 種 + 数値 30 種）: 基準を満たすものなし。最も一貫したのは調教師×競馬場（発見・確認とも z=2.5〜4）ですが、検定数を考えると有意ではありません（§5）。
  • C 交互作用を表現できる NN（DCN-v2・FM・DeepFM）: 構造の上乗せはなし。効いたのは『掛け合わせの構造』ではなく『NN という別系統 + レース内ソフトマックス』で、構造なしの MLP が最良でした。V5 の LightGBM 単体にブレンドすると勝率 −0.0013 ですが、現行の合成（S0）に足すと勝率 −0.00022（上限 −0.00011）・連対と複勝は変化なし、L3 を含む合成の上では −0.00014 で基準（0.0002）に届きません（§6）。
  • D 残差ブースティング: 現行の合成にはもう学べる構造がほぼ残っていない。V5 の OOF ロジットを土台に浅い木（切り株 = 加法のみ / 深さ 3 = 3 列までの交互作用）を LOYO で学習すると、現行の合成（S0）に対しては深さ 3 でも勝率 −0.00002（上限 +0.00003）・連対 −0.00012・複勝 −0.00005。V5 の LightGBM 単体に対しては勝率 −0.00019（切り株）→ −0.00027（深さ 3）で、交互作用で取れる分は −0.00008、残りは加法で、合成が既に取っています（§8）。
  • 結論: 掛け合わせに上乗せなし。追加する列・表はありません。NN メンバーは現行の合成へ勝率のみ −0.0002 で、L3 と重なるため単独の採用基準に届かず、v5 最終学習で L3 を足すか決めるときに同条件の候補として残します（§9）。

2. 方法

  • スコア検定: 学習済みモデルの OOF 確率を offset として、列 z を 1 本足したときの対数尤度の傾き（score）を、再学習なしで測ります。勝ちはレース内ソフトマックス（offset = log p_win）、連対・複勝は二値ロジット。z = g/√I は『上乗せなし』で標準正規に近くなります。実装は有限差分と一致することをテストで確認（tests/pipeline/test_tp58_score.py）。レースの中で動かない列は 0 になるよう、レース内で中心化してから情報量を計算します。
  • 発見期間と確認期間: 候補の選別は 2022–23 年、確認は 2024 年で別に行い、選別バイアスを避けます。OOF が存在するのは 2022〜2024 年だけです。
  • 多重検定: 試した候補数を全て記録（A: 44,631、B: 12 種×4 統計 + 30 種）。帰無の分布が標準正規より広い（OOF の較正のずれ・列間の相関）ため、全候補の MAD から帰無のばらつきを推定して z を割り、そのうえで Bonferroni を使いました。
  • 確認: スコア検定で有望なものだけを、V5 と同じ設定の LightGBM（検証 2022/23/24・seed 0,1・同じパラメータ）に列として足して再学習し、feature_bakeoff.compare_oof（レース単位のブートストラップ。採用 = 勝率の差の上限 < 0・効果 ≥ 0.0002・連対と複勝が悪化しない）で V5 と比べます。

9. 判定と v6-features との統合方針

  • 掛け合わせの列: 採用なし。自動の総当たり（44,631 候補）・手設計のカテゴリ交差（12 種）・手設計の数値交差（30 種）のいずれも、発見期間で多重検定を超えるものがなく、残差ブースティング（深さ 3）でも現行の合成に勝率 −0.00002（上限 +0.00003）しか残っていません。最も一貫した調教師×競馬場（発見・確認とも z=2.5〜4）は、検定数と帰無の広がりを考えると有意とは言えません。LightGBM に列として足す確認は、選別を通る候補がなく、ホストが他の実行で過負荷だったため実施していません（§7）。
  • NN メンバー: 掛け合わせの構造（DCN・FM）は効かず、効くのは別系統としての MLP のみ。現行の合成（S0）に足すと勝率 −0.00018〜−0.00026（上限 −0.00008〜−0.00013）で連対・複勝は変わらない（新 seed でも再現）。ただし L3 を含む合成（S11f）の上では −0.00014〜−0.00015（基準 0.0002 未満）で、L3 と同じ信号に重なります。tp-51 の結論『別系統メンバーは足しても効果なし』と矛盾せず、NN は勝率の 0.0002 を L3 と分け合う関係です。採用しない（v5 最終学習で L3 の採否を決めるとき、重みつき MLP 1 本を同条件の候補にする）。
  • v6-features との統合方針: 追加採用がないため、v6 の列に足す作業はありません。将来採用する場合は、積・差・対数比の列 tp58_pairs.pair_column（定数は 2021 年以前の行のみ、列名 x58_<op>__<a>__<b>）と as-of 交差 tp58_cross.shrunk_cross（列名 x58_<名>_<目的>_{m,dev,n}）を v6 の表に結合するだけで、列名の接頭辞 x58_ は v6 の列と衝突しません。
  • 副次の知見（掛け合わせではない）: 調教の時計（tl_*・wc_*）の単独列に、発見・確認で同符号の残差が残る（§4）。残差ブースティングの切り株（加法）で −0.00019 取れるのは、この種の主効果が V5 の LightGBM 単体にはまだ残っていることを示しますが、合成には入っています。調教の列を作り直す v6 側の仕事で扱うのが筋です。
