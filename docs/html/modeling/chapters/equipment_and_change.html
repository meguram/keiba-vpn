馬具と「初めて・替わり」系の状況特徴（tp-32）

ブリンカーなどの馬具、距離の延長・短縮、芝↔ダートの替わり、初経験、昇級・降級、転厩、乗り替わり、去勢明け、馬体重・斤量の変化、年齢の節目と、それらの組み合わせについて、「その状況かどうか」と「その状況での過去の成績（馬自身の as-of 親和度・全馬の as-of 成績率・初経験フラグ）」を特徴量にして、V4（1,062 列）に対する増分を測った。休み明け・間隔は tp-34、輸送・滞在は tp-33 の担当で、ここでは参考の結果だけを載せる。

要点. 第 2 段で採用基準を満たした群はありません。 評価は valid 2022〜24 の LightGBM（第 1 段: 2022+2023・seed 1 本、第 2 段: 2024・新しい seed 2 本）。採否は『CI 上限<0・効果≥0.0002・連対/複勝の悪化 0.0002 以内』。test 2025・2026 年は使っていない。

1. 馬具データの所在と使えるか

# tp-32 馬具データの所在調査（2026-10-18）

## 結論
| 項目 | 判定 |
|---|---|
| ブリンカー（馬具）の過去分 | **使える。** SmartRC の fullresults（馬ごとの全戦績。2015 年〜）に、各出走の当時の blinker が入っている。確定した過去の事実で、取得が出走後でも変わらない。 |
| 出走表（runners）の blinker | 自レースの確定戦績の blinker と 324,802 行中 323,746 行で比べて **一致率 100%**（不一致 1 件、年別でも全年 1.0）。取得時点の最新値ではなく、そのレースの申告・使用値。 |
| 出走前に分かるか | netkeiba の**馬柱（race_shutuba_past）に、馬名の右に印 B（`<span class="Mark">B</span>`）** が出ており、これが blinker と 140/140 頭で一致（アーカイブ済みの 10 レースで確認）。出馬表（race_shutuba）・結果ページ・調教・厩舎コメントには馬具の記載なし。 |
| 馬具のその他（シャドーロール・チークピーシーズ・ハミ等） | **取れない。** 馬柱の印は B のみ（10 レースの Mark の値は B だけ）。SmartRC の runners にも blinker 以外の馬具項目は無い。 |
| 出走前に取った値での直接検証 | 過去分は不可（保存は全件出走後の取得）。**今後**は馬柱の B 印（パーサー拡張済み）と smartrc_prerace（eve スナップショット）で前向きに検証する。 |

## 根拠
- runners_eq 324,802 行・career_eq 497,001 行（2015〜2026 年の戦績、horse×race の重複除去後）。
- 出走表の項目と、同じレースの確定戦績の項目の一致率: blinker 1.0000、handicap 1.0000、ustat 0.99999、interval 1.0000、jcode 1.0000。
- 馬具の使用率は年とともにやや増える（blinker=1 率: 2020 年 9.8% → 2026 年 13.1%）。連続出走での変化率は 5%（初着用 9,581 件・外し 4,693 件）。
- SmartRC の `_meta` に取得時刻は無い（tp-27 の smartrc_scraped_at を参照）。
- 馬柱の HTML はアーカイブに直近 10 件しか残らない（保持=10）ため、過去の B 印は取り戻せない。これからの保存分から馬柱の blinker が溜まる。

## 前向き検証の計画
1. 馬柱のパーサー拡張（blinker と marks を保存。2026-10-18）で、eve/T-60 の馬柱から出走前の blinker が溜まる（毎開催日 約 400 頭）。
2. KEIBA_EVE_SMARTRC_SNAPSHOT=1（ホストの .env に設定済み）で、eve の SmartRC 取得時に runners を smartrc_prerace に不変で保存。次の開催日の前日夕方から。
3. `verify_equipment_snapshot` で、出走前のスナップショット/馬柱 B と出走後の smartrc_race を比べる。2〜3 開催週（約 1,000 頭以上）溜まれば、blinker の一致率を 95% 信頼区間つきで出せる。

4. 今後の取得（cron）と前向きの検証

  • 馬柱（race_shutuba_past）の馬名の右の印 B（ブリンカー）を保存するようパーサーを拡張。前日夕方（eve）の馬柱取得で、出走前の blinker が毎開催日 約 400 頭溜まる。
  • KEIBA_EVE_SMARTRC_SNAPSHOT=1 で、eve の SmartRC 取得時に出走表（runners）を smartrc_prerace に phase ごとに不変で保存（出走後の再取得で上書きされない）。
  • 備考（horse_race_remarks）の日次の増分取得: 毎日 03:00 JST、直近 14 日に走った馬のうち直近の出走の行が無い馬だけ取り直す（scripts/cron/install_horse_remarks_cron.sh）。
  • verify_equipment_snapshot で、出走前の値（スナップショット・馬柱 B）と出走後の smartrc_race を比較し、一致率を測る。2〜3 開催週（約 1,000 頭以上）溜まれば信頼区間つきで判定できる。
