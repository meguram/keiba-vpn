めぐ指数 v3b の集約と、『無視してよい低下（excusable）』の判別（tp-69）

2026-10-21、ユーザー決定『tp-65 の改良案（勝ち馬−40 点の下限、低信頼セルの縮約、加重 Huber）は採用してよい』『不利や状態の異常で着順が悪く、指数が外れ値になることがある。それは予測の特徴量に反映せず、使える指数だけを使いたい。本当に力がなくて低いのか、無視してよい低下かを判断するロジックを作ってほしい』への回答。資料: 指数の分散の比較（tp-65）・めぐ指数 v3a・展開タイプ（tp-61）・決定ログ。対象は 2020〜2025 年の中央の平地（障害を除く）で指数がある 312,809 走。2026 年は観察のみ（選択・当てはめに使わない）。市場オッズ・人気は使っていない。

結論

  • v3b（下限＋低信頼の重み＋加重 Huber）は採用。次走予測（勝ち馬の対数尤度、2023〜25 年）は、下限＋加重 Huber の骨格 0.2984 に対し、低信頼の走の重みを 0.5 にすると 0.3020（+0.0036、3 年とも改善、2025 年は区間が 0 を含まない）。低信頼の走を完全に除くと悪化する（−0.0087〜+0.0010）。
  • 『無視してよい低下』は、観測できる信号からはごく弱くしか見分けられない。低い走（直前 5 走の中央値より尺度 1 つ分以上低い走。全体の約 11%）の 46% は次の 2 走で通常水準に戻る（反発）。判定器の AUC は 0.57〜0.60（履歴の外れ度だけのベースライン 0.53〜0.55）で、判定した走の反発率は 52〜60%、それ以外は 41〜46%（lift 1.2〜1.4）。誤除外率（判定したのに戻らなかった割合）は 40〜48%。
  • 除外して集約すると、次走予測は悪化する。excusable の上位 35% を除くと −0.0064〜−0.0079（3 年とも区間が 0 を含まない）、上位 20% でも −0.0028〜−0.0046。重みを半分にしても −0.0001〜−0.0015（改善なし）。したがって v3b の値は excusable を除かない（既定の重み 1.0）。判定は『参考: 一過性の可能性』の表示用にとどめる。
  • 不利・出遅れの備考（trouble_rem、slow_rem）、上がり上位なのに着順が下、馬体重の変動などの単独の信号は、反発率の差がほぼ無い（lift 0.97〜1.08）。効いた信号は『レース全体の上がりが遅い（消耗戦）』（lift 1.16）、初めての距離・馬場（1.12・1.08）、休み明けは逆向き（0.85）。
  • V5（1,142 列）への増分の LightGBM 評価は、ホストの共有スロット待ちで未実行（下記の手順で完了できる）。

1. v3b の定義（v3a の値は変えない）

V5 は v3a で学習済みなので、v3a の値そのものは変えない。v3b は『走ごとの指数を、履歴として集めるときの扱い』だけの追加層（src/pipeline/megu_index/v3b.py）で、UI（めぐ指数テーブル・めぐ印・成長曲線）と v6 以降の特徴量候補に使う。

2. 次走予測への効果

3. 『無視してよい低下』の判別

3-1. 信号（その走の結果が確定した時点以降に分かるものだけ）

  • 結果表の事実: 着順の割合、最初・最後のコーナーの位置、最後のコーナーから着順にかけての順位の変化、上がり 3F の順位と着順の乖離、着差（秒換算）、頭数。
  • レース水準（結果から作ったもの、共有表 race_quality）: レース全体の上がりの偏差、脚質×ペース×隊列の 3 着内率の比（tp-61 の分類、評価年より前の年だけで作る）。
  • 備考のフラグ（不利・躓き・挟まれ・出遅れ。生テキストは持ち出さない）、馬体重の変動、休み明け（90 日以上）、初めての距離・馬場、斤量の変化、重・不良馬場、多頭数、低信頼セル。
  • 馬自身の履歴: その走の指数が、直前 5 走の中央値より尺度いくつ分低いか（own_drop。3 走以上ある馬だけ）。

3-2. 評価用の事後ラベルと判定器

低い走（own_drop ≥ 1）のあと、次の 2 走（指数がある走）の平均が、その前の通常水準（直前 5 走の中央値）− 0.5×尺度 以上なら『反発』。これは評価・学習のラベルにだけ使い、判定そのものには使わない。判定器は standardize 済みのロジスティック回帰（24 信号）。評価年 Y の判定器は、Y−1 年 6/30 までの低い走だけで当てはめ、ラベルは Y 年 1/1 より前の次走だけから作る（先読みなし）。2020〜2021 年の走は判定しない（除外なし）。

4. 『除外しすぎる』弊害

  • 判定した走の 40〜48% は、その後も通常水準に戻らなかった（誤除外）。除外すると、本当に衰えた馬の低下を見逃す。
  • 低い走そのものに、次走を予測する情報がある（深く落ちた走は戻りにくい）。除外では、この情報も捨てることになり、次走予測が −0.003〜−0.008 悪化した。
  • 加重 Huber は、極端な低値の影響を有界にする（外れ値の対策としては、判別して除くより、頑健な集約のほうが効く）。
  • 休み明けの低下は戻りにくい（反発率 0.41）ので、『休み明けだから仕方ない』という見方は、この集計では支持されない。

5. V5（1,142 列）への増分 — 未実行

V5 の 1,142 列に累積する LightGBM の評価は、ホストの共有スロット（3 本）が他の評価で埋まっているため、待ち行列に入れた（tp69-A、tp69-X）。組 A = v3b（excusable の除外なし）の 3 列（v3bA_wh、v3bA_max5、v3bA_mean5）、組 X = A に excusable の除外を足した 7 列。判定は既定の 2 段階評価（勝率の 95% 区間の上限 < 0、効果 ≥ 0.0002、連対・複勝の悪化 ≤ 0.0002）。次走予測の結果（除外は悪化）からは、組 X が組 A を上回る見込みは低い。完了後の手順:

scp keiba-remote:/home/jovyan/work/tp69_out/lgb_v3b{A,X}/result.json  # それぞれ lgb_v3bA/ lgb_v3bX/ に置く
python -m src.scripts.data.tp69_report --in <置いたディレクトリ>

6. API・UI への出し方

  • src/pipeline/inference/megu_excusable_attach.py の annotate(ex, runs) を、expected_megu.attach_expected_megu で過去走の詳細（race_details）を recent に反映した後に呼ぶ。ex["v3b"]（集約値）と、recent[i] に low_run / excusable / excusable_p / excusable_reasons（根拠の短文、最大 2 つ）が付く。判定できるのは、直前に 3 走以上ある走だけ。
  • API では勝ち馬の指数が無く下限は使えない。備考とペース区分も無いので、その信号は欠損（中立）で判定する。判定器（config/megu_excusable.json）が無いときは何も付かない。
  • UI は『参考: 一過性の可能性』と薄く表示し、めぐ印の集計からは除外しない（除外すると予測が悪化するため）。

7. 先読みの検査と限界

  • 信号は『その走より前の走』だけから作る（切断日以降を消しても、それより前の信号は完全一致、将来の指数を書き換えても変わらない。tests/pipeline/test_tp69.py）。
  • 反発ラベルは次の 2 走を使うが、評価・学習にだけ使う。評価年の判定器は、その年の 1/1 より前に確定したラベルだけで当てはめた。
  • 反発率の基準が約 46% と高く、『戻った』の定義（通常水準 − 0.5×尺度）は緩い。厳しくすると反発率は下がるが、判定の順位は同じ向き。
  • 判定に使える信号の多くは結果表の事実で、映像で見た不利・道中の詰まりは含まれない。備考は記入率が年とともに下がる（2022 年 21.6% → 2025 年 12.1%）。
  • API 版の判定は、備考・ペース区分が欠損の分、学習時より精度が落ちる。
