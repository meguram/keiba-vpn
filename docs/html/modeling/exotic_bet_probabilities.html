馬連・ワイド・3連複の確率モデル

勝率・連対率・複勝率の 3 つのモデル出力から、馬連・ワイド・馬単・3連複の的中確率を同じ着順分布で一貫して計算し、期待値（確率 × オッズ）に使う。実装は src/pipeline/inference/exotic_probabilities.py、馬券最適化への組み込みは betting.py。

1. 結論

  • 着順は Plackett–Luce（= Harville）に着順ステージごとの減衰指数 α を付けたモデル（Benter 型の割引 Harville）で生成する。α=1 なら Harville。
  • α2（2 着目）・α3（3 着目）は文献の定数を使わず、そのレースのモデルが出した連対率・複勝率に合うよう 1 レースごとに当てはめる（周辺確率の整合）。
  • 当てはめると、勝率・連対率・複勝率と、馬連・ワイド・3連複が矛盾なく同じ分布から出る。総和の制約（馬連 1 / ワイド 3 / 3連複 1）は自動で満たされる。
  • 真の分布が既知のシミュレーションでは、組合せ確率の誤差が Harville の 1/6〜1/9 に下がる。実データ 36 レースの市場オッズとの乖離（KL）も 馬連 36%・ワイド 48%・3連複 47% 小さくなる。
  • ただし実際の着順に対する対数損失は 36 レースでは差が出なかった（§7）。「確率が現実に近づいた」とまでは言えず、較正は検証待ち。

3. 着順の生成モデル

P(i が 1 着)                 = w_i                                  （α1 = 1）
P(j が 2 着 | i が 1 着)      = w_j^α2 / Σ_{k≠i} w_k^α2
P(k が 3 着 | i, j が 1-2 着) = w_k^α3 / Σ_{k∉{i,j}} w_k^α3

この形は Benter (1994) の rank-level dampening（P(π) = Π_r λ_{π(r)}^{α_r} / Σ_{k∈残り} λ_k^{α_r}、α_r∈(0,1]）で、Lo & Bacon-Shone の割引 Harville と同系統。α=1 で Harville (1973)。

なぜ割引か: Harville は「1 着を除いた残りの中での強さ比」で 2・3 着を決めるため、人気馬が 2・3 着にも入りやすくなり、穴馬の連対・複勝を過小評価する（HZR 1981 以降の実証で知られる）。α<1 は 2・3 着の決まり方を荒れさせ、これを緩める。

4. 各馬券の的中確率

馬券的中条件確率
単勝i が 1 着w_i
複勝i が 3 着以内r_i（モデル出力を総和 3 に正規化。無ければ着順分布の周辺確率）
馬単i→jP2[i,j] = w_i · w_j^α2 / Σ_{k≠i} w_k^α2
馬連{i,j} が 1-2 着（順不同）P2[i,j] + P2[j,i]（総和 1）
3連複{i,j,k} が 1-3 着（順不同）6 通りの順列 P3 の和（総和 1）
ワイドi, j がともに 3 着以内Σ_k 3連複{i,j,k}（総和 3）

期待値は EV = 確率 × オッズ。ワイドは払戻に幅があるため下限オッズ、複勝も下限オッズ（BettingConfig.wide_use_min_odds / fukusho_use_min_odds）。JRA の払戻率は単勝・複勝 80%、枠連・馬連・ワイド 77.5%、馬単・3連複 75%（控除後）で、確率が市場と同じなら EV の期待値は払戻率になる（EV>1 は市場より有利だとモデルが言っている場合のみ）。

5. 当てはめ手順

  1. q・r を、各 ≤1 を保ったまま総和 2・3 に正規化する（反復スケーリング）。
  2. q があれば α2 を連対率の二乗誤差最小で決める（連対率は α3 に依存しない）。
  3. r があれば、その α2 のもとで α3 を複勝率の二乗誤差最小で決める。
  4. r だけのときは α2=α3 を複勝率に合わせる。どちらも無ければ α=1（Harville）。
  5. 探索範囲は 0.2〜1.5（黄金分割法）。18 頭でも 1ms 台。

3 着目までの確率は n³ 配列で厳密に計算する（n≤18）。

読み方と限界
  • 市場との乖離（KL）は明確に改善した。馬連・3連複の市場情報を使わない設定（勝率+複勝率のみ）でも改善しているので、循環ではない。
  • 実現した着順の対数損失は差が出ていない（36 レースでは標準誤差が差より大きい）。「市場と近い」ことは示せたが「現実に近い」ことは未検証。
  • この検証の勝率・複勝率は市場由来。本番のモデル出力（勝率・連対率・複勝率）での検証は、予測の蓄積後に同じスクリプトで行う。

7.3 学習済みモデルの出力での検証・調整（後で実施）

上の検証の勝率・複勝率は市場由来で、本番モデルの出力ではない。モデルが学習できたら、保存された予測（race_predictions）と実際の結果で次のコマンドを回して検証・調整する。コードは用意済みで、モックの予測は既定で除外される（_meta.mock_prediction / dev_mock）。

# 評価だけ（期間はレース数が 200 以上になるように）
python3 -m src.scripts.data.validate_exotic_probabilities predictions --from 20260101 --to 20261231

# 全レース共通 α を config/exotic_alpha.json に書く（連対率・複勝率が無いときの既定値になる）
python3 -m src.scripts.data.validate_exotic_probabilities predictions --from 20260101 --to 20261231 --write-config
出力見方
全レース共通 α2, α3実際の 2・3 着の対数尤度が最大になる値（勝率を worth とした Benter 型の最尤推定）。0.7 前後なら Harville は後ろの着順を過度に人気馬へ寄せている
−log P（Harville / レースごとの当てはめ / 共通 α）馬連・ワイド・3連複の実現確率の対数損失。標準誤差を併記するので、差が誤差より大きいか確認する
較正 win / top2 / top3Brier・対数損失と、予測確率を 10 分位に分けた「予測平均 → 実測」。ここが崩れていれば、割引 Harville より先に勝率・連対率・複勝率の較正が必要
  • --write-config はレース数が --min-races（既定 200）未満、またはモック予測を含むときは書かない。
  • レースごとの当てはめ（連対率・複勝率あり）が共通 α より良ければ、予測側が連対率・複勝率を出し続ける運用が有利。同程度なら共通 α でも足りる。
  • 期間を変えて（例: 前半学習・後半評価）α が安定しているかも確認する。モデルを更新したら再実行する。

8. 制約・今後

  • 入力の質に依存: 連対率・複勝率が較正されていなければ、割引後の確率も歪む。勝率・連対率・複勝率の較正（実績との照合）が先。
  • 連対率が無いときは α2=α3 の近似（複勝率だけで 2 着目と 3 着目を同一視）。
  • Henery（正規）・Stern（ガンマ）型は着順分布の形が違い、馬ごとのばらつきも表現できる。必要になれば同じ RankDistribution の差し替えで比較できる（周辺確率に合わせる枠組みは共通）。
  • 市場オッズとの併用（Benter の 2 段階: モデル確率と市場確率を混ぜる）は未実装。DEC-026 の「市場対比」と合わせて検討。
  • 3連単は対象外（P3 がそのまま使える）。
