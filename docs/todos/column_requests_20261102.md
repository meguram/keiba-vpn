## A 騎手・調教師の読み（依頼 13）

### やったこと
- 原因: 騎手コラム（jockey-long-distance の jockey_distance_chart）の reading は、生成コードが無く JSON に手書きされていた。
  168 騎手のうち 104 人が漢字・カタカナのまま（斎藤・菱田・横山典・Ｍデムーロ など）、他も名の一部だけ（よこやまたけ・とざきけい）や誤読（木幡＝こはた、岩田望来＝いわたのぞむ、鮫島＝さめじま、原田和＝はら）で、50 音順が崩れていた。
- 読みのマスタを新設: `data/meta/person_reading/jockey_reading.json`（341 人）・`trainer_reading.json`（367 人）。
  対象は 2020 年以降のローカルのレース結果（race_result_flat）に出た全 id。1 人 1 行で、id・正式名・読み（ひらがな、姓と名の間に半角スペース）・表記ゆれ（略称・印付き・コラムの表記）・確からしさ・出どころを持つ。
  - 調教師 160 人は netkeiba の人物ページ（ローカルに取得済み）のフリガナを使い、姓・名に分けた（分け方は目で確認、20 人は手で指定）。
  - 騎手は全員、調教師の残り 207 人は手で読みを付けた（ローカルに騎手のフリガナは無かった）。新しいスクレイピングはしていない。
  - 外国人騎手は姓だけ（デムーロは M/C を区別するため名も）。
- `src/utils/person_reading.py`: `jockey_reading(name|id)` / `trainer_reading(name|id)` / `kana_sort_key(reading)` / `sort_by_reading(names, kind)` / `lookup()`。
  略称・全角・見習いの印（▲△☆★◇）から引ける。人が決まらない略称（「角田」）は姓の読みだけ返す。
  kana_sort_key は姓→名の順に比べ、清音と濁音・カタカナとひらがな・長音を辞書式にそろえる。
  `python -m src.utils.person_reading --missing` でマスタに無い新しい騎手・調教師を洗い出せる（今は 0 件）。
- `src/research/columns/apply_readings.py`: 全コラム JSON の name+reading を持つ要素の reading をマスタで付け直す。jockey-long-distance の 164 人分を更新（4 人は既に正しかった）、引けない名前 0。
  画面（ColumnChart の五十音順）は reading を localeCompare("ja") で並べており、半角スペース入りでも姓→名の順になることを確認。
- テスト: tests/utils/test_person_reading.py（6 件）。

### できなかったこと・注意
- 確かな読みの出どころ（JRA の騎手名鑑など）は今回スクレイピングしていないので、上の「推測」は未確認のまま。確認できたらマスタを直接直し、confidence を high にする。
- 50 音順を使う他の騎手一覧（塊 F のランク表・得意競馬場など）は、`sort_by_reading` か `kana_sort_key(jockey_reading(name))` を使い、記事 JSON の reading も `jockey_reading` で付けること。塊 F が jockey-long-distance.json を作り直す場合は、最後に `python -m src.research.columns.apply_readings` を流せば読みがそろう。
- マスタは data/meta に置いた（config/ は避けた）。Cloud Run の API から使う場合は、イメージにこのファイルが入るか確認が要る（今は研究・コラム生成のローカル用）。
